`graph.membership_matrix` fills a concrete gap: separate owner and pod axes
retain all observed deployment edges without duplicating both node sets on
both square axes. Existing deployment groups and edge tiles repeat endpoint

## RQ3.17 v2 opt-in additions

The user requested a node-and-directed-arrow control for every topology arm,
and matching colored numbered circles instead of long inter-panel connectors.
`component(..., node_layout="layered_grid")` reuses `graph.node_link` and its
original curved arrows. SCCs determine layers only; all original nodes,
self-loops, cyclic and typed edges remain. Wrapping layers at fixed readable
slots addresses the concrete 105-node overlap problem of shrinking concentric
rings. The default ring component is unchanged. Matching matrix/node arms use
the maximum of both layouts' required panel heights.

`relation_bindings(..., style="numbered")` is additive; omitted style retains
the original connector implementation. Number groups are sorted public
source/target identities, not rankings. Multiple operation cards can bind the
same edge and share a number/color. The exact matrix glyph or an actual point
on the directed SVG path is ringed; a matching badge is placed beside the
duration card title. The manifest records both actual anchors, group identity,
and annotation pixel bounds. Missing/ambiguous target or colliding labels fail
rendering rather than silently moving to another entity. Red/coral and yellow
are correspondence cues only; existing telemetry and relation colors stay.

Development previews that failed placement or used visually confusing merged
orthogonal routes are preserved under the RQ3.17 v2 qualification directory.
Dense topology still contains edge crossings. Example regression is not model
perception evidence or complete runtime qualification; user review is pending.

## RQ3.17 v3 direct colors

The user replaced circle/number annotations with direct correspondence colors.
`relation_bindings(..., style="color")` recolors only the exact request_parent
matrix glyph or complete node-link arrow and the bound duration card's
parent/child and operation labels. Each arrowhead is cloned per edge so other
edges retain their original colors. Geometry, dash patterns, typed slots,
reference/current points and all facts remain unchanged. Public directed
source/target order assigns coral/lime; multiple operation cards for one edge
share a color. More than two distinct groups fails the current palette capacity.
The current RQ protocol selects at most two relations. Colors encode observation
correspondence only, with the same mapping in every non-BASE text prompt.

Original attributes and exact affected field IDs/bounds are audited so bound
versus unbound HTML can be normalized and pixel differences checked. No circle,
number or inter-panel connector is generated by this style. Existing omitted
style and numbered style remain available with identical historical pixels.

## RQ3.17 v4 dashed width option

The existing component operation accepts optional `dashed_width_scale` on
`graph.node_link` (default unchanged). It scales only non-calls dashed paths;
SVG strokeWidth marker units scale their arrowheads too. RQ3.17 opts in at3
only for CALLS, not DEPLOY. Solid edges and their heads retain the default.
Three-case v3/v4 image comparison verifies unchanged pixels outside CALLS.
