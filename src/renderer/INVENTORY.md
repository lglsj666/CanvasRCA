# Additive typed inventory — RQ4.1

The pure-visual contract places exhaustive candidate IDs and global observation-window metadata in the image. Existing graph nodes would claim candidate membership is an observed topology fact, or reorder the candidate sequence. The literal.text component is a screenshot control and does not express a typed inventory. `inventory.identities` therefore preserves an explicit ordered identity sequence as chips, with existing detail captions for public global metadata. Numerical series, latency comparisons, logs, and edges continue to use their existing registered components. No existing component/operation meaning changes. Empty diagnostic panels and missing-sample warnings are not generated. Full source coverage is a separate experiment audit, never inferred merely from this component passing rendering.

`comparison.paired` addresses another explicit gap: supplemental metric medians, captured-request counts, and inclusive-duration summaries cannot use trace.paired_bars (exclusive-p95 meaning) or time-series charts (no fabricated timestamp). Each row has its own named quantity, original unit, zero-inclusive axis and reference/current operands. Raw captions retain all original statistics; zero/negative values are valid; null operands are not converted to zero.

The additive `canvas_extent` operation enables a 8,192px maximum side only when explicitly declared by a new design, following the user's RQ4.1 capacity amendment. Historical designs retain 4,096×8,192 logical bounds. Physical PNG dimensions in the new capability are bounded after scale, not merely before scaling. This does not change the model processor's pixel limits.

Final user correction: new images are bounded by 8,192×8,192; the preceding 16,384 proposal was withdrawn before qualification.

`foreground_audit` supplies an audit capability absent from existing operations: actual glyph foreground for canonical source roles and mandatory anchors. It validates binding IDs and a small target-part enum, preserves the original dashboard HTML/PNG before any audit-only mutation, and produces separate transparent role/anchor masks. These false-color audit artifacts never enter a model request. Fields may not silently be represented by their entire bounding-box whitespace.

`CanonicalForegroundV2` is an explicit additive provenance/audit schema. It
retains non-operand detail values as mandatory context, including identity and
descriptive metadata, instead of silently dropping them from a pruned request.
Only explicitly typed numerical operands receive allocation roles. The original
V1 operation output and normal dashboard rendering remain unchanged; V2 is
requested explicitly by the RQ4.1 source compiler. Both variants use the same
registered renderer and binding audit, with separate non-diagnostic rasters.

### Semantic HTML evidence export (RQ4.3 explicit control, 2026-10-11)

`renderer.semantic_html.export` exports the existing validated public card packet
as one directly readable HTML table. Column headers are shared; nested public
values use JSON cell syntax to retain types, nulls, units and exact strings.
`decode` independently reconstructs the ordered card records. This is an explicit
HTML/text comparison authorized by the user, not a PNG renderer, visual method or
fallback. Existing components and their default output are unchanged. Raw web
exports exceed the 40,960 context even after fonts/styles are removed; this export
preserves all public card fields without drawing coordinates, CSS or font data.
