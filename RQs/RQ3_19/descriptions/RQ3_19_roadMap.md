# RQ3.19 implementation and stopping boundary

1. Implement and register all core paths before qualification.
2. Static source/configuration/history audit, then complete CPU preparation and
   regression. Check actual input budgets without relaxing the plan.
3. Inspect the three fixed dataset PNGs and long/zero/extreme/single/fallback
   cases. Verify exact text-to-image transfer, not only hidden DOM attributes.
4. Freeze the qualified source. Bind the user's existing execution authority
   to that source; run the shared18-call/600-second smoke and inspect artifacts.
5. If all required checks pass, launch all1,480 core positions in the background
   and verify the live service, queue and first durable responses. Stop the
   assistant's task at that verified startup, as the user requested.

Current implementation/qualification state is maintained only in
../findings/exp_visual_replacement_qa_findings.md and result receipts; this
prospective roadmap is frozen with the protocol. Conditional attention,
baseline and extension gates remain explicit, not automatically triggered.
