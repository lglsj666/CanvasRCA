# RQ4.7 implementation and qualification roadmap

1. Save research and protocol; implement five modules and additive renderer exports.
2. Run AST/symbol/config/TypeScript/JavaScript/shell and protected-source static checks.
   **Stop here in this session.**
3. After explicit later authorization: offline unit tests; all-case source export,
   actual processor checks, mechanism compiler checks and multi-image transport.
4. Open fixed three-dataset and boundary PNGs; record a source-bound visual-review
   receipt. CPU success never enables a model entry by itself.
5. Freeze code, model provenance, inputs and queues. Run the single registered smoke,
   inspect its actual outputs, images, stage accounting and attention. Correct
   rankings are not a qualification gate.
6. Freeze/run the development DAG with eight CPU workers and eight model requests.
   Resume skips committed stages before loading inputs. Analyze both nominees and
   controls, including QA coverage, source assertions and logical two-call costs.
7. Conditionally qualify independent sources, exposure registry and scoring contexts.
   Only nominees passing their own engineering requirements enter the 90-case
   confirmation. No independent cases are invented or relabeled.
8. Drain writers, audit hashes/references, deduplicate immutable content, enforce
   directly-readable retention, remove only the explicit runtime cache, and report.

The broad scientific completion criterion remains a measured useful RCA method
and a defensible empirical evidence chain. Implementation and CPU admission are
not evidence of ranking improvement.
