
Field dictionary and magnitude checks:

- rrt means average application response latency, and rrt_max means maximum application response latency. They are durations, not request counts, throughput, or traffic volume. A fall in rrt means shorter measured response latency; by itself it does not mean requests stopped. Read request/response counts to assess volume. Keep the displayed metric's source units; do not apply the trace panel's milliseconds label to other metrics automatically.
- LOG-R event rate and error rate are events per minute over their respective baseline/current periods. volume_drop_x30:q prints q = current event rate / baseline event rate, NOT the fraction lost. The lost fraction is 1-q; the score contribution is 30*(1-q). A ratio close to one means a small rate reduction, not cessation. error_ratio_x50:q prints current error rate / baseline error rate and contributes 50*q. new_errors:+100 is a fixed score bonus when the baseline error rate was zero and the current error rate is positive; it does not mean 100 errors. logs_appeared:+20 is likewise a fixed bonus, not 20 events. raw_error_count_x10:n means n observed current error events multiplied by ten. These score weights are not physical quantities, probabilities, or independently observed faults. Use the printed rates and message alongside the score.
- Each metric lane uses an automatically fitted raw-value axis. A near-flat baseline followed by a very small change can therefore look like a full-height jump. Read both axis endpoints and the base/peak numbers before calling a jump large. A working_set_bytes value is an amount of memory in bytes, not a percentage of capacity; it cannot establish memory exhaustion without a limit or corroborating symptoms. An IO-utilization value is not automatically saturated because it increased. Capacity and free-space quantities are not utilization percentages.
- Trace count and latency are separate observations: a latency increase is not an increase in requests. Derive any stated fold change from current/base for that same owner and operation; do not infer it from the length of the plotted log-scale segment. A call arrow shows who calls whom, not which end must have caused the fault.
