## V2 refinement after actual-image inspection

V1 rendered three cases and preserved native byte replay, but grouping unrelated
owners to balance row counts weakens the intended relationship, and the full-
height topology column wastes area. V1 remains in code/artifacts as a rejected
CPU prototype, not a model result. V2 makes a joint card only for one exact or
public-pod/service-linked owner with evidence in at least two of M/R/L. All
unmatched rows remain grouped by modality. G remains complete; no arbitrary
node/trace or node/log pairing. Remaining M uses the native left lane; joint
cards and remaining R/L/G stack on the right. V2 preserves the source/prompt/
window contracts below and uses at most twelve cards. Cases with no cross-modal
owner are explicitly non-interventions, not forced artificial pairings.

SEARCH28's same-source facets did not help. Full training-answer review shows
some cross-owner attributions and separated resource/trace observations. Test
whether reducing the distance between related M/R/L evidence helps, not whether
more decorative titles help. SEARCH29's saturated range score is not used.

Hold the SEARCH23 selected packet, all numbers, source curves, candidates,
estimated public time window, Solver prompt and recipe fixed. Group M/R/L rows
by exact owner, optionally joining a pod to a service only through a selected
public membership fact. Never infer pod-node hosting. Keep all G facts together
so cross-group call edges are not lost. Groups are display associations, not
claims that an entity caused the fault.

Rejected V1 only (not the execution rule): allocate at most four M/R/L bundles by deterministic largest-first balancing
of public row counts (M=4, R=2, L=4), tie by numeric entity key and group index.
An owner's evidence cannot be split across bundles. Unowned metadata is assigned
once to a bundle containing its region. Each bundle places M next to R/L;
the complete G card stays separate. No facts, labels or candidate IDs are added
or removed. These display weights are not anomaly scores or root rankings.

All metric facets use the same selected public estimated window for shading.
Its metadata is displayed once; splitting a card must not silently remove that
context from later curves. No private timestamp is used. Preserve exact native
render replay under the default card-local context policy.

CPU acceptance checks exact-once fact binding, pod/service association, no
implicit hosting, row-order determinism, complete metadata, unchanged curve
values, shared-window shading, pixel containment and native replay. Actual PNGs
must be inspected before calls. Capacity failure is retained; no evidence is
deleted to make a layout fit. First probe uses already registered training
cases only. No validation, eval, Composer update or new attention is authorized
by this CPU registration.
