## 2026-09-24 决定：先验证可核验的错误，再决定是否修改推理

但实际回答存在可核验问题：未知／带前缀的候选、重复候选、实体类型混淆、onset 倒置以及调用关系与部署关系混用。它们有时发生在正确答案中，因此“回答事实可靠”与“根因排名正确”要分开测量。

选择做 CPU 核验，不直接采用自动重采样：前者可用现有证据衡量覆盖与误报，后者会改采样分布、调用成本及一次调用契约。保留负向结果；本次不改旧 scorer 或推理配方。若发现的问题很少，也要报告，不能依赖合成突变命中率宣布现实收益。

## 原始文献与适用范围

1. **CARS — Constrained Adaptive Rejection Sampling，ICML 2026。** [论文 v2](https://arxiv.org/html/2510.01902v2)、[官方会议论文列表](https://icml.cc/Downloads/2026)、[作者代码](https://github.com/pparys/cars)。阅读方法、实验与讨论，核查 README。记录违反约束的前缀及其概率质量，提高拒绝采样效率，并保持条件分布。它不是 RCA 推理器，也不是现成的 Z3 审查工具；大量有效样本的摊销收益不能直接搬到一次 RCA 调用。约束满足与真实诊断正确是不同目标。当前不改 vLLM decoder，不称实现为 CARS 复现。
2. **SAT-LM，NeurIPS 2023。** [正式论文](https://proceedings.neurips.cc/paper_files/paper/2023/hash/8e9c7d4a48bdac81a58f983a64aaf42b-Abstract-Conference.html)、[代码](https://github.com/xiye17/SAT-LM)。阅读方法、主结果、选择性预测与局限。模型给出声明式约束，由求解器执行推断并区分矛盾和多解。借鉴“前提—断言—求解”分离，不把噪声遥测和调用图当成完备物理故障模型。
3. **LINC，EMNLP 2023 main。** [正式论文](https://aclanthology.org/2023.emnlp-main.313/)、[代码](https://github.com/benlipkin/linc)。阅读方法、结果和错误分析。形式化遗漏／误译本身是重要失败源；借鉴 open-world 与不确定结果，不能让抽取器产生新幻觉，再让证明器为它背书。

三篇均为方法启发，不复制论文效果数字作为本项目预期。CARS 是用户指定的新论文，SAT-LM/LINC 是直接相关的已发表基础工作；当前实现使用本地已有 Z3，不导入这些项目或外部 RCA 仓库。

## exp_claim_verification_cpu

范围：RQ3.3 `witness_v2/analysis/check.json` 全部 120 cases × 5 arms × 2 models。失败／没有完整输出的单元明确列出，不补推理。五 arms 为 TPV、SIRCL_TEXT、P0_MORE_TRUE、W_T、W_G。

### 事实编译

- candidate membership 只由该请求的完整候选列表决定；不猜测前缀对应关系、不自动修复。
- 类型只在请求明确说明三／四／五位映射时启用。没有说明的旧文本条件不借其他 arm 的指南判类型错误。
- 先解析真实可见文本，保存 part、line 和源文本。G 的同事实 W_T ledger 可作 G 图的离线来源核验，但先验证 W_T/W_G 的 M/R/L、候选、附录文本对应，以及待审 arm 的图像 hash 与 W_G 相同。不能把 ledger 当作该视觉请求额外收到的文本；当前核验不是 OCR 完整性证明。
- 没有通过 twin 身份检查时，图像事实记为未核验；不能替换成完整原始池。
- onset 显示值用显示精度对应的保守闭区间；相同／相邻区间不强制先后。显示引用检查使用区间相交，严格先后使用 SMT 蕴涵。
- 边是正向观测，缺少反向边不推出反向边为假。没有完整观测的部署关系不设置唯一宿主约束。
- 只编译已实际显示的 appendix 数值，不从 private 文件恢复事实。精度、单位和 reference/current 绑定保留。

### 核验与结果状态

候选与重复检测用普通确定性代码，不为简单集合操作包装 SMT。Z3 用于有界数值、顺序及关系断言，结果分为 entailed、refuted、unknown、inconsistent_evidence、solver_unknown、unsupported。先检查事实库可满足，避免矛盾前提推出一切。

自然语言的有限规则只产生 **review_required** 的断言候选，保存逐字原句；即使其形式断言被 refuted，也不能直接计为已确认 hallucination。特别区分 graph node 与基础设施 node、局部 metric onset 与实体总体 onset、否定句与肯定句。没有声明“自动覆盖所有 reason”。

离线记录：每个单元的核验耗时、确定输出错误、待审 claim、编译事实覆盖、失败及来源位置。汇总按模型、arm、数据集，同时给两个 AIOPS 合并和整体描述结果。不做事后改分，不将自动标记率称真实幻觉率，不以删除 flagged cases 后的 MRR 作为方法效果。

### CPU 检查

覆盖：非法和重复 ID、无类型指南、显示精度、相同 onset、不一致数值、开放世界反向边、时间反向、无因果规则、单位不兼容、NaN、事实来源、文本候选冲突、twin 不匹配、自然语言抽取未覆盖、无 private 字段进入编译器。合成正确／错误断言用于软件测试，不是现实诊断效果。

运行仅扫描已有小 JSON，不加载原始遥测／大型 pickle，不启动 vLLM。全阶段 CPU 审计 15 分钟上限，超时保留 partial，不能称完成。输入摘要和源码版本落盘；不进行历史大文件重新 hash。结果独立目录，不改 RQ3.3 的 flag、状态、输出或成本记录。

## 后续 GPU 实验：仅作为下一阶段候选，当前未启动

先人工核验 CPU 标记的代表性案例，明确抽取误报与漏检。研究成功必须分别回答检测精度／覆盖率、可靠性、MRR 和成本，不仅报告错误数下降。

第一候选是冻结强 TPV 的 **precompiled relational facts**：只给同一证据可推出的实体绑定、时间先后和显式关系，不删候选、不暗示根因。需匹配普通事实重述／等 token 控制；文本 G 与图像 G 采用同一证书，分离证明信息和视觉效应。它仍可保持一次 Solver 调用。

另一候选是 **post-answer audit**：不改变排名，输出核验告警。这是可靠性产物，未必提高 MRR。若日后增加局部修复调用，必须另注册双调用对照（同成本自审、无 solver 审查）、保留原答案并报告 repair/break；不能因答错反复重采样。自由文本语义解析的开销和错误必须计入。

没有完整故障模型时，不把“与观测兼容的根因”称为“唯一被证明的根因”。当前不给最早／最异常实体设置因果硬约束，不把 CARS 精确条件采样保证转译为 RCA 正确性保证。

## DD-RQ34-02：将原路线与自动推理合为下一轮

**日期：**2026-09-24。**状态：**用户要求的合并设计；实现与运行资格待完成。

**依据。** [RQ3.3 报告第14节](../../../docs/RQ3_3_Results_Analysis_2026-09-24.md)原本优先处理输出／类型契约、宿主—实例归因、证据优先级、视觉绑定。CPU 核验新增的是定位显式错误的工具，而不是足以取代原路线的效果证据。247 份回答的待复核标记包含语义歧义，不能作为根因错判标签或路由信号。

**决定。** 将“选对证据—比较故障范围—算清事实关系—可靠承载—正确排序”作为统一方法链。三个主要干预用完整二水平因子设计，不再顺序挑冠军。输出契约单独控制，视觉与重述单独控制。主指标 MRR；事实可靠性是独立结果而不是 MRR 的替代品。

**放弃的方案。** 不另开独立的六条件 auto-reasoning 全队列再重复原路线；不立即上训练、CARS decoder、多次答案修复或任意 MaxSAT 根因打分；不把“早于”“更异常”硬编码成因果规则。通用自审已缺乏稳定增益，若将来做 solver 反馈修复，须另注册同成本双调用对照。

### A. 共同契约与数据

- 两模型顺序运行；沿用 RQ3.3 当前实际生效的本地统一配方、一次调用、8192 output cap、300 秒 request timeout、无 attention。请求 timeout 记录并继续，其他基础设施错误 fail-fast；不新增 5% 自动放行门槛。
- 复用 canonical per-case corpus、当前合法公共统计及小型缓存。新选择只在 CPU 侧访问 public telemetry，不经旧 top-k 先截断，不读取 private root/fault/injection time 或旧模型答案。
- 开发组为 RQ3.3 `analysis/screen.json` 的全部 **60 个唯一 cases**，三个主数据集各20个；包含历史失败case，不从只含58个配对case的 method_lock 列表取样。另一组为 `analysis/check.json` 的全部120个唯一cases，各40个，作锁定复核。
- 两组均已在既有研究中暴露，后者还被用于本轮 CPU 审计。不得称为 untouched confirmation 或新 test。新调用前核对身份／事件窗口分组；若跨组不满足原隔离规则，停止登记落地，不拆组凑数。
- 复用 roster 而非按错误类型／是否答错挑样。RE2 不在本次有界机制开发中；结论限于这三个数据集，不能声称完成五数据集泛化。未来是否扩展 RQ480／新事件，须另行登记，不自动启动。
- 所有输入与完整输出、conversation、实际图像、逐例成本及状态落盘；历史原始结果和 scorer 保持。相同完整请求在同模型及评分契约兼容时可复用；重复调用若登记为噪声测量则必须另设 replicate，不得命中缓存。

### B. 三个正交因素：P、H、K

**共同底座**：保留原 TPV 的 M/R/L 文本、候选、诊断方法和 G 图，不让新增信息挤掉底座。追加原始观测预算固定为两 tokenizer 均不超过2048 tokens，最多四包、每包最多四项观测；新增关系块独立预留最多512 tokens。两模型使用相同公开事实和同一图像，CPU 统一按两 tokenizer 可满足的共同界限选取，不各自截断不同证据。

**P：证据优先级，0=旧规则，1=影响规模／持续性／去冗余。**

- P0 继承 RQ3.3 已冻结的 W_RAW 选择。只有完整请求相同时才能称旧 W_G 直接复用；若共同预算使选择变化，明确注册新校准，不伪称逐字桥梁。
- P1 保留共同候选池、统计窗口、数值和类型定义，仅改优先级，不更换统计投影。对于连续量，将变化幅度与持续比例分开记录：相对尺度使用 `max(1.4826*MAD_ref, 0.01*abs(median_ref), 已知测量分辨率)`；分母仍为零时不得生成无穷分数。常量仅因极小分母产生的巨大 Z 不获得额外优先级；上升和下降均处理。
- 持续比例是在同一公共 current 区间、有限观测 bins 上超过注册偏离阈值的比例，同时记录观测支持；缺失不填零。离散状态、计数器重置、流量率分别按已有测量语义处理，不把它们伪装成连续资源 Z。
- 同测量语义／单位内按幅度、持续性、观测支持作非支配排序；跨不兼容机制不直接比较物理量，也不将每组第一名都赋予相同“诊断第一”。有限预算内优先新增观测支持的机制与实体，重复实体／同向同语义曲线只保留更有支持的项目，再按冻结 hash 打破并列。
- 这是待 CPU 验证的确定性工程规则，不是根因概率。其相对旧规则的实际差异、并列率、重复率与基于 private 标签的离线 repair/break 均须记录；不能用标签调权重。

**H：宿主—实例范围，0=原候选包，1=显式 scope 对照。**

- 四包中最多两包可用于 scope 对照，仍计入同一预算，不增加总容量。候选按已观测 node→pod、service→pod 归属生成；每包最多“宿主自身、焦点实例、同宿主另一个实例、同服务异宿主实例”四项兼容观测，来源不足时保留实际存在的部分。
- 对所有有来源的实体生成候选，不能先看模型的根因提名，也不能按已知故障类型路由。不强制完整四元组，单侧资源／状态信号仍可入选。包优先级采用所处 P 水平的规则，H 不能暗中顺带启用 P1。
- 目标是呈现观测影响范围，不直接输出“共享宿主故障”“单 pod 故障”。调用边不当作宿主关系；监测中断不当作零流量／健康；peer 的稳定必须有足够观测和同语义同区间支持。
- 无合格 scope 关系时退回同一 P 规则并显式标记 no-op，case 仍计入主分析。不得把“图端点出现了”计为该实体自身遥测被覆盖。

**K：来源可核验的关系，0=原观测，1=确定性关系编译。**

- K0/K1 的原始选中观测、顺序和图像完全一致；K1 的附加关系只可由这些事实推出，不访问未展示的 private 或完整池额外事实。
- 声明键必须包括 `entity / region / measurement / interval / unit / source_id`。G 的 displayed onset 与某个具体 latency series 的 onset 不混用；匿名类型、显示精度区间、明确 calls/hosts/owns 分开。
- 输出是事实级内容，例如“已显示 G onset 区间 A 完全早于 B”“已观测宿主关系 N→P”“同语义指标在指定区间的变化方向”。不提供根因分数或红色根因提示，不把时间先后转成传播因果。
- 公开绑定不明确、事实相互冲突或求解 unknown 时，不产生确定断言；只在离线审计记录，不能往 RCA 输入添加无诊断意义的 missing／solver 状态说明。相同区间不强行排序。
- 关系块采用实体局部绑定，统一且有限长度；按已选观测顺序与稳定规则生成，而非按最早／最异常实体排序推荐根因。底座与原始操作数不可为腾位置删掉。
- 候选检查用普通集合；SMT 与普通区间／关系程序对相同受支持声明做 CPU 等价性检验。若结果相同，不浪费 GPU 比较后端名称，也不把 Z3 本身作为创新。当前核验原型尚不支持生产级完整语义绑定，必须先实现并测试。

### C. exp_contract_alignment：输出损失单独拆开

60 cases、两模型，三个条件，最多 **360 calls**：

| Arm | 改变 | 保持 |
|---|---|---|
| SIRCL_NATIVE | 既有 SIRCL_TEXT 请求 | 原证据／模型／评分；只作历史桥梁 |
| SIRCL_IDS | 将不匹配的名字例子最小适配为 case-local 数字 ID，明确3/4/5位及候选闭集 | 其余方法、证据、候选顺序及 JSON schema |
| SIRCL_IDS_ALT | 在 IDS 上仅增加“保留有独立证据支持的备选解释，不为凑数填满五个”的候选提名提示 | 不要求固定候选数，不扩大 max_tokens |

IDS−NATIVE 检查契约适配；ALT−IDS 检查提名提示。分别报告 AC@1、AC@5、MRR、列表长度及无效 ID，不以 AC@5 因列表变长而提高就宣布推理更好。其发现限于该文本管线，不自动改其他 arm 的 prompt。此实验不用于挑选后续主方法或改旧评分。

### D. exp_evidence_reasoning_factorial：统一主实验

固定 G 图式承载，运行 `P∈{0,1} × H∈{0,1} × K∈{0,1}` 全部八组合；另加 TPV 和等追加观测预算的 P0_MORE_TRUE，共 **10 arms ×60×2＝1,200 calls**。

| P | H | K | 含义 |
|---:|---:|---:|---|
| 0 | 0 | 0 | 原规则追加观测，新共同预算下的校准 |
| 1 | 0 | 0 | 仅改善证据优先级 |
| 0 | 1 | 0 | 仅加入宿主—实例 scope 对照 |
| 1 | 1 | 0 | 新优先级与 scope 结合 |
| 0 | 0 | 1 | 原选择＋可核验关系 |
| 1 | 0 | 1 | 新优先级＋可核验关系 |
| 0 | 1 | 1 | scope 对照＋可核验关系 |
| 1 | 1 | 1 | 预注册统一主方法，不事后逐 case 选最优 |

原始观测预算一致，K1 额外关系块成本单列，不能将其与 K0 的差称为严格 token 相等。P/H 的条件效应在各 K 背景下分别计算，并计算二阶／三阶交互；不把条件贡献称普适贡献。三个因素同时固定后才进行新调用，不能跑一半发现成绩不好就换规则。

### E. exp_verified_visual_binding：核验、重复提醒和视觉分开

固定 P1H1，不根据上个实验谁最高分改变基准。`G 承载∈{完整文本ledger, 原真实图像} × 关系块∈{NONE, REPEAT, VERIFIED}`，六条件，每 case 的源事实与身份对应一致。

- NONE：原选中观测，无关系块。
- REPEAT：重述 VERIFIED 所用的相同实体、原始操作数与显式边，使用相同局部分组，但不提供派生先后／比较结论；按预登记规则匹配长度，不能塞无意义 padding 或替换未选事实。记录实际 token 差，不能声称必然逐 token 相等。
- VERIFIED：相同原始事实，加显式计算的关系。它包含派生断言，必须记录信息来源与推导，不能称与 NONE 逐字段完全相同。

图像 NONE 与 VERIFIED 已在因子实验中提供，严格复用；只新增 **4×60×2＝480 calls**。文本和图像获得相同关系块，不能只给图像额外证据。比较 VERIFIED−REPEAT 与同块图像−文本，检验关系可用性及选择性视觉的条件增量。

原 G PNG 不重画。这里先检验事实／关系的局部绑定和图文承载，不声称已经检验图内节点重排或完成新的布局搜索；后者仍属原路线中的条件式后续问题。所有关系文本均计入成本，这些 arm 应准确称为选择性视觉／混合输入，而非纯视觉。

### F. 核验作为所有条件的共同结果层

确定的候选契约错误与待复核的自由文本断言分别统计；报告可核验断言覆盖、输出长度、未解析／unknown 比例。错误变少但解释也变少，不作为无条件可靠性改善。针对类型、量、时间、调用／部署分别审核源事实绑定，并检查告警中仍然 AC@1 正确的样本；不把原 CPU 筛查的247份回答当真值。

这允许分别得出“检测有效但 MRR 未改善”“事实更可靠但诊断退化”“修复了实际排名”三种不同结果，不能相互替换。

## DD-RQ34-05：时钟指标的公共相对投影

**日期：**2026-09-24。**状态：**用户授权修复；本轮CPU验证，不追加GPU调用。

实际prompt核查确认追加 `container_start_time_seconds` 暴露绝对Unix时钟；同一完整public池另有 `container_last_seen` 和 `istio_agent_process_start_time_seconds`。仅排除启动时间会遗漏同类字段；按数值大小删除则会误伤内存/流量等普通大数。

采用 `relative_clock_v1` 显示投影：三种明确登记的秒值指标，以同case全部这类观测中有限reference/current median的最小值为共同原点，显示各median减去原点后的秒数，单位为 `relative_clock_seconds`。这是指标时钟的共同原点，不是注入时间，也不冒称观测窗口t=0。仅在实际选中时加一句对应单位说明。原点本身不进入prompt、关系块或projection sidecar；canonical数据及源观测保留原样。共同平移保留跨实体先后、前后变化与时间差；MAD、观测支持与公共统计窗口不变。聚合观测能支持启动时间变化，不能由两个median推出准确重启次数。

P/H仍用原始注册的统计量、排序及候选包；公共序列化与预算计算使用安全投影，K从实际显示值重新编译。所有T/G、NONE/REPEAT/VERIFIED条件共享此投影。相对值长度变化可能影响预算入选，必须实测并报告，不预先承诺全部成员不变。

NaN/Inf/非正时钟、单位不明确或新增值字段不能默默猜测：缺测None保持None，其余未注册语义在提交请求前报错。模型输入另做有指标语义约束的绝对时钟检查，发现继承文本或旧缓存中的时钟仍为epoch时拒绝提交；普通bytes/counts大数不据此删除。旧缓存没有投影版本标记时拒绝使用，需要显式的小范围缓存升级，不能靠flag自动掩盖旧科学输入。
