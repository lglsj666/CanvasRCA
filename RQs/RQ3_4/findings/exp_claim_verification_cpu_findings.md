# exp_claim_verification_cpu

状态（2026-09-24）：CPU 可行性核验完成，静态检查与 20 项单元回归通过。**零新增模型调用，无训练，无重评分。** 本文件是核验器可行性结果，不是新 RCA 方法的 performance 结果。

## 1. 已做什么

依据 [RQ3.4 协议](../descriptions/RQ3_4_experiments.md)，只读扫描 RQ3.3 check 的 120 个已暴露 cases、五个 arms 和两个模型，共 1,200 单元。1,197 个完整回答完成核验，另外三个单元是原队列明确记录的请求 timeout，没有补推理或忽略缺失原因。

当前结果：[summary.json](../results/claim_audit_v4/summary.json)、[全部逐回答记录](../results/claim_audit_v4/records.json)。输入、原句、断言、来源位置和 SMT 结果均可追溯。程序入口为 `bash RQs/RQ3_4/scripts/audit_claims.sh`；已完成结果防覆盖，再跑须显式指定新的结果版本。

固定环境已有 Z3 4.15.4；未安装依赖或启动模型。扫描／核验／汇总约 **3.57 秒**，每回答中位数 **3.13 ms**、P95 **4.35 ms**、最大 **7.96 ms**。这里读取的是已有小 JSON，使用进程内输入缓存，时间不包含最终结果 JSON 写盘；不是从 raw telemetry 开始的端到端 RCA latency，也不是未来完整自然语言解析的成本。

## 3. 一个已经抓到的具体问题

`INC-50C26A55D214 / Gemma / W_G` 原回答：把 `871` 称为 node，并声称其 onset 为 4.9m、`762` 的 onset 为 5.2m，进而声称 871 更早。

实际输入指南中两者均为三位 service ID；对应公开 G ledger 为 `871: +5.2m`、`762: +4.9m`。核验器指出类型不符及两处显示时间冲突。考虑显示精度后，两个保守区间仍不重叠，因此手动提供的“871 的 G onset 早于 762”断言被 SMT 反驳，并返回这两条来源；反向顺序获支持。

同一回答的 `810 calls 762` 获事实支持。也就是说，不必把整段 reason 一概判对或判错，可以定位到具体断言。进一步查询“762 就是真实根因”则返回 unsupported，因为没有合法的确定性因果规则将这些事实推导为根因结论。

图像事实在本次审计中取自已经登记的同事实文本 ledger：先核对 W_T/W_G 的共同文本，并核对被审视觉条件的 G 图像 hash。718 个视觉回答均通过这个来源对应检查；核验记录区分 ledger 原始 part/line 和编译后的坐标。这不是重新 OCR 图像或证明每个像素都可读。

## 4. 抽查也暴露了形式化风险

从两模型 × 两类 refuted claim 中，按 `SHA256(call_key + sorted JSON claim)` 各取两个，共八条，逐字阅读 reason 与证据；不是按根因是否正确挑选。结果记录在 [人工式核对表](../results/claim_audit_v4/manual_review.md)（由本助手阅读，不是双人标注或人工研究）。

其中 `INC-8E0FB1B7B3FE / Qwen / P0_MORE_TRUE` 声称的是 **exclusive-latency onset 34m**，核验器匹配到的 G 字段却是 **M 来源的实体 onset 33m**。两者不是同一个量，不能仅因数字不同确认它幻觉。这是候选 claim 形式化的边界，不是 SMT 求解错误。

因此现在只对清楚的候选契约错误自动定性；解释筛查保持 review_required。后续部署必须提供 quantity/region/entity/source 的明确绑定，或者遇到歧义直接返回 unknown。不能把模糊断言转成错误前提，再用证明器“证实”它错误。

## 5. 下一步决定

保留**低成本、来源可定位的事实核验**作为正式研究方向。它不需训练，且不依赖先跑另一个模型得到“标准答案”。

下一阶段优先做强 TPV 背景下的小规模、同事实对照，而不是扩大 Witness：原输入、等长度普通事实重述、确定性关系编译，以及对应文本 G 对照。先明确类型与量的绑定，测量真实错误的修复、原本正确答案的 break、MRR 和额外 tokens；不能只看输出变得自洽。

纯 ID 检查用集合操作即可。时间关系目前也能用普通区间运算实现，SMT 的价值在可组合约束、冲突定位和证明记录，而不是给简单检查改一个新名字。后续必须保留普通规则核验的相同语义对照；若没有收益，不坚持使用 SMT。

本次没有改写候选、修正历史回答、重新评分、开启 vLLM 或新增 GPU 实验。正式的推理改进及 MRR 增益尚待后续受控验证。

五个功能模块加包标记，约 1,007 行非空非注释源代码；Ruff、格式检查、语法编译和 20 项 CPU 测试通过。包括 open-world、反向关系、四舍五入、单位／语义不兼容、矛盾前提、防 private 对象传入和图文来源绑定。
