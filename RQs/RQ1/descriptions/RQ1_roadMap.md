# RQ1 Road Map

RQ1 follows a qualitative mechanism-to-outcome sequence; it does not use a
result-dependent roster or a rigid numerical branch tree.

1. Freeze the 469-case eligible evaluation roster and the 289-case headline
   subset before model execution; preserve the eleven invalid exclusions.
2. Rerun `legacy_q9`, `cross_region`, and `typed_two_stage` on Nibi to establish
   direct readability, cross-region composition, and handoff behavior using
   Q&A T/P/V/H and actual renderer-v12 factorial crops under one final runtime.
3. Run `direct_rca` and `matched_rca` to determine whether the representation changes actual
   ranked root-cause performance rather than only intermediate operations.
4. Run `visual_counterfactual_rca` to test whether controlled visual semantics
   causally move evidence selection and rankings beyond placebo or blank-image
   sensitivity.
5. Run `ledger_handoff_rca` to locate any remaining loss before versus during
   the agent handoff.
6. Report the three primary datasets together only through paired case-level
   evidence; report AegisLab, each AIOPS dataset, RE2-OB, and final-OOD RE2-TT
   separately. Saturated RE2 results cannot establish the headline claim.
7. If visual evidence is readable and causally influential but does not improve
   RCA, carry the identified failure point into RQ2 rather than redescribing
   influence as utility. If an equal-fact visual or routed arm improves RCA
   without material dataset-specific harm, freeze it as an RQ2 candidate.
8. Treat fixed-canvas density, blank-space compaction, and other layout/content
   redesigns as RQ2 variables. Do not tune them on RQ1 final outcomes.

All seven experiments use new final result lineages and the unified contracts. Their
records carry model-call-free renderer-density and ledger-region diagnostics.
The v17 Q&A correction removes the Controlled text canvas from formal arms;
that canvas remains historical diagnostic material only. The v16 two-stage
RCA successor remains unchanged and uses compact, non-null visible record keys
rather than model-transcribed telemetry arrays or nullable identity tuples;
deterministic binding supplies exact facts to Stage 2 and records rejected
keys in the grounding audit.
Every visual request additionally captures the registered Q-to-visual-K
attention vector and heatmap during its existing prefill, with zero additional
model calls or experiment units. This diagnostic remains correlational and
does not form an eighth experiment, a performance gate, or a causal claim. Smoke
correctness never selects a method, partial formal outcomes never tune a prompt
or roster, and historical local results are not mixed with final Nibi cells.
The formal runner processes up to four different cases concurrently while
preserving within-case arm order and two-stage dependencies.

Execution ownership is whole-experiment. Nibi advances one experiment at a
time: all Qwen shards, then all Gemma shards, then verification, before the
next experiment is activated. It must not interleave a few shards from several
experiments. `direct_rca` and `matched_rca` are local whole-experiment heldouts;
the remaining five experiments are Nibi-owned. Different sites may work on
different whole experiments concurrently, but may not split one experiment.

Before a heavy rerun, compile and audit every registered arm against both
effective model contracts without model calls. Each of the seven experiments
then receives exactly one independent bounded smoke covering both Qwen and
Gemma. Within each experiment's single logical smoke, Qwen and Gemma each have
an independent 18-call allowance; the 600-second bound remains attached to the
corresponding model phase. The model phases run sequentially, so a complete
two-model logical smoke has at most 1,200 seconds of active phase time. A
one-model smoke cannot authorize a two-model final
run, and an omnibus smoke spanning multiple experiments is not permitted.
Exhaustive per-arm live inference is unnecessary when the experiment's static
matrix covers equivalent serializers and its bounded live matrix covers every
distinct request path and response schema.

CPU preparation remains separate from GPU inference. During a stable formal
run, record queued/running request depth together with GPU utilization and
throughput. Short idle transitions at startup, shutdown, or a model boundary
are operational metadata; repeated idle periods while runnable cases remain
indicate a runner-throughput defect that must be repaired without changing the
scientific prompts, arms, or model-specific inference recipes.
