# Qualification and stopping boundary

Current authorized endpoint: implementation and static checks, then STOP. Static execution does not prepare a case, create a dashboard, import the model, run tests or authorize a later stage.

Future sequence, only after user authorization:

1. Source-bound CPU permission; unit regressions, renderer build, complete 220-case preparation using <=8 independently pinned physical cores, source/cloudbed round-robin dispatch. Freeze QA targets and public strata before new answers.
2. Audit facts/candidates, explicit new complete-pair source delta, 4096²/28-card bounds, glyph differences, actual processor grids, D/O, fusion partitions, request capacities and all independent single-question proofs. No scientific/capacity failure is bypassed by shrinking text or dropping a case.
3. Offline processor/MRoPE, atomic commit interruption, references versus independent repeats, central scores, invalid-answer accounting. Finite manual image review <=6 new images including three datasets and dense/long-name/markless cases.
4. Freeze queues and source snapshots. Three independent GPU scopes: organization/hybrid, operators, QA; each <=18 attempted calls in its single 900-second window. Actual output errors are recorded, not retried for correctness. Numerical GPU/tensor checks share the operator scope. Review exact submitted PNGs/prompts/raw responses/scoring/attention and per-path activity.
5. Source-bound formal authorization requires every prior qualification and three reviews. Run heavy preparation before GPU startup. 8 CPU workers, 8 request slots, bounded 24GB prefetch RAM; vLLM BF16, memory utilization .8. Pause file drains active calls; power interruption resumes from atomic commit markers without bulk graph revalidation.
6. Finish all writers; analyze before retention cleanup. Verify every required conversation object/hash, evaluator context, source/operator/attention mapping. Retain readable shared objects; remove only redundant own cache/preparation. Storage <=2.5MB per completed actual call and attention accounting <=0.1MB per call. Open conversations with `view --key` or the generated local HTML index.

No CPU, visual, GPU or speed qualification is claimed in the static-only delivery. In particular the new complete-pair pure-visual canvas capacity, real processor behavior, renderer pixel compatibility and native GPU numerical behavior require future execution.
