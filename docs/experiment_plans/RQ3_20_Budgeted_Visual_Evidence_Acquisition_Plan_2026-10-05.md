# RQ3.20：视觉引导的预算化取证，以及“读懂—取证—诊断”的脱节机制

日期：2026-10-05。用户已明确要求实施本计划。单主 agent；新一轮最多 3,000 次调用。执行顺序为先 CPU 可行性、实现与静态、完整 CPU/视觉资格、共享 GPU smoke、冻结开发批次和条件性验证。CPU 科学语义或预算失败即停止候选，不放宽门槛。状态以 RQ3.20 唯一 findings 为准。

## 1. 主线、决定与历史依据

**研究遥测证据的表示方式如何影响诊断决策，并据此构建更准确、更省成本的 RCA 方法。** 下一步改变视觉参与诊断的位置：先检验它是否帮助选择值得查看的证据，再由精确文本支持最终诊断；同步追踪读取改善能否通过取证行为转化为排名改善。

| 已有证据 | 本轮设计决定 |
|---|---|
| RQ1.1、RQ3.6、RQ3.7：部分条件下关系视觉有益 | 检验视觉关系在取证阶段的作用 |
| RQ3.8、RQ3.17：完整图形及组合可能退化 | 不把全部图形追加到最终诊断请求 |
| RQ3.14：窗口摘要文本有效 | 以既有摘要构造概览 |
| RQ3.1、RQ3.2：选择器曾丢失资源和 node 证据 | 全部原事实留在账本，概览不只保留显著服务 |
| RQ3.11、RQ3.19：视觉压缩未达到目标 | 不重启数值写法、精确补丁、少量字段移交路线 |
| RQ3.19：读取辅助改善 QA，未建立对应 RCA 收益 | 检验读懂以后是否改变取证和诊断，不用 QA 分数路由 |

RQ3.19 视觉替换相对完整文本配对 ΔMRR 约 −0.0450，各数据集总 token 增加约 2.8%。跨轮约 0.4 到约 0.5 的成绩不能当作同一方法连续提升。important_docs 的双线主线保留；“QA 校准表示分配”仍待验证。

问题：**相同概览事实下，视觉是否帮助取回更有诊断价值的明细，并在计入全部调用后超过强文本？** 工具取证、事实 ID 与视觉工具本身不是首创。与 [ThinkFL](https://arxiv.org/html/2504.18776v2)、[ChartAgent](https://aclanthology.org/2026.acl-long.843/) 的增量在于读取、选择证据与最终决策的阶段差异及受控 RCA 成本证据，不能预先宣称新颖性或正结果。

## 2. 方法、接口和预算

预选方法 **VISUAL_FETCH**，最多两次模型调用。继承 RQ3.19 全部公共事实、候选、单位、窗口和评分。原始序列、样本与 M/R/L/G 全部可按稳定 ID 回取。来源证明留审计侧，标签和历史回答禁止进入公共包。

- `EvidenceLedgerV1`：完整公共事实及来源绑定。
- `EvidenceIndexV1`：概览字段、可回取的明细包及预算信息。
- `FetchSelectionV1`：最多八个不同明细包 ID，按优先级排列，不含根因排名。

概览保留所有既有指标、Trace、日志的实体绑定和摘要，以及完整公共关系账本。长序列和请求样本按需回取；候选不减少。文本/视觉概览只切换关系结构的载体，其余事实相同。视觉复用 unified renderer 的实体节点和有向箭头，调用、部署分开；不追加边际图，不新增拓扑画法、异常严重度或因果边，不通过删边、缩字体或调 processor 像素限制过预算。

选择阶段最多输出 512 token，宿主按 ID 回取精确原文。包单位为完整指标序列、操作记录、日志模板或请求配对，携带单位、阶段、实体和必要关系。最终统一为公共概览＋精确明细文本，保留原五候选 JSON、解码配方和 8192 输出上限，不传递选择阶段解释、置信度、临时排名。

按优先级整包装入，不截断数组。超预算的包跳过并审计；无效选择回退无新增明细概览，不修补 ID、不重答。基础设施中断保持未知。

设原完整文本实际输入为 F_i：首轮概览输入 ≤0.40F_i；两轮输入＋首轮预留 512 输出 ≤0.85F_i。T/V 共用最终预算，首轮按两种概览的较大实际输入预留。图像、提示、候选、重复传输全部计入；每请求输入＋输出上限 ≤40960。概览或最小完整明细包不能容纳时，所有概览/取证条件共同回退完整文本，仍在分母内。三个数据集各至少 50% 病例合格才进入 GPU，否则停止。

这是相同可用账本/概览事实下的工作流比较；选择不同导致最终明细不同，不称为相同最终输入的纯表示收益。

## 3. 实验、机制与调用登记

220 个已暴露 eval：AIOPS-2022/2025 各60、AegisLab100。所有配置和抽样在调用前冻结。

| Arm | 每例调用 | 设计 |
|---|---:|---|
| FULL_TEXT (F) | 1 | 冻结完整强文本 |
| SUMMARY_TEXT (ST) | 1 | 文本概览直接诊断 |
| SUMMARY_VISUAL (SV) | 1 | 同事实视觉概览直接诊断 |
| TEXT_FETCH (T) | 2 | 文本概览选择，精确文本诊断 |
| VISUAL_FETCH (V) | 2 | 视觉概览选择，精确文本诊断；预选 |

按固定哈希预选60例（各20，优先不同事件组），每例 T/V 各一次完整独立重复。输入可相同，调用身份必须独立；普通条件可以引用本轮完全相同的请求结果，须标明引用并计逻辑部署成本。

机制线保留原始 V 选择集，再由公共数据构造两类正确读数卡：关注组涉及所选明细的实体；匹配组不涉及这些实体但关系类型和复杂度匹配。卡片仅重复概览已有事实，不加入标签/建议；关注组不等于真实根因相关组。不适用病例记录，不按成绩替换。

每例七次新调用：无卡/关注卡/对照卡三次独立 QA；关注卡/对照卡两条完整取证流程（各两次）。固定检查实体、类型、方向；QA 输出不传 RCA。追踪读取准确率→取证集合→回取覆盖→RR，病例作为统计单位。

Attention 仅在固定机制子集复用真实调用，小样本被动记录既有首个 full-attention 层、prompt query 与至多128个注册输出token的聚合。每调用≤64KiB；含索引、临时文件每万次峰值<十进制1GB。不保存全矩阵、Q/K/V或逐调用热图；真实processor几何区分标题、图元、标签、文本。测量显存/开销，失败或不合格关闭，不阻塞主实验。本轮不删除sink token、不做VAR；高attention不代表因果使用或有害sink。

## 4. 判定与收官

主要族 V−F、V−T、V−SV；病例、事件组分别三项Holm。双侧Pratt-zero Wilcoxon，差值12位，配对dz，不报告CI。次要族 T−F、(V−T)−(SV−ST)、T/V各自重复差异。QA读取干预与RCA干预单列机制族。

方法门槛：V−F整体≥0.03，病例/事件组校正均通过；三个数据集MRR、AC@5点估计不下降；每数据集全阶段实际input+output/F≤1.05，优先降低≥15%；重复主要方向一致。视觉归因门槛：V−T≥0.02并通过校正；V−SV为正且通过校正。只有交互获支持才声称阶段差异。整体有效而单机制未建立时承认整体收益，收缩机制主张。

MRR≈0.60是目标而非保证。不超过强文本就结束候选，不自动改图/预算或追认事后赢家。模型无效回答原零分，基础设施缺失未知，配对与全分母紧界限分开。报告绝对MRR、AC@1/3/5、AVG@3/5、逐集/宏平均、修复破坏、失败、成本、重复。固定哈希每集12例审核实体、单位、关系和无依据因果断言。

## 5. 实施与验证

代码 RQs/RQ3_20，五功能模块≤7500行，所有图经过 src/renderer。单主agent、最多8个不同物理核worker、优先分散source/cloudbed。保留历史源、数据、结果与默认绘图语义；跨缺测连接、不标记缺测。

1. CPU可行性先行：220例账本、事实一致、明细回取、实际processor预算和共同回退。失败停止。
2. 实现及静态：白名单、冻结依赖、调用上限、标签边界、入口默认关闭。
3. 完整CPU/实图：零/缺失/长名/密集图/重复事实/超预算/坏ID/原子提交/恢复/真重复。
4. 三个固定eval身份共享18次/600秒GPU smoke，包含启动保存验证；本地Qwen、40960 context、0.75显存、并发36。不按MRR调参，不重置已耗额度；修复保留历史失败。
5. 资格通过后运行冻结开发批次，按依赖和哈希交错；不按部分成绩改变队列，排空后统一审计。
6. 方法通过后冻结，在提前按事件组和曝光记录选定的90例（各30）运行F/T/V最多450次；无足量隔离病例则报告受限，不改名独立测试。

目标是在授权后两天内完成主要开发批次与决策，随后优先完成合格基线/冻结验证；attention兼容不延误决策。实验结束关闭自有服务，更新唯一findings、计划索引和devlog。CPU门槛失败同样有明确终态报告，不能登记为GPU已通过或已执行正式矩阵。
