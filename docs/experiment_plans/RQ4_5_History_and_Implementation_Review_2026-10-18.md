## Literature-to-design map

[SeeRepo, arXiv 2606.14061v4](https://arxiv.org/html/2606.14061v4) motivates assigning graph structure and precise content different carriers. Its repository exploration is multi-step and does not establish savings or improved RCA in a single call. It also does not establish strict source-exclusive ownership; that is this candidate's constraint to test.

[FEATHER](https://arxiv.org/abs/2412.13180) motivates grounding/localization checks and caution about attention-based selection. This implementation does not copy its architecture-specific pruning recipe or claim that our geometric selector is FEATHER.

## Concrete implementation choices and limitations

- Duration sample/static numeric spellings are recovered from frozen source tables, with visible labels bound to actual sample glyphs; parsed floats are only positions.
- Public pair records are whole-source ownership groups. Distinct relation IDs define separate source-local sampling groups; parent/child and both phases support that same record. Equal entities never merge observations.
- Original standalone public `request_parent` relationship observations retain their own source occurrence; necessary pair endpoint identities are permitted join labels, not additional diagnostic text.
- Topology metadata support counts use the existing inventory/details component next to actual graphs; no second new drawing grammar is introduced.
- New renderer code is opt-in. Existing component implementations and prior config entries are preserved. Integration changes extend validation, types and registration only.
- CPU preparation and model transports are lazy imports and separately gated. Static checking neither instantiates test cases nor imports GPU models/processors.
- Runtime inherits the native vLLM gather/MRoPE path with isolated RQ4.5 activation, 1700 shared attempt ceiling, 18-call aggregate smoke, 122 recovery reserve, 8 workers/8 concurrent requests and bounded RAM prefetch.
- Post-run retention validates exact images/conversations and measured attention. The code contains a hard final density audit; current storage compliance is not claimed before actual artifacts exist.
- Required follow-up still includes all 220 numerical/ownership/geometry/token checks, actual image review, independent offline runtime regressions, model/processor provenance freeze and GPU qualification. Static success establishes none of those empirical gates.
