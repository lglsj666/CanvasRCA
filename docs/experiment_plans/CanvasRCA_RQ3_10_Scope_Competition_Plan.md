## 1. 核心判断与可证伪主张

MRR 优先。本轮聚焦 AIOPS-2022/2025：同一组异常，究竟支持局部实例资源变化、
跨实例的同服务资源变化，还是跨服务的同宿主资源变化？

不以根因标签粒度直接定义故障影响范围。service 标签也可能对应单个故障 pod；
宿主故障并不必然影响每个实例。这里的计算是对**已观测资源变化范围**的支持、
有条件软冲突与未知，不是因果证明、根因概率、健康判定或硬排除规则。
网络、代码、请求组成等故障仍依赖保留的原 M/R/L/G；资源范围解释不完整时允许不适用。

新发现的目标是区分三环：补入可比较观测 → 显式整理支持/软冲突 → 用共享空间显示这些观测。
若精确文本和 CPU 排名已解决问题，而图像没有增量，必须保留这个结果。

### 3.1 完整池、选择与资格

复用已提交的 WitnessPublicContextV1 的**完整**公共 Metrics 观测目录，并从其对应
canonical public per-case metrics.parquet 一次读取 timestamp 和所需列。该上下文不是历史 top-k。
不重新扫 raw 日志/Trace、大表或 cloudbed；不加载 private/natural-to-label 映射来绑定。
源列→匿名实体、公共窗口及同一案例关系必须和冻结锚点一致，否则准备失败，不偷偷改 ID。

补充上限十二个 series；最多四个已知 service 行、三个已知 node 列，另有明确未绑定槽。
先选最多两个基础资源观测作为锚，再以关系类别轮转补入同服务跨宿主、同宿主跨服务、
同服务同宿主及宿主自身观测。类别内按稳定 hash 排列，不按 gold、成绩、模型输出或异常大小选对照。
入选的非基础观测即使未变化也可保留；所有选择/省略原因保存离线审计。

只有登记的精确指标键可参与资源范围计算；累计 counter、state、配置值、未知语义均
不被当作利用率。它们仍在原输入中。未知计量单位保持 source_unit，不猜换算；
peer 的数值比较要求相同指标键、单位与公共窗口。

64 个共同时间箱，baseline/current 分界继承原公开分析窗口，绝不用注入时间。
源样本先按阶段分开再分箱；跨分界的箱不能混入另一阶段。
每阶段需 >=3 个有效样本；baseline >=8、current >=3 个有效箱且有限箱覆盖 >=0.8。
尺度为 max(1.4826×baseline MAD, 0.01×|baseline median|)；零尺度明确未知，不能无穷大。
变化：|current median−baseline median|/scale >=3 且同向改变箱比例 >=0.5。
稳定：该比值 <=1 且所有当前有效箱距基线 <=3 scale；中间状态为不确定。
上升和下降均记录，但“变化”不自动等于资源压力或故障源。

Trace 当前/基线正请求计数（来源到对应实体直接绑定，各 >=5）证明活动；无 Trace 时，
登记的累计请求计数器在两阶段各有正增量且无 reset 才证明活动。不能从资源数值非零、
日志少或采集存在推断活动；没有活动证据的稳定实例标为 unknown，不能用于软冲突。
活动观测实际进入补充文本；不只写进 manifest。

### 3.2 三类解释与计算

所有解释仅针对展示的资源变化，不是三类互斥的真实 fault type：

- 局部实例：一个 pod 改变，合格同语义 peer 稳定是局部解释的支持；peer 改变只降低其局部性。
- 同服务共享：至少两个不同 pod、不同 host、相同指标/单位的改变构成支持；
  合格活跃跨 host 稳定 peer 是软冲突。只有同 host 实例不能区分 service 与 host。
- 同宿主共享：至少两个不同 service 的 pod 在同 host、相同指标/单位改变构成支持；
  合格活跃同 host 跨 service 稳定 peer 是软冲突。node 自身改变是附加支持，不能代替实例对照。

每项保存参与观测 ID、规则、支持/软冲突/未知以及不能判断的原因。
同语义改变的方向也需一致，反向改变保留为未知，不直接投共享支持或健康票。
单独一个改变锚点不能证明任何范围，包括局部实例；没有合格 peer 时不给局部解释支持票。
资格公式、阈值、实际样本/箱数、覆盖和活动计数在所有补充条件共同显示，不能只在带计算条件
中偷偷多提供数值；仅支持条件的规则文字也不包含软冲突说明。
未显示的实例、未知映射、低覆盖、不活跃及不同语义的指标不能投健康票。
无合格比较时整例照常诊断，只是范围计算不适用；不得从主 MRR 中选择性删除。

CPU 排名：用同一范围账本计算每个候选的 support/(1+support+conflict)，
没有信息者为零；并列用固定 hash，不按异常度或根因粒度加权。
单独报告覆盖、并列与不适用比例；此分数不是概率，不给 Solver 看 CPU 排名。

## 4. 一轮六条件，先做小而有解释力的比较

暴露 eval：AIOPS2022 60、AIOPS2025 60、AegisLab 20，共 140。
按 seed42 + 版本 + opaque ID 固定 hash；既不按难例、label，也不按历史成功抽样。
这不是 untouched 测试，Aegis 的 20 例不用于宣称完整迁移能力。

| 条件 | 模型看到什么 | 目的 |
|---|---|---|
| BASE_TEXT | 冻结原完整公共文本 | 本轮锚点；历史强基线另只读配对，不改旧输入 |
| CONTROL_TEXT | 原文本 + 同预算补充源观测、活动、窗口和归属 | 测“补入了信息” |
| SUPPORT_TEXT | 同 CONTROL_TEXT + 仅支持账本 | 校准已有正向证据整理，缺省不代表其他证据不存在 |
| SCOPE_TEXT | 同 CONTROL_TEXT + 支持、软冲突、未知及规则的精确文本 | 测有条件否证/不确定性整理 |
| SCOPE_MATRIX | 完整 SCOPE_TEXT + 同观测的 service×node 图形板 | 测强文本已有全部信息时视觉冗余的增量 |
| SCOPE_TILES | 完整 SCOPE_TEXT + 完全相同图形，取消 service×node 共享排列 | 测共享坐标，而非有图本身 |

SCOPE_MATRIX 与 SCOPE_TILES 使用同一证据 DTO、图元、字体、总画布、每个 cell 尺寸、
数字精度与颜色。只改 cell 的位置与公共行/列标头的排布；每 cell 保留实体/host/service标签。
没有事实的矩阵格是明确未展示，不声称“无故障”；映射未知进入 Unknown 栏，而非删除。
并列条/点显示 baseline/current 或有符号标准化变化（轴固定 [-6,6]，溢出箭头与确切值同时显示）；
颜色表示增减/未知，绝不表示根因优先级。图中保留 qualifier 与活动证据标识。
所有补充条件共用条件式图形阅读说明（有图时适用）；视觉条件只添加 PNG，不再额外添加指南。
因此 SCOPE_TEXT 与两个视觉条件的全部文本和任务说明逐字段一致，而不仅是数值事实相同。
CONTROL_TEXT−BASE_TEXT 是补充源观测、公共资格数值与阅读契约的合并校准，不能把其差值
只归因于“更多实体”。SCOPE_TEXT−CONTROL_TEXT 是整个显式资格/解释账本的效应；
软冲突与未知的增量需看 SCOPE_TEXT−SUPPORT_TEXT，不能仅凭 primary 成绩宣称来自否证。

已有组件库和操作库全部保留；新增 scope.matrix、scope.tiles，两者复用同一 cell 组件。
此实验允许跨文本/图像重复，目的是检验额外图形编码，而非声称输入信息不同。

四项 primary（同一个 Holm family）：
SCOPE_TEXT−CONTROL_TEXT；SCOPE_MATRIX−SCOPE_TEXT；SCOPE_MATRIX−SCOPE_TILES；SCOPE_MATRIX−BASE_TEXT。
primary 检验病例为 120 个 AIOPS；分别报告两个数据集、等权 macro 和配对 pooled。
secondary：CONTROL_TEXT−BASE_TEXT、SCOPE_TEXT−SUPPORT_TEXT、SUPPORT_TEXT−CONTROL_TEXT。
Aegis、fault type、根因层次、适用范围的分层属于预先定义的探索性分析，不能替代整体检验。

## 5. 统计、模式与扩量决定

MRR primary；AC@1/3/5、AVG@3/5、top5→top1、前五新增、repair/break、非法ID、
输出失败、输入/图像/输出tokens、提取/渲染/推理时长、完整成本同时报告。
配对 Pratt-Wilcoxon、paired dz、Holm；不报告 CI。重叠事件用注册 leakage_group 做组级敏感性分析。
每个 arm 自己的 design-infeasible 排除且列出；比较使用共同可执行集合，不置零。
model-output failure 保留原零分；请求 timeout 是缺失，给共同配对与最坏/最好缺失界，不设5%门槛。

分析链：原输入根因/机制证据是否存在 → 对照能否资格化 → 解释是否可区分 → 模型是否引用 → 排名。
同时查看修复、破坏、不变：局部 pod 被升为 node、node 被降为 pod、service标签对应单实例、
资源解释无法覆盖的网络/代码案例。标签仅离线分层，不改变选择/图形/规则。
数值引用与归属可确定性核验；自然语言诊断依据只作人工可复核探索，不伪装自动语义真值。

本轮结束先完整分析，不自动扩量。后续考虑条件：AIOPS macro ΔMRR>=0.03、
两 AIOPS 各不退化超过0.03、同 SCOPE_TEXT 视觉差为正、无系统性 node/pod 伤害；
这些是探索性扩量信号而非显著性或非劣证明。若只有文本改善，保留可用方法并停止视觉分支；
若对照大多无法资格化，先报告可观测性缺口，不靠降低健康资格来制造结论。

长期目标仍是 test MRR>=0.65、两 AIOPS 各>=0.60，本轮不保证达成，也不提前开独立test。
