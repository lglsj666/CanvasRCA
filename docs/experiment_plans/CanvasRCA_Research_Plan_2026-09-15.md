## 1. 项目定位：高 MRR 是前提，视觉必须提供可验证的增量价值

建议将项目范围确定为：

> **面向冻结、单次调用 RCA 模型，研究如何选择能区分竞争根因的遥测证据，并通过视觉组织提高诊断准确性、证据可靠性与效率。**

研究的核心不再是“把遥测画成图”，也不是“尝试足够多的方法，总能有一次答对”，而是：

**面对多个同时异常的组件，系统能否选出有区分力的证据，让模型把故障源与受影响组件分开，并给出能够核验的高质量排名？**

部署边界：

- 一个冻结的 RCA Solver，一次调用，最多一张真实 dashboard。
- Qwen3.8-27B 为主模型；Gemma 为跨模型检验，不混合两个模型的答案。
- 允许纯视觉，或最多一个模态采用文本、其余模态进入同一张图。
- 完整候选列表、公共任务和静态指南仍放在文本中。
- 第一版不训练模型，不增加先诊断一轮再检索的推理循环。
- Composer 的 SFT/RL 是条件式后续工作，不是本篇论文必须完成的环节。

评价优先级为：

1. **MRR、AC@1 和 AC@5，以及跨数据集稳定性。**
2. **答案依据是否真实、实体和关系是否绑定正确。**
3. **对噪声、无关上下文和非语义变化是否稳健。**
4. **输入、输出和完整系统成本。**
5. 提供可复算的来源绑定、失败分析和自动核验覆盖率。

不能用“更好看”“更省输入”弥补明显的诊断退化，也不预设视觉一定胜过文本。

修订 3 把希望检验的主线进一步收敛为：**在有限上下文中保留能区分竞争根因的完整比较，并检验视觉是否使这些比较更容易被正确利用。** 方法贡献是诊断对照的构建与预算选择；视觉贡献必须在强文本对照下单独成立；机制与独立验证共同支持二者。不是给旧方法增加术语，也不承诺任何 reviewer 会给 Strong Accept。

## 2. 两篇新论文如何改变技术路线

### 2.1 多源数据的价值取决于选择和组织，而非来源数量

已完整阅读的 *Too Many Cooks: Assessing the Need for Multi-Source Data in Microservice Failure Diagnosis* 是 ISSRE 2025 研究论文。它比较了多种诊断方法及数据源组合，发现增加来源可能引入冗余、无关信号和相互干扰；有些方法删除某个来源后反而改善。其日志结论依赖具体数据集及方法，不能直接转化为“CanvasRCA 应删除所有日志”。[论文](https://doi.org/10.1109/ISSRE66568.2025.00014)、[官方会议记录](https://issre.github.io/2025/program_research.html)

对本项目的影响：

- M/R/L/G 不必在每个 case 中具有相同诊断价值。
- 保留模态入口不等于强制每个模态占满相同份额。
- 必须拆分“选到了更好的信息”和“同样的信息表达得更好”。

### 2.2 最异常的组件可能只是受害者

已完整阅读的 FSE 2026 论文 *Rethinking the Evaluation of Microservice RCA with a Fault Propagation-Aware Benchmark* 指出，简单异常排名在部分基准上已经很强；更复杂场景的难点包括症状与根因分离、遥测中断、未监测组件和跨来源矛盾。作者同时承认调用深度等只是难度代理，不能替代真实诊断分析。[论文](https://doi.org/10.1145/3797100)、[项目](https://operationspai.github.io/revisiting-rca-evaluation/)

对本项目的影响：

- 增加“最异常组件”这类简单基线，检查复杂系统是否真正超过简单规则。
- 区分源头/受害者、node/pod/service 层次竞争与候选排名失败。
- 不把“根因实体出现过”视为“关键诊断信息已充分表达”。
- 不把 AC@5 命中直接解释成正确推理。
- AegisLab 已属于现有数据来源，不能借该论文重新包装成全新外部基准。

### 2.3 视觉的合理作用：减少关联和比较的负担

图形表示的理论价值不是创造新事实，而是让位置、分组和关系成为可直接利用的结构。信息相同，不意味着完成搜索与比较的难度相同；但这种优势取决于使用表示的系统，不能从人类图形推理直接推断 VLM 一定受益。[Larkin 与 Simon](https://onlinelibrary.wiley.com/doi/10.1111/j.1551-6708.1987.tb00863.x)

另一方面，VLM 对复杂图关系也会出错，因此“画成图”本身不是成功保证。[VGCure，ACL 2025](https://aclanthology.org/2025.acl-long.1482/)

本项目要检验的具体视觉收益是：

| 潜在收益 | RCA 中的具体作用 | 对应证据 |
|---|---|---|
| 实体绑定 | 少把一个 pod 的指标归给另一个 service | reason 中错误归属率 |
| 对比组织 | 同时比较故障源候选与受害者候选 | 排名修复、竞争候选误选率 |
| 时间对齐 | 更容易关联变化先后、持续时间和恢复 | 时间引用正确率、相关干预 |
| 层次表达 | 区分宿主故障、单 pod 故障与服务异常 | granularity 错误率 |
| 噪声控制 | 避免大量显著但重复的症状占据判断 | 加入干扰后的排名退化 |
| 输出可核验性 | 自动定位 reason 中明确引用的观测及归属 | 确定性核验的支持/矛盾/未决数量与覆盖率；不测量工程师效率 |

这些都是待验证的假设，不是预先写好的论文结论。

建议主线：

> 遥测并非越多越好，图像也并非天然更好。诊断需要保留能够区分竞争解释的证据，再用适合比较和核验的表示，将它们组织成一个有限预算内的诊断上下文。

## 4. 方法：对比式证据编译器，而非再增加一轮模型诊断

暂名：**CanvasRCA-Contrast**。名称仅表示方法方向，不作为创新性证明。

```text
完整 canonical public telemetry
        ↓
可追溯的公共统计、实体层次与调用关系
        ↓
候选间可比较的证据包
        ↓
预算约束下的对比式选择
        ↓
同事实的 Text / Compact / Screenshot / Dashboard
        ↓
冻结 Solver：一次调用
        ↓
原 top-5 JSON 与统一 scorer
```

### 4.1 从完整 public pool 开始

复用当前 V3 processed corpus，不重做 raw preparation。

新方法不能局限于旧 dashboard 已筛过的小池。核查并补足合法 public 字段的入口，包括：

- 增加、降低、停止和恢复的信号；
- service、pod、node 及公开归属关系；
- 操作级延迟、请求量、错误与日志事件；
- 非异常但具有区分作用的正常对照。

没有采集到数据不能自动解释为零；只有具有计数、采集覆盖或其他观测支持时，才能形成“请求停止”等诊断事实。不新增无诊断价值的 missing-bin 图例或说明。

### 4.2 用证据包比较候选

第一版只采用四类证据包：

| 证据包 | 解决的问题 |
|---|---|
| 本地执行与外部等待 | 延迟是组件自身执行变慢，还是等待其他组件？ |
| 宿主与同类实例对照 | 是整个 node 受影响，还是单个 pod/实例异常？ |
| 时间、流量与错误联合变化 | 请求下降、重试、错误和延迟是否形成一致的观测序列？ |
| 离散状态与跨来源矛盾 | readiness/restart、状态码、日志与 trace 是否支持不同解释？ |

每个证据包包含实际观测、可比较对象、公开关系和来源索引，而不是一句“该组件就是根因”的建议。

约束：

- 调用边不自动等同于故障传播边。
- 不用两个汇总 p95 相减，冒充逐 span 的 exclusive latency。
- 不把日志少、trace 缺失或无错误记录直接视为健康。
- 不从私有标签构造候选、关系、时间分界或选择分数。

### 4.3 第一版选择机制

不先调用 LLM 获取候选，也不利用旧轮次的错误答案建立在线候选。CPU 从完整公共证据池和真实关系生成第 4.2 节四类 `ContrastBundleV1`。普通单实体摘要仍可通过覆盖名额进入上下文，但不能冒充双侧对照。

**第一项方法强化：选择的基本单位是完整对照，不是孤立异常。** 每个对照包必须包含：

- 比较的问题类型，例如本地执行/外部等待、宿主/同类实例；类型由公开字段和关系决定，不由真实 fault type 决定。
- 比较对象及其角色；可以是两个实体，也可以是一个实体的两个可分解过程。记录真实调用、归属或同类关系的来源。
- 比较所需的两侧观测、相对时间、单位和有观测支持的参考值；缺少必要一侧时，不填零、不推断健康状态、不生成该类对照。
- 比较资格：字段语义是否一致、时间是否可对齐、计数分母是否可用。跨不同量纲只并列相关观测，不能直接相减或排序。
- 原始来源绑定与去重身份。它是一份供诊断的证据，不是“已证明谁是根因”的证书。

例如，某 caller 的整体延迟升高时，同时保留其有合法逐 span 支撑的本地耗时、下游等待及相关 callee 的观测，比只保留最慢组件的一条曲线更适合比较两个解释。这是待验证的机制假设；若 source 没有足够 span 字段，不能靠两个 p95 相减补造证据。

**第二项方法强化：预算选择奖励新的诊断比较，而不只是更大的异常幅度。**

1. 在同机制内，为包计算冻结的公共相关性 `r(b)`、匹配参照下的对比强度 `d(b)`，均归一到 `[0,1]`；名称、ID、标签和历史回答不参与。对比强度不是根因概率，也不是“差异越大越可能是故障源”。
2. 定义对照类别 `j=(比较对象、关系类型、机制类型)`。包只能覆盖来源审计确认其确实支持的类别；不会因为提到很多实体而自动覆盖所有候选对。对需要不同字段的机制分别定义资格和统计，不能用一个跨单位的最大绝对差替代。
3. 在已选集合 `S` 下，对照覆盖使用饱和累计：`F(S)=Σ_j w_j max_{b∈S} q(b,j)`；空集合的最大值为零。`q(b,j)` 是该包对类别 j 的合法公开对比强度，`w_j` 对四类机制等权、类内归一，防止 pod 数多或边多自然垄断预算。只对实际存在的关系枚举，不生成全候选的平方级笛卡尔积。
4. 四分之一的语义预算先用于机制/实体覆盖；其余按新增 `F`、公共相关性和新增覆盖的等权秩分数，扣除已登记的重复度，除以包的新增预算占用，进行确定性贪心选择。并列按冻结 hash。完整双侧对照及其必要上下文是不可拆单元，不能只保留看起来异常的一侧来省空间。
5. 预算单位是与表示无关的规范化字段/序列/关系占用：64-bin series、完整模板数值、边及其附属字段分别使用冻结权重。权重由开发集上的可呈现性检查确定，不由 RCA 标签或正式成绩确定。最终还要通过两个模型的实际 tokenizer 和画布容量检查；语义预算不是 token 数或 GPU 成本。
6. 记录每一步选择了哪个完整对照、替代了哪些候选包、耗费多少预算。渲染阶段不得再筛选。不适用对照仅离线记录，不向 Solver 增加内部检查说明。

饱和覆盖只是对现有贪心机制的可复现定义，不宣称新的最优化理论或因果识别定理；混合目标和画布约束下不直接套用经典近似保证。实现前需在正式协议中列出四类机制各自的输入字段、`r/d/q` 算法、资格检查、成本权重及并列规则。CPU 构造例必须证明：一个幅度更大但重复的异常，可以被一个具有新比较信息的合法对照替代；也必须覆盖“没有可用对照”的情况。

这些是 v1 工程假设，不宣称最优。只允许在登记的开发集进行一轮有界修订，最终评估前锁定。原来的“去掉区分度”消融具体化为关闭 `q/F` 的对比收益，其他覆盖、包闭包、预算与表示不变；不能顺带移除正常对照或换一套 renderer。

### 4.4 视觉如何承载这些证据

提供两种固定画法，不继续无限搜索 dashboard：

- **Standard**：按 M/R/L/G 分区，沿用既有可读图表风格。
- **Contrast**：将可比较的实体、同类实例和关联时间片段放在相邻位置，保持身份标注、时间轴及单位一致。

Contrast 不把“系统判定谁更可能是根因”画成红色重点，也不展示选择器评分。图中仍是观测及其关系。

主视觉条件为全部证据进入一张图；受限混合条件为 **M 文本＋R/L/G 图像**。它来自已有实验线索，但仍需新的同内容检验。TPV 保留为强对照；其三个文本模态不意味着部署路线放宽为任意混合。

### 4.5 最小接口

只新增必要契约：

- `ContrastEvidencePoolV1`：公共事实及来源索引。
- `ContrastBundleV1`：比较对象、事实集合与公开关系。
- `ContrastSelectionV1`：选择顺序、预算和选择理由。
- `RepresentationTwinV1`：同一事实集合的文本、截图和图表映射。
- `DiagnosisAuditV1`：排名、引用、错误归属和成本。

复用统一 client、scorer、writer 与本地模型配置。候选仍在文本中；service/node/pod 保持 case-local 数字匿名化。

### 4.6 强文本对照：相同事实，也给予相同的比较机会

仅有 fact inventory 一致，还不足以说明收益来自视觉。若图像把竞争候选并排、对齐时间，而文本把相关字段分散在不同模态段落，比较同时改变了载体和组织方式。

**现有实现与待实施补强分开。** `X_C` 的代码在 `RQs/RQ3_1/src/renderer/contrast.py::project_compact_comparative_text`：先给比较组及观测引用，再按区域/字段排列统一观测目录。`main.py::_parts_from_twin` 确实将此文本送入 Solver。它已提供 contrast 语义，但具体值仍可能需要跨段查找。本次不宣称它已经是候选数值直接并排的文本，也不覆盖其旧输入。

新增 **`X_C_TABLE`：直接并列观测的强文本 contrast**，作为视觉主张的必需比较对象，而非看到旧文本成绩低才决定是否运行的可选基线。

1. 共用 X 的同一 selected facts、完整 bundles、候选集、比较对象、关系和时间；不重新筛选、不重新摘要。比较组及组内实体顺序使用与视觉相同的公开规则。
2. 在可比语义/单位下，把双方观测直接放进同一紧凑表格；例如行是相对 bin，列是两个实体的同类序列。计数、baseline/current、状态和单位在对应行就能查到，不要求为完成主要比较去另一目录找实际值。
3. 跨量纲观测使用有明确字段/单位的相邻表格或独立列；不强行把不同单位放到同一数值尺度。日志保留消息、数字与事件数，拓扑保留方向和部署关系，未成对的已选事实放公共上下文表，不删掉它们。
4. 共享观测优先通过多列共用表呈现，避免不必要的长序列重复。确需重复一份观测时，事件数不增加，记录唯一事实与实际呈现次数。语义同事实与显示次数相同是不同检查；不能以人为冗长的表格制造视觉 token 优势。
5. 使用简洁、可读的字段和共同时间标识，避免长边框、巨大空格填充和无意义 ID。采用一个固定的确定性格式；只能在 eval 上检查可读性/容量，不依据 test 成绩选择 Markdown/CSV/其他格式。
6. 共同 RCA 方法、候选顺序、输出、scorer 和 sampling 不变。文本只获得字段/表格说明，图像只增加必要视觉语法；任一说明不得额外给出根因推理提示或 case-specific 结论。
7. 用实际 tokenizer 检查完整请求，保留完整字段、bins 和精度。溢出记容量问题，不截断或移走难 case；分析分别报告可执行率、端到端效用与预定配对可执行子集，不能把文本放不下单独解释为图形推理更好。

同一份内部比较结构分别投影为表格和图元，审核来源绑定。表示效应指这些具体可部署实现间的效果，不称为与布局、重复度和读法完全无关的“纯视觉”抽象效应。

再增加 **`X_C_TABLE_S`**：把完整 `X_C_TABLE` incident fragment 按原顺序逐字渲染为一张可读截图，只有换行/必要页面排布，不加图表、摘要或新观测。候选和共同指令仍是文本。它只在预定 100-case eval 子集运行，不是另一种部署候选；任何容量失败都保留，不以删除行或缩到不可读解决。

| 同一子集上的比较 | 可回答的问题 |
|---|---|
| `X_V_CONTRAST − X_C_TABLE` | 对比信息已直接供文本使用时，真实 dashboard 是否仍有价值？ |
| `X_C_TABLE_S − X_C_TABLE` | 同一并列表格仅更换为像素载体，表现/成本如何变化？ |
| `X_V_CONTRAST − X_C_TABLE_S` | 相同事实都经图像通道输入时，图表编码与空间组织相对文字表格的作用是什么？ |
| `X_C_TABLE − X_C` | 消除文本引用跳转、改变文本组织后，结果是否改变？该项为探索性解释，不是纯载体比较。 |

后两类图像的像素布局、processor geometry、呈现次数和图像 tokens 不保证相同，逐项记录。上述三角对照收窄替代解释，但不能把三个均值相减解释为唯一的认知机制分解。

`X_T`、`X_C`、`X_S` 均保留原定义；`X_S` 仍截图 `X_T`，不偷偷替换为表格截图。`X_C_TABLE` 及其 screenshot 使用新 arm/call key，待实现、追加注册和资格检查后运行。两个文本 contrast 都完整报告，不挑 test 上较弱的一个做正文对照。

## 5. 三个新 RQ 与实验

### RQ3.1-A：新方法能否达到强基线水平，并带来准确率或成本改善？

注册 `exp_contrastive_rca_effectiveness`。

当前可执行主实验包含 14 个逻辑条件；修订 8 追加实现后为 15 个：

| 条件组 | Arms | 用途 |
|---|---|---|
| 既有强基线 | 原 T、原 V、原 TPV、T 的无损 compact text | 比较完整方法是否值得采用 |
| P0 校准 | `P0_T_CAL`、`P0_V_STANDARD`、`P0_V_CONTRAST` | 分离公共描述层及新绘图接口的影响 |
| 新选择器 X | `X_T`、`X_C`、`X_S`、`X_V_STANDARD`、`X_V_CONTRAST`、`X_MTEXT` | 同事实比较自然语言、紧凑文本、截图及真实视觉 |
| 既有方法对照 | `SIRCL_TEXT` | 与原生工具和 SIRCL-style 文本方案比较 |
| 待实施强文本补充 | `X_C_TABLE` | 同一选中事实与比较对象直接并列，检验视觉是否超过合理组织的文本 contrast |

其中：

- Compact 不靠额外摘要制造节省；`X_C` 是引用＋目录，新增 `X_C_TABLE` 是第 4.6 节的直接并列版本，两者身份分别保留。
- Screenshot 严格来自对应 `X_T` 的文本。
- 原基线不因新方法出现而被重新生成或覆盖。
- 校准条件与原桥梁的变化单独报告。
- 历史结果仅在请求、模型和评分契约兼容时复用；否则登记新调用，不修改旧记录。
- `SIRCL_TEXT` 使用原工具的最小适配，公开时间与评分差异；不直接拿论文 MRR 当配对结果。
- EvoRCA 对照需与其作者确认可公开的版本，作为条件式额外 arm，不由我们擅自定义其“官方方法”。

额外运行零 LLM 调用的简单排名基线：异常计数/幅度、原生 BARO 组件排名及 X 的内部排序。检查 Solver 是否真的比 CPU 候选排序更好。

所有 RQ480 cases 都纳入，不按成功或失败选择运行对象。该批次现在是方法开发／选择 eval，不是独立 test；旧结果及新比较可用于分析和选择方法，泛化结论由第 5 节 C 的封存 test 检验。

**主要分析：**

- MRR、AC@1/3/5、AVG@3/5。
- baseline 前五内但非第一的案例，被新方法提升至第一的比例。
- baseline 前五外的新增提名与此前正确案例的破坏。
- 输入、图像、输出 tokens 分开。
- 所有五个数据集分别、五数据集等权 macro、480-case pooled，以及两 AIOPS 分开与合并报告。

**提前固定比较的解释，不看结果后改变故事：**

| 比较 | 回答什么 | 不能混算的因素 |
|---|---|---|
| 完整 X 方法 vs 原 T、TPV、SIRCL_TEXT、CPU 简单排名 | 新系统是否值得采用，Solver 是否超过简单规则 | 总收益不能全部记给视觉 |
| `X_T−P0_T_CAL` | 更换完整证据处理策略后的文本诊断效果 | 共同 task/候选/scorer；P0/X 各自提取、分界与统计，不能称纯排序或视觉效应 |
| `X_V_CONTRAST−X_C_TABLE`，同时报告对 `X_C` | 同事实、文本直接可比较时，视觉是否仍有增量价值 | `X_C_TABLE` 尚待实现；原引用式文本不能独自排除文本查找负担这一解释 |
| `X_V_CONTRAST−X_V_STANDARD` | 同内容下，视觉对比组织的作用 | 不允许同时换选择器或事实集合 |
| `X_S−X_T` | 同一文本改为像素传输的作用 | 不等于真实图表的增量作用 |
| `X_MTEXT−X_V_CONTRAST` | 同组事实中，Metrics 保留为文本的取舍 | 使用共同对比结构，仅改变 M 的载体 |

所有主条件都报告。最终推荐纯视觉还是受限混合，根据 RQ480 eval 上预先定义的规则选择，并在打开 test 结果前锁定。每个方法版本的输入规则和协议先登记再运行；允许在 eval 上开发、按预算作一次有界修订，但不得修改已完成版本的记录。不能对每个 test case 挑较高分条件，也不能把 eval 上挑出的最佳分数当作独立泛化证明。具体 Holm families、推荐规则和统计主次在实现前写入正式协议，此处不把未来需要登记的内容称为已完成注册。

**补充零调用的诊断竞争指标。** 除总体排名外，在每个 case 上用同一公开异常排序与真实关系建立竞争者候选目录；evaluator 再区分根因与非根因，不使用被比较模型的错误答案来挑竞争者。分别报告根因对高异常非根因、上/下游相邻非根因以及层级相关非根因的排名胜率，先在 case 内聚合再统计。根因未提名但竞争者已提名算负，二者均未提名单列为未区分，不算成功。只有来源确实证明传播关系时才称“受害者”，普通调用邻居不自动获得这个标签。该分析复用全部主输出，用于回答收益是否真的集中在候选竞争，而非用新的分数取代 MRR。

### RQ3.1-B：收益来自证据选择，还是视觉组织？输出是否有可核验的观测支持？

注册 `exp_visual_diagnostic_mechanisms`。

首先利用主实验补齐的四个条件：

|  | Standard | Contrast |
|---|---|---|
| P0 | P0＋Standard | P0＋Contrast |
| X | X＋Standard | X＋Contrast |

计算选择效应、视觉组织效应及二者交互。它们是这四个条件中的效应，不称为所有 RCA 设计的普适贡献。

再按冻结 hash，从五个数据集各选 20 个 cases，共 100 个，增加八个机制条件：

1. 去掉区分度优先，仅按相关性选择：Text、Vision 各一。
2. 相同 X 事实取消候选对比分组：一个 Vision 条件。
3. 相同 X 事实取消跨卡片的共同时间对齐，但保留正确时间标注：一个 Vision 条件。
4. 移除一个预先审核的根因关联证据包：Text、Vision 各一。
5. 移除数量、模态和显示规模匹配的非目标证据包：Text、Vision 各一。

后两项是 evaluator-private 构造的机制干预，不是部署选择器。没有合格目标/对照时记不适用，不编造证据，也不将缺少事实后的输入称为等信息。

**自动核验只检查明确、可绑定的观测断言。** 冻结的 matcher 提取实体＋字段/关系＋值/时间，使用实际 model-visible facts 及允许的显示精度核验，不把“reason 中出现正确数字”当成绑定正确。调用方向与宿主关系区分类型；缺少端点、单位、字段或指代不唯一时记未决。

- 输出分为：有可见证据支持、与明确可见证据矛盾、可解析但可见上下文没有依据、无法判定。无依据不等于事实必定为假，未决不归为模型错误；完整 public pool 中存在但未展示的观测另列，不能反过来替模型补证。
- 以 case 聚合，报告已解析且可判定断言中的支持比例，以及矛盾/无可见依据的数量。同步报告每输出的可判定断言数、至少一项可核验断言的输出覆盖率、未决数、空 reason 与无可判定断言数；分母为零记 N/A，不记满分。不能声称覆盖率是对所有自然语言断言的抽取召回率。
- 在不调用模型的正/负控制上验证 matcher：正确引用、交换实体、反转边、换单位、合法舍入、含糊指代等。它验证核验规则的能力范围，不替代对自然语言解释的人工语义评估。
- 不把这些结果统称为完整 reason correctness、依据充分性或隐藏推理忠实。若需声称因果诊断理由充分，必须另有相应验证，当前不纳入主贡献。

证据移除实验优先看行为：令 `drop_target = RR_clean − RR_target_removed`、`drop_control = RR_clean − RR_control_removed`，在有合法匹配的同一 case 上比较 `drop_target − drop_control`。并报告 repair/break、适用率及选择偏差，所有方向均保留。根因实体关联包可能只是症状包，因此称为“对根因关联观测的选择性依赖”，不直接称真实因果证据或正确内部推理。文本与图像都可能通过这项检查；它不能独自证明视觉更好。

另为三个关键条件开展同输入重复调用，保持现有采样配方，使用独立 replicate 身份防止缓存复用。估计观察到的输出波动，不把重复成功或历史 oracle 当作新方法的单次能力。

机制移除条件的 Text 端沿用 `X_C` 的对比式紧凑格式，Vision 端沿用 Contrast；同一对条件移除同一证据包。无区分度选择条件也维持对应格式，只改选择规则。若“取消对比分组”与 `X_V_STANDARD` 的完整请求实际相同，复用记录并登记逻辑映射，不能把相同输入当成两项独立机制证据；不通过额外改动制造差异。三个重复条件的身份也需在正式推理前登记，不能事后挑波动最小或收益最大的条件。

**预算曲线：视觉是在高 MRR 下更省，还是只在一个预算点碰巧更好？**

在同一预先 hash 抽定的 100 cases 上，为 `X_C` 和 `X_V_CONTRAST` 增加两档语义预算：标准预算的 `0.50`、`0.75`；`1.00` 复用主实验。采用同一冻结贪心规则按各预算独立选择完整包，不承诺三个集合必然嵌套。每一档的文本/图像共享完全相同的选择，不改变 precision、bins、候选或公共统计。既不能截断半张卡片，也不能让画布不够时偷偷减信息。

这四个条件共最多 `100×2预算×2表示×2模型=800` 次新增调用，归入现有机制实验，不增加独立 smoke。报告 MRR/AC@1、实际输入/输出成本、事实及对照覆盖率的离散曲线；绘制逐模型的准确率—成本 Pareto 点，不凭三个预算点声称任意预算下的最优。它检验有限上下文中的表示取舍，不把语义预算相同写成 token 成本相同。

**修订 8 的补充与节制。** 在同一 100-case 子集增加 `X_C_TABLE_S` 的 200 次调用；给 `X_C_TABLE` 补 0.50/0.75 两档预算共 400 次，1.00 复用其主实验输出。与现有 Contrast 使用完全相同的事实选择，不能为文本换一套 selector。取消先前双人审核 600 份 reason 的必需任务；自动核验和上述干预复用输出，不增加 LLM judge、QA 或 attention。可由作者解释少量示例，但只作示例，不能伪装成独立标注实验。

**自然竞争事件对（零额外模型调用，条件式分析）。** 方法锁定后，由 evaluator 在封存事件中，按预先定义的应用、拓扑、负载档和采集覆盖匹配不同根因的真实事件；不按模型成绩挑对。优先查找类似症状下分别由 caller/callee 或 node/pod 引起的事件。每个事件最多入一对，按确定性匹配和 hash 处理并列。复用最终注册方法的原始输出，报告两事件均诊断正确的比例、逐事件排名及竞争者误选。没有合格事件对则报告不适用，不拼接遥测、不修改 gold。两事件不是严格反事实，因此只作为“相似症状、不同根因仍能区分”的外部证据，不能据此断言物理因果识别；这是成对事件分析，不混入以 case 为单位的主检验。

**二、非语义稳健性。**

在上述 100-case 机制子集，分别测试：

- 完整一致的 ID 重匿名化。
- 候选列表顺序重排。

对 X_C 和冻结的视觉部署条件各运行两项。所有关系及 gold 映射同步变换，不改变诊断事实。报告 AC/MRR 变化、排名翻转和错误归属，不只报告输出文本是否一致。

**三、重复证据负载：是否会把重复出现的症状当成更多支持？**

修订 2 只有重匿名化和候选重排，不能支撑“抗遥测噪声”的广泛说法。本版增加一个范围明确、gold 不变的压力测试：在上述 100-case 子集，保持 X 已选的全部事实和比较关系，重复显示部分已有完整证据包，增加标准证据占用的约 `25%`、`50%`。待重复包按冻结公共相关性排序并用 hash 并列，不按根因或模型输出选择；两档采用同一重复顺序的前缀。

- 每份重复的实体、数值、模板、计数、时间和来源完全相同，不伪造新采样、增加日志 multiplicity 或声称发生了额外事件。唯一事实集合不变，显示次数有意改变。
- `X_C` 和 `X_V_CONTRAST` 重复同一批包、相同次数，并保持对应比较结构。标记来源供离线审计，但不给某个 arm 额外的“忽略干扰”提示。
- 原有事实不被挤出；保持画布总尺寸和正常版的字体可读性下限。若确实无法合法放入，记录该档容量失败与实际可执行覆盖，不通过缩字至不可读、删除内容或额外图片“通过”测试。
- 登记实际重复比例、可见次数与像素/文本占用；小 case 的两档若得到相同输入，复用并报告退化，不能多算一次独立测试。

两档×两表示×两模型×100 cases，最多新增 800 calls，归入现有稳健性实验。比较相对干净输入的 MRR、错误竞争者上升和归属错误变化，并计算两表示的配对退化差。容量失败单列并报告端到端效用，不能仅留下能放入的 cases 宣称鲁棒。该实验测量**对冗余呈现及其密度负担的敏感性**，不宣称覆盖错误遥测、随机噪声或真实事故中的所有干扰；新的不同数值症状不在本版添加。

**修订 8 的强文本压力对照。** 同一批 100 cases、同一重复包/次数再生成 `X_C_TABLE` 的两档负载，共 400 次调用。与其干净表格基线配对，再和视觉的配对变化比较。控制独特事实、重复包身份及次数，不强行等化 token 数；记录实际长度和容量。新增表格未完成前，既有 X_C 的鲁棒性结果只适用于引用式文本，不能声称已超过直接文本 contrast。

**人工研究退出本篇执行范围。** 原招募工程师、12 人/24 cases 的用户研究改为未来工作，不占资源、不作为完成门槛，不用模拟工程师或 LLM judge 代替。机器诊断结果与公开输出自动核验不能推出人工核验时间、错误建议接受率、MTTR 或工程师工作负担改善。

### 统计

- 统计单位为 case，不把不同 arm、重复调用或两个模型当作独立病例。
- 使用配对 Pratt-Wilcoxon、Cohen’s dz 和预注册 Holm families；沿用不报告 CI 的项目规则。
- 存在重叠事件组时补充 group-level 敏感性分析。
- 主模型和跨模型结果分开；五数据集均报告，不以 RE2 拉高总体后掩盖 AIOPS 退化。
- 标签只用于评分和离线分层，不进入选择器或模型输入。

“实质性准确率提升”沿用 ΔMRR≥0.05 且 adjusted p<0.05。低于该幅度仍报告实际结果，但不扩大称为大幅提升。

高 MRR 必须同时看绝对值和强基线；通过统计门槛不自动意味着达到 SOTA，也不意味着生产可用。

独立性审计包括人工探索和历次方法选择，不仅查 optimizer 是否见过数据。重新分割已暴露的 480 cases 不会恢复独立性。若未暴露事件不足，不删掉已有对比结果，但缩小泛化结论；五数据集均值、各数据集结果、模型差异和不确定结果同时呈现。不显著不等于等价，`ΔMRR>−0.05` 的点估计也不等于已证明统计非劣。

新增预算和重复负载比较分别构成 secondary family，采用 case 内配对差；不能把三个预算点或三个负载点视为三倍样本。机制假设预先落为可否证预期：关闭对比收益应主要损伤有合法候选对照的情境；取消分组/共同时间对齐应影响需要对应比较的情境；重复负载用于测试退化差，允许视觉反而更差。样本不足时保持描述性，不在结果出来后重定义“适合视觉”的 subgroup。新事件主检验与已暴露 480-case 分析分开，不用后者的显著性替代前者。

**修订 8 的预定统计补充（待写入 successor 注册）。** test 的两个固定视觉条件分别对 T/T_COMPACT/TPV/SIRCL_TEXT/X_C/X_C_TABLE，跨两个模型一起构成 **24 项主比较**的 Holm family；不能把新增强文本单独拆成宽松 family。eval 使用同一比较清单，但标明开发结果。核心视觉结论必须面对 `X_C_TABLE`；不能 test 后挑较弱文本、换推荐模型或只报告有利数据集。

表格截图子集比较 `X_V_CONTRAST−X_C_TABLE_S` 与 `X_C_TABLE_S−X_C_TABLE`，两模型共四项组成独立 secondary family。预算和重复负载各自形成一个 family：三个表示（X_C/X_C_TABLE/Contrast）的两个干预水平相对自身标准条件，两模型共 12 项；另加 Contrast 与 X_C_TABLE 在两水平的配对变化差，两模型共四项，每个 family 合计 16 项。以 case 为单位构造差值后检验，不用“一个显著、另一个不显著”代替差异之差。原模型内点估计、每数据集方向和失败分母全部报告；没有新结果时不预先宣称任何方向。

6. 完成直接表格强对照的追加注册、实现与资格检查，在 eval 完成该对照；按既定规则锁定部署方法、文本格式、prompt、自动核验规则、负载/预算测试及扩展 test 统计 family。
7. 完成 RQ480 内的机制／压力测试，诚实标为已曝光开发材料；若因此修改部署方法，必须在开启 test 前重新锁定版本并核对预算。
8. 在登记的 360 个 test cases 上一次性评估，另列旧 validation 140／补入 220 的分层；按已定规则做自然事件对分析，不根据 test 分数回头选择或修改同一版本。
9. 完成自动核验、受控干预与成本/稳健性分析，明确规则覆盖和未决部分；没有受试者或独立标注者任务。
10. 最后决定是否值得开展 Composer 学习。

此前阶段的执行授权不等于本次新增条件已经实现。当前用户要求本轮更新计划后停止，不启动实现、测试或追加调用。后续实施时仍需单 Agent 科学审查、相应资格和完整 test 注册，不能仅凭本文更新启动新路径。已有后台工作不由此文档改动停止或改变。

## 8. 必须通过的检查

实现前将以下检查注册为验收条件：

- 完整 public pool 没有被旧面板 top-k 提前截断。
- 不输入根因、注入时间、dataset 名或可识别案例路径。
- 数字 ID 一对一，node/pod/service 关系来源明确。
- 选择动作真实改变事实集合，表示动作不暗中重新筛选。
- Text/Compact/Screenshot/Canvas 的对应事实、单位和时间一致。
- 原 `X_C` 与 `X_V_CONTRAST` 的比较语义一致；新增 `X_C_TABLE` 在主要比较位置直接提供完整双方数值，实际输入人工工程检查不得只看 manifest。关系事实不由图像独占；原 X_S 来源于 X_T，新 X_C_TABLE_S 只来源于 X_C_TABLE。
- 审核字段/关系/时间/单位及事实可见性，分别计数唯一事实和重复呈现；避免故意拉长文本、将文本截断、只给视觉更强 RCA 提示。文本和图像的实际容量与成本都报告。
- 自动核验通过已知真假及模糊引用控制；空理由/未解析断言不记完美支持率，不以匹配结果替代因果推理或工程师效率证据。
- 所有关键事实真正进入可读文本或可见图元，不只存在于 manifest。
- 两模型同 case、同 arm 的公开输入一致，模型模板差异单独记录。
- 无源数据支撑的关系、正常状态和“信号消失”不得生成。
- 原基线与新校准层之间的差异可追踪，不静默更新桥梁。
- 格式失败、少于五个候选、未知 ID 和基础设施失败分别处理。
- 断点续跑、完整请求去重、partial output 与 writer drain 正确。
- 独立评估不接触开发过程，人工难例分析不反向改变已锁定方法。
- 选择分数、覆盖名额、去冗余、并列规则和超预算行为在推理前有可执行定义；不以“更有区分力”等抽象措辞代替算法。
- 相关性-only 消融保留其他选择和表示设置，确实只移除被检验的区分度机制；CPU 案例核查可见动作与来源绑定，不替代真实 RCA 效果评估。
- 同一请求的重复结果与去重复用身份分明；科学统计不将复用记录或重复调用视为新独立 case。
- 对照包两侧观测与必要关系闭合，语义预算不依赖表示或标签；减预算不留下无参照的半包。
- 负载测试只重复已有观测的呈现，不伪造事件次数；干净事实保留，重复比例、容量失败与输入去重可追踪。
- 自然事件对只在方法锁定后由 evaluator 形成，不能按模型成绩配对或将两事件包装成严格反事实。
- 新事件来源审计包括全部旧 train/validation/探索使用；匿名化不能被当作独立性证明。

## 9. 预期论文贡献及与邻近项目的边界

建议争取形成三项扎实贡献：

1. **问题发现：** 量化当前模型在竞争候选、实体绑定与排名上的具体失败模式，定位选择与承载的不同瓶颈。“最异常不一定是根因”是已有知识，不作为本项目首创新发现。
2. **方法贡献：** 以完整诊断对照为选择单元、以比较覆盖约束有限上下文的可追溯证据编译器，服务于冻结 one-shot Solver。贪心、覆盖或绘图库本身不是创新性声明。
3. **实证贡献：** 用强文本/TPV 对照、选择×组织交互、证据干预、预算/冗余负载曲线及独立事件，给出可否证的效果与适用边界。释放可复用的匿名输入、来源绑定和测试协议，让别人能检查方法为何成功或失败。

与 SIRCL 的区别不能只写“它用文本、我们用图像”；需要证明视觉组织在同内容下的增量作用。与 EvoRCA 的区别不能只写“我们不训练”：其部分路线同样通过诊断检查和上下文组织改善固定模型。本项目不以演化诊断检查或学习候选评分规则作为核心，而以**可核验的视觉证据组织及其诊断效果**作为独立研究对象。

第一篇优先形成强方法及完整证据链，按 ASE/FSE/ICSE 方法论文的评审问题组织正文，并为 TSE/TOSEM 等软件工程期刊保留更完整的分析材料。具体投稿场所尚未选择；是否达到要求取决于实际效果、独立验证和方法贡献，不能靠实验数量或漂亮图表保证。

只有在固定方法已经证明有效，且不同案例确实需要不同、可预测的证据/表示决策时，才恢复 Composer 学习路线：格式 SFT 教合法调用，后续效用学习优化已经验证的动作空间。不会因为固定方法 MRR 不理想，就直接把剩余问题交给 RL。

**最终希望讲清楚的故事是：CanvasRCA 不是用图像替代文字，而是用可核验的视觉比较，把“多个组件都异常”转化成更容易区分、排序和检查的诊断证据；这种变化必须在高质量 RCA 结果上得到验证。**

## 10. 论文题目、主线与详细大纲

### 10.1 建议题目

> **CanvasRCA: Contrastive Evidence Selection and Visual Organization for Microservice Root Cause Analysis**

中文：**CanvasRCA：面向微服务根因分析的对比式证据选择与视觉组织**。

Contrastive 指竞争候选间的证据比较，不是 contrastive learning，不意味着需要训练。若故障源/受害者辨别的最终结果特别扎实，可考虑备选标题 *Beyond Anomaly Rankings: Contrastive Visual Evidence for Microservice Root Cause Analysis*。当前不在标题中预先承诺 Causal、Trustworthy 或 Faithful Reasoning。

论文主线是：**发现可定位的诊断瓶颈 → 提出针对性方法 → 证明准确率与视觉增量价值 → 检验独立事件和适用边界**。不是按开发日志罗列 RQ1.1、RQ2.1 和全部淘汰赛轮次，也不是把一组方法的联合覆盖包装成一次诊断的性能。

### 10.2 正文章节

**1. Introduction**

- 用一个来自真实记录、可以追溯的实例解释多个组件同时异常时的候选竞争；不编造成功案例。
- 说明增加数据、直接画图和更换异常分数各自为什么不足；区分既有知识与本项目新增发现。
- 概括固定单次调用方法与三项贡献：具体瓶颈的实证、对比式视觉证据方法、受控效果与机制验证。
- 摘要和引言中的效果数字只在实验结束后填写，同时说明数据集、比较对象及绝对/相对变化。

**2. Background and Motivating Study**

- 定义 service/pod/node、调用与部署关系、MRR/AC@K 及一张图的输入边界。
- 从既有分析提炼三个现象：表示存在取舍；根因实体有遥测仍可能诊断失败；不同方法互补却不能直接部署 oracle。
- 区分未选到相关证据、没有正确绑定/比较、正确候选排名靠后，不能仅凭 AC@5 判断推理原因。
- 正文保留支撑设计的关键统计和代表案例；完整旧 arms、轮次及负面结果移入附录或 artifact，不删除历史证据。

**3. CanvasRCA Approach**

- 按公共输入、证据包、预算选择、表示投影、一次 Solver 调用和来源审核的顺序写。
- 给一张架构图、一个贯穿案例和一段可复现伪代码，定义区分度、单位/时间可比性、去冗余与预算规则。
- 交代四分之一覆盖预算和等权分数是工程假设，说明设计依据；不能声称是理论最优，也不为投稿自动新增搜索。
- 说明无适用证据、关系未知或预算不足时的行为，以及选择和渲染的计算复杂度。

**4. Evaluation Design**

- 将完整方法比较和同内容机制比较分开，明确强文本、TPV、SIRCL 和 CPU 排名基线的职责。
- 说明 RQ480 方法开发／选择 eval、360 个 test 内旧 validation 140 的历史用途及补入 220 的边界；不把开发集最好分数当泛化成绩，也不将整个 test 称完全未见。
- 写清统一模型/候选/评分契约、模型失败与基础设施失败、每项指标分母、配对检验和多重比较。
- 交代自动断言核验的规则、正负控制、适用范围及未决/空理由分母，不把规则匹配包装成对完整推理的人工评估。

**5. Results**

论文可重新使用 RQ1–RQ3 的阅读编号，但不改仓库历史目录或实验身份：

| 论文编号 | 仓库计划对应 | 主要回答 | 必须展示的材料 |
|---|---|---|---|
| RQ1：诊断效果与成本 | RQ3.1-A | 完整方法是否超过强基线，成本取舍如何？ | 分数据集 MRR/AC@1/3/5、repair/break、输入/输出成本与 Pareto 图 |
| RQ2：作用机制与输出依据 | RQ3.1-B，复用 A 的主条件 | 选择、组织及交互如何影响结果，公开断言是否有观测支持？ | 2×2 效应、直接表格文本/截图对照、目标/对照移除、可判定实体/关系断言及覆盖率 |
| RQ3：泛化与稳健性 | RQ3.1-C | 新事件、重匿名化、候选重排和重复负载后是否保持收益？ | 锁定 test 成绩、逐模型/数据集变化、排名稳定性与压力下配对退化 |

每个小节采用“问题 → 比较 → 结果 → 解释 → 适用范围”。不把论文 RQ2 的组合效应写成所有设计空间中的固有贡献。正确与错误案例均展示；代表案例的筛选方式公开，不能用成功截图代替全量统计。

**6. Discussion**

- 解释视觉在哪些实体绑定、时间对齐和候选比较上有效，以及在哪些精细数值或高密度条件下不如文本。
- 分别讨论证据干预后的排名变化、诊断改善和可核验断言，明确它们不是隐藏推理忠实性的同义词。
- 给出有限且可操作的设计建议；只有验证了固定方法和动作效用之后，才讨论未来 Composer 学习。
- 不将 RL、双 Agent 或交互式 dashboard 加入本篇必须完成的方法链。

**7. Threats to Validity**

- 讨论历史探索暴露、事件重叠、注入故障与真实事故、共享应用、候选全集与根因粒度。
- 讨论两个模型的代表性、源数据采集范围、自动核验的解析边界与有限样本的统计功效。
- 不把公开 reason 当成隐藏思维链，不把未显著差异称为相同，不把来源相关性称为传播因果性。
- 本篇没有人工实验，贡献限定为机器诊断，不报告降低人工 MTTR 或提升工程师效率。

**8. Related Work and Conclusion**

- 按异常/因果/传播型 RCA、LLM 上下文工程、视觉表示、证据核验四类组织。
- 说明与 SIRCL/EvoRCA 的实际算法和评估差别，忠实区分组件适配与完整系统复现。
- 总结最终证据支持的发现，包括限制；不按“必须证明图像必要”的预设目标挑结果。

### 10.3 正文图表优先级

优先保留：①真实候选竞争的动机案例；②架构与证据来源图；③强基线逐数据集 MRR；④准确率—输入/输出成本图；⑤选择×组织效应与配对 repair/break；⑥证据审核及独立事件结果。不是固定版面数量，信息拥挤时拆图，完整大表放附录。

## 11. Reviewer 视角的证据要求与投稿判断

### 11.1 每一项主张必须对应一个检验

| 拟支持的主张 | 必需证据 | 不足以替代的材料 |
|---|---|---|
| 完整方法具有高质量 RCA 性能 | 同任务/粒度的强基线，绝对 MRR、AC@1/5、逐数据集与独立事件结果 | 仅胜过弱全视觉基线或历史联合覆盖 |
| 对比式选择有作用 | 公共区分度的操作定义、相关性-only 对照、选中集合与竞争模式分析 | 工具名称不同、主观“更有区分力”描述 |
| 视觉有独立增量价值 | `X_V_CONTRAST` 对 `X_C_TABLE`，同时报告原 `X_C`；结合同表格截图及 Standard/Contrast 比较 | 只胜过需要跨段查值的文本，或只有视觉内部消融 |
| 公开断言有更好的观测支持 | 可绑定实体/数值/关系的规则核验，支持/矛盾/无依据/未决与输出覆盖率 | AC@5、attention、少量漂亮解释或把未解析句子都算正确 |
| 方法能泛化 | 不用于任何开发决策的事件，按来源和重叠组隔离，冻结后一次评估 | 将已暴露案例重新命名为 heldout |
| 系统更省 | 输入/图像/输出 tokens 分开，加上选择、渲染及已有推理耗时 | 仅输入下降便声称输出、延迟或能耗同比下降 |

### 11.2 必须在实现前收敛的评审风险

1. **算法贡献含糊。** 将证据包和选择公式写到可复现程度；明确哪些来自原工具，哪些是本项目新增规则。不能将已有“异常不等于根因”常识包装为发现，也不要求每个组件都原创才算有贡献。
2. **视觉与组织混淆。** 第 4.6 节是本次主要补强。不能让文本失去图中可用的实体比较和时间对应，也不能假定紧凑文本一定更便宜。
3. **开发暴露。** 独立事件数量先审计再承诺；不足时缩小外推范围，不再挖掘同一测试集并称之为验证。
4. **有效性与可解释性混淆。** 去掉证据影响排名并不证明所有理由都忠实；事实正确但判断错误、排名正确但解释错误都要保留。
5. **预算和适用范围不透明。** 一次调用限制是研究边界，不是所有竞争系统都必须服从的定义。对不同调用/训练预算的方法标明条件，不把组件基线包装成完整 SOTA。

修订 8 为上述核心混淆规划增加 2,680 次调用，其余分析优先复用已登记输出。所有新增条件须先进入版本化执行注册并计入 40,000；本次只更新文档，不能用旧授权或文档完成状态冒充新增路径资格。

### 11.3 怎样判断论文是否值得投稿

若最终同时得到强基线上的实际诊断收益、强同内容文本对照下的视觉价值，以及可信的新事件验证，就具备支持方法论文接收的核心理由。这里是投稿准备标准，不是对真实 reviewer 决定或接收概率的承诺。

不要求每个模型/数据集都第一、解决全部故障、证明普适贡献或完成 RL/用户研究；结论必须限定到有证据支持的范围。相反，仅仅增加实验数量、提升 oracle coverage 或展示热点图，不足以弥补核心混淆。

若新选择策略有效但视觉对强文本没有明确优势，如实收敛为证据选择贡献，保留视觉的负面或条件性结果；若图像只在精度保持时节约成本，也只能按该实际结果组织论文。不能为维持标题和预先设定的故事事后换统计口径、挑模型或删除退化案例。

### 11.4 从“可接收”走向更强贡献：实施优先级与论证结构

“Strong”不是把 Weak Accept 改写成 Strong Accept，也不是再加一轮 RL。最有价值的升级按优先级如下：

| 优先级 | 要增加的实质 | 为什么能改变论文的说服力 | 完成依据 |
|---|---|---|---|
| 必需 | 新事件先封存，强基线统一任务/候选/粒度，独立验证不反哺调参 | 排除反复探索同一批题目和弱比较对象这两项关键替代解释 | 来源使用审计、锁定时间、八方法 test 规划及实际完整结果 |
| 必需 | 完整诊断对照与公共比较覆盖的可执行定义 | 回答“方法到底新在哪里”，而不只展示一个打分公式 | 代码/伪代码、原工具差异表、关闭对比收益的结果 |
| 必需 | 强文本直接提供对应观测，先保证绝对 MRR 和 AC@1/5 | 区分选择收益、文本查找负担和视觉组织效应 | X_C_TABLE/表格截图/Contrast；原 X_C 与强基线仍完整报告 |
| 高价值 | 预算/重复负载曲线、竞争者错误和自动可核验断言 | 解释何种诊断比较及何种负担下有效 | 同 case 配对变化差、规则覆盖和零调用联合分析 |
| 条件式 | 自然竞争事件对 | 检查类似症状下不同根因是否仍能区分 | 按预定规则得到的合格真实事件对；没有就报告不适用 |

正文聚焦三个互相衔接的答案：**确实诊断得更好 → 收益可定位到对照证据和视觉组织 → 换事件/增加负担后仍有哪些收益与失效边界。** 每个正向例子配一个有代表性的破坏或无效例子，不能用补充实验堆积代替这条论证。

若预算收紧，优先减少未授权的探索和可选对照，不删强文本、新事件或失败记录。若新事件无法获得，应明确缩小迁移主张并讨论后续数据补充，而不是承诺仅靠更多旧集 ablation 达到 Strong Accept。是否需要更多模型或真实事故，由当前结果暴露的外推缺口决定，不作为无条件新增任务。

最终交付一个紧凑的可审计 artifact：固定方法和输入生成规则、匿名对照包及来源映射、主结果和失败分母、机制/负载测试、复算脚本，以及受到许可证/隐私约束而不能公开的清单。这是复现条件，不额外包装成一个未经独立验证的新 benchmark。

### 11.5 如何回答“直接用文本 contrast 就够了，为什么需要 Canvas？”

本文不主张图像在逻辑上不可替代。文本能够表示同样事实；研究问题是在冻结单次调用模型及登记预算下，图表是否提供**可测量的诊断价值**。论文回答必须按以下证据顺序展开：

1. **先给文本充分机会。** X_C_TABLE 直接列出双方证据，保持语义和候选一致；保存模型实际输入，读者可以检查它是否被人为削弱。
2. **再做直接比较。** 主方法在 eval 上锁定后，于 test 同时比较两个文本 contrast 及强基线。高绝对 MRR 与视觉相对强文本的增量是两个分别需要成立的问题。
3. **再排查替代解释。** 表格截图区分像素传输与图表组织，视觉分组/时间消融定位设计作用，预算/负载中比较变化差；任何单项都不能独自替代主比较。
4. **最后给有限机制解释。** 来源绑定、目标/匹配移除、竞争者排名与自动断言核验共同说明输入如何影响输出。不以 attention、主观可读性或 AC@5 命中推断模型的隐藏思维。

| 观察到的结果 | 可以形成的论文主线 |
|---|---|
| 锁定视觉方法相对直接文本达到登记的实质性 MRR 提升，强基线与跨事件结果也成立 | 高质量 RCA 前提下，具体视觉表示有独立诊断增益；限定模型/数据范围，不说文本永远不能替代 |
| MRR 没有明确提升，但较低成本或更小的负载退化有配对证据，且标准条件没有明显准确率代价 | 具体成本/稳健性取舍；不把不显著差异或 ΔMRR>−0.05 的点估计当作已证明等效/非劣，也不替代项目准确率目标 |
| 只胜过 X_C，不能胜过 X_C_TABLE | 旧文本查找/组织是合理替代解释；视觉独立诊断优势未成立，不能用成功截图挽救这项主张 |
| 表格截图与真实图表表现接近，均胜过直接文本 | 结果与像素传输效应相容；没有证据证明图表编码独有作用，接近也不等于统计等效 |
| 新选择策略改善文本与视觉，但视觉没有可靠增量，或持续退化 | 证据选择贡献与视觉负面结果分别保留，收缩视觉中心的故事；不以追加 RL/挑 case 来掩盖 |

在新 test 结果出来前固定这些判断。只对已登记的机制类型、实体粒度、比较跨度和密度作有明确分母的分层；结果后新发现标探索性，不挑一个有利小群体代替整体。没有人工研究不会使自动 RCA 方法失去意义，但必须以机器实验的直接证据支撑机器贡献。

### 12.1 修订 3 的方法学依据与来源边界

本次阅读了 Ribeiro 等的 *Beyond Accuracy: Behavioral Testing of NLP Models with CheckList*（ACL 2020）的动机、黑箱测试分类、三项 NLP 任务实验、用户研究及局限。它用能力×测试类型组织评估，区分最小功能、不变性和方向性测试，并明确行为测试补充而不替代普通评估。这里借鉴的是“围绕具体能力提出可失败的输入—输出预期”，不是将其 NLP 结果移植为 RCA/视觉的已证实收益，也不恢复独立 QA。上述预算与重复负载实验是本项目的诊断任务设计，并非 CheckList 原有测试。[论文与正式记录](https://aclanthology.org/2020.acl-main.442/)

前一轮新读取的官方公开评审也提供了补强依据：RUBi 的 reviewer 追问简单强基线；Learning from Failure 的 reviewer 追问验证过程隐含使用的知识及假设；Sanity Checks 的 reviewers 区分直观例子、定量检查与解释充分性。这些是论证检查的参考，而非接收概率的统计证据。[RUBi 评审](https://papers.nips.cc/paper_files/paper/2019/file/51d92be1c60d1db1d2e5e7a07da55b26-Reviews.html)、[Learning from Failure 评审](https://proceedings.neurips.cc/paper/2020/file/eddc3427c5d77843c2253f1e799fe933-Review.html)、[Sanity Checks 评审](https://papers.nips.cc/paper/2018/file/294a8ed24b1ad22ec2e7efea049b8737-Reviews.html)
