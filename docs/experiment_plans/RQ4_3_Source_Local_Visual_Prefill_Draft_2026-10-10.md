## 2. 历史与文献给出的新切入点

### 2.1 历史实际上说明了什么

1. **应该保留均匀剪枝的性能与成本起点。** RQ4.1 的复杂来源选择没有稳定超过均匀选择；RQ4.2 SEM 的总 token 约为 A_UNIFORM_E50 的 2.89 倍，排名仍更低。
2. **位置扰动确实值得研究，但原因未定位。** RQ4.1 中移动卡片产生明显首选翻转，而独立重复没有相应翻转；当时移动也改变了编码特征和部分 mask，不能直接归因于语言侧序列顺序。
3. **改变视觉编码器分组没有解决问题。** RQ4.2 SEM−GEOM 约 −0.0004，不能据此宣称所有来源组织无效，也不能继续把相同分组换个名字重测。
4. **读数改善不自动带来排名改善。** RQ4.2 SEM 的阶段 QA 点估计有改善，MRR 未超过 GEOM。QA 保留为独立机制终点，不作为自动路由或采用依据。
5. **attention 不能代替上述检验。** 已有记录主要来自语言骨干一个 full-attention 层的少量 query，不能解释全部视觉编码或递归状态，更不能凭标题 attention 高就删除标题。

逐份历史报告及设计决定见[阅读与去重附件](RQ4_3_Source_Local_Visual_Prefill_Draft_2026-10-10_assets/review.md)。

### 2.2 为什么考虑语言骨干中的视觉预填充

本地模型目录名是 Qwen3.8-27B，但实际 `config.json` 的架构为 `Qwen3_5ForConditionalGeneration`。只读核对显示：语言骨干共 64 层，其中 **48 层 linear attention／Gated DeltaNet、16 层 full attention**；首三个语言层是递归层，第 3 层是第一个 full-attention 层，以上均为零起始编号。视觉编码器另有 27 层。

这意味着 RQ4.2 修改的 27 层视觉编码器，和本轮考虑的语言骨干，不是同一部分。图像在二维空间同时呈现证据，进入语言骨干后仍有序列化与递归处理。**这种顺序是否妨碍了标签、图元及阶段信息的联合使用，是待检验假设；现有结果尚未证实。**

文献对本提案的作用限定如下：

- [FEATHER，ICCV 2025](https://openaccess.thecvf.com/content/ICCV2025/html/Endo_Feather_the_Throttle_Revisiting_Visual_Token_Pruning_for_Vision-Language_Model_ICCV_2025_paper.html)提醒我们：常规问答上的剪枝表现不能代替细粒度读取、定位验证。保留均匀基线，不按 attention 大小直接判断证据价值。
- [SoFA，CVPR 2025](https://arxiv.org/html/2503.13792)研究多图位置偏差，并说明强行改变因果掩码可能损害准确率。本轮借鉴温和混合思路，但单图、递归层与原论文不同。
- [Gated Delta Networks，ICLR 2025](https://openreview.net/forum?id=r8H7xhYPwz)提供递归更新及高效实现依据，**没有证明我们这个 RCA 模型发生了记忆覆盖，也没有证明无需训练的反向扫描有效**。
- [Ask Twice, Look Twice，2026 预印本](https://arxiv.org/html/2607.15565)提供静态任务在图像前后出现的低成本启发；其收益并非在所有任务和模型上都成立。因此它是实用优化对照，不是核心创新。

更广的检索还包括空间绑定、图表感知、多尺度特征、特征重构剪枝、推荐系统递归记忆与视觉对比解码。没有把需要训练、额外整套前向或新数据的论文方法，包装成可直接套用的免费改进。

## 3. 候选核心方法：来源内的双向视觉上下文补充

### 3.1 要解决的具体问题

一条指标的标签、单位、曲线与阶段摘要，往往分散在一张卡片的多个视觉 token 中。提案让这些 token 在语言骨干的早期处理中获得一条**来源单元内的前后文补充路径**，同时保留原有全局路径供跨指标、跨实体 RCA 使用。

候选贡献不是“双向计算”或“实体分组”本身，而是：**在冻结的混合递归 VLM 上，用可审计的图元来源限定局部补充计算，在同图、同保留 token、同调用预算下检验读取、绑定和 RCA 的变化。** 创新性仍需与近邻方法进一步评审，初稿不作“首次提出”的判断。

视觉提供的可利用结构是图元的二维支持区域与共同来源。它可以把标签和观测定位为同一视觉单元。不能据此声称文本原则上无法表达相同信息，或相同技术绝不适用于文本。

### 3.2 完全继承的部分

- 使用 RQ4.1 `A_UNIFORM_E50` 对应的公共包、候选目录、PNG、实际 processor 几何及保留 token 索引；逐例核验后复用，不重新选出更有利的样本或 token。
- 数值写法、单位、阶段、所有原始图元和原有候选身份不变。没有 ECHO 的算法比较保留 patch 的原始三维位置编码；ECHO 按原生消息模板计算新增前置文字导致的位置偏移，图内相对空间坐标不变，不声称其完整 position tensor 与 U 相同。不旋转图片、反转曲线时间、改箭头方向。
- 所有诊断证据仍只在 `src/renderer/` 生成的图像中。来源清单仅控制计算和审计，不转为文字事实、答案提示或额外语义 embedding。
- 原模型参数、视觉编码器、输出评分口径和已资格的五候选排名解码保持冻结；不得顺便更换 schema、增加候选白名单、宽容评分或答案修复。
- 每个 RCA 条件只执行一次完整生成。不增加选择器、前置诊断、重采样或答案投票。

### 3.3 来源单元与共享支持

来源单元按原始**记录及出现位置**定义，而不是按“同一个实体”全部合并。例如：一条指标及其自身标签／单位／窗口统计；一个 Trace 操作记录；一个日志模板卡片；一个关系组件。相同实体、相同数值不意味着相同来源。

利用真实 processor 变换后的图元支持建立 token→来源单元映射。只有支持唯一且来源可验证的保留 token 进入局部分支；涉及多个来源的 token、全局页眉、公共候选目录和无法唯一归属的背景继续走原路径。**不为取得更多局部 token 而伪造独占归属，不删除共享 token。**

视觉编码器已经发生全局混合，因此“几何上属于某卡片”不等于“特征仅包含该卡片信息”。局部分支是有依据的计算组织，不能被解释为干净的因果隔离或新的隐私边界。

### 3.4 初稿固定操作

暂定只在语言层 **0、1、2** 的视觉预填充启用，融合系数 **λ=0.25**。这些是保守的工程起点，不是文献给出的最优值，也没有用 RCA 分数选择。后续评审如需修改，须在新推理前版本化冻结，不做有结果反馈的层数／系数搜索。

每层保留原始递归计算。在投影和原生短卷积完成后，复用相同的 q/k/v、门控参数：

1. 对每个合格来源单元按原序列顺序执行零初态局部扫描，得到 `o_forward`。
2. 对同一组投影后向量反序扫描，再恢复对应位置，得到 `o_reverse`。
3. 对这些视觉位置，在原有 gated norm／输出投影之前融合：

   `o_new = (1 − λ) × o_native + λ × (o_forward + o_reverse) / 2`。

4. 未参与位置保持原生输出。第 3 层及以后使用原始全局处理与原生生成。

这里反向的是同一来源内向量的**计算顺序**，不是遥测时间或调用方向。短卷积仍按原生方向计算，因此本方法不具有精确的排列不变性；反向支路也不等于重新从像素反向编码整张图。

文本位置仍走原生递归路径。局部状态不写入生成缓存；保留该层原生状态更新，后续层正常处理已融合的视觉表示。实施时必须独立验证 prefill、缓存和增量解码一致性，不能仅因输出 JSON 合法就判定适配正确。

### 3.5 主要失败可能

冻结权重未按这种计算训练，局部零初态、反向门控和混合输出均可能产生分布偏移；全局视觉特征也可能使局部来源限定并不有效。RQ4.1 原图部分处理后文字仅约 12–16px；新路径不能恢复视觉编码时已经丢失的细节。保持原图便于清晰比较，但不意味着它已经解决可读性问题。额外扫描增加计算，不能用“token 数没变”代替成本证明。

若小规模算子验证、数值稳定性、来源覆盖或实际耗时不合格，先停止本候选。不得通过缩小问题范围、放宽覆盖门槛或悄悄替换算法，强行进入全量。

## 4. 三个优化条件与三个必要控制

简称 `U` 为复用的 A_UNIFORM_E50。以下六臂均使用它的图像与 token mask。

| 新 Arm | 改变 | 独立问题 |
|---|---|---|
| **U_ECHO** | 在图片前重复原任务说明的第一个自然段；原图后说明逐字保留 | 极低成本的静态任务前置是否改善现有方法？ |
| **U_LOCAL_BI** | 仅启用上述来源内双向补充 | 新计算本身是否有效？ |
| **U_LOCAL_BI_ECHO** | 双向补充＋相同静态前置段 | **预选完整候选**，组合能否推进实际性能？ |
| U_LOCAL_FORWARD | 与 BI 相同来源、层数、λ，只使用 `o_forward` | 局部来源路径与反向信息分别有什么作用？ |
| U_SHAM_BI | 与 BI 相同计算，破坏局部来源对应 | 真正的来源对应是否优于同成本的任意局部分组？ |
| U_SOFT_IMAGE | 仅在语言骨干第一个 full-attention 层，对视觉 query 混合原输出与图内双向输出 | 常规 soft visual attention 是否已经足够？ |

`U_ECHO` 的前置内容只能是原 `VISUAL_TASK` 第一段，包含任务和五候选格式语义，不含当前病例实体或观测。实施前记录准确字节和实际 token，不能不断改写提示寻找收益。现有请求为 system→image→task，因此这里确有新增前置内容；没有复制图片。

`U_LOCAL_FORWARD` 使用 `o_new=(1−λ)o_native+λo_forward`，其计算略少，不能称为与 BI FLOPs 完全匹配。

`U_SHAM_BI`：保持所有合格 token、组数和每组 token 数，按病例哈希的单一固定种子打乱 token→组分配；组内重新按原序列索引排序。图像、坐标和输出格式均不变，不把错误绑定画进图中。不能搜索更多种子挑效果。它隔离的是正确来源的局部组织，不等价于随机删除证据。

`U_SOFT_IMAGE`：初稿使用同一 λ=0.25，分别计算原生输出和允许视觉 query 访问整张输入图像的输出，再做线性混合；文本 query 及生成仍为原生因果模式。**这是受 SoFA 启发的单图输出混合适配，不是 SoFA 原算法复现。** 原论文官方仓库当前只有待发布说明，不能声称复用了其可运行实现。不要混淆 mask 混合与两次归一化后输出混合。

普通相同请求与相同计算可以引用本轮已提交结果。没有局部支持的 BI/FORWARD/SHAM 条件若实际与 U 相同，引用 U；BI_ECHO 若实际与 ECHO 相同，引用 ECHO。回退必须显式记账，不能计作成功干预。不存在转为文字诊断的回退。

## 5. 机制子集：固定图像，拆开两个问题

固定哈希选择 60 例，每数据集 20 例，优先不同事件组，不按历史成败、解释错误或 QA 分数挑选。

### 5.1 QA 是否改善，以及改善有没有进入排名

对 U 与 U_LOCAL_BI 各一次独立 QA，每例最多六题，覆盖单值读取、实体／单位绑定、两阶段比较，沿用 RQ4.2 修复后的独立 QA 接口。两臂问题和答案标准相同，目标标记通过 unified renderer 加入对应图形。

QA 不继承 RCA 排名任务；QA 答案不进入 RCA。无法实例化的题记录不适用，不换题。QA 是每例一份回答，不能将六题当六个独立病例。报告三个子能力和 ΔQA–ΔRR 的关联及边界，不把无显著相关写成统计独立。

### 5.2 图像不变时，语言侧顺序是否仍会改变诊断

对同一子集的 U 与 U_LOCAL_BI 各做一次受控顺序干预。PNG、视觉编码器输出、保留 token 集合与每个 token 的空间 MRoPE 坐标完全相同；仅在进入语言骨干前改变来源 token 块的串行位置，采用固定半序列循环位移，单元内顺序不变，共享／全局 token 使用固定位置规则。

必须分别管理因果序列索引和空间位置编码，不能把空间坐标一起重编号成新位置。非连续单元的打包规则、全局 token 固定位置及半移位的完整置换表在运行前冻结。这个干预涉及语言骨干的短卷积、递归和后续因果处理，**不是只改变一个纯粹 GDN 因素**。

它比历史重画卡片更明确地排除了图像重编码和剪枝选择变化。若接口不能保持这些等同性，就取消该干预并说明缺口，不以重画图片代替。

从此子集再固定 12 例（每数据集 4 例），U 与 U_LOCAL_BI 各做一次完整独立重复，用于本次运行的翻转噪声参照。不是整批基线桥接重跑；历史 360 次零排名翻转不能直接保证新算子也完全稳定。

## 7. 资格与实施顺序（未来获准后）

### A. 先做可行性与去重，不提取整批新特征

1. 建立生成身份／评分身份分离清单；核对历史 U、T、混合基线的病例、评分器版本、失败分母、模型、提示、mask 和解码版本。
2. CPU 完整审核 220 例公共来源与实际 processor 几何，确认图片及保留集合未改。核算源单元覆盖、共享支持、各组长度及实际文本 token。
3. 初稿的有意义覆盖门槛：每个数据集至少 50% 病例有两个以上合格局部单元，且各单元至少 8 个保留视觉 token、合计覆盖至少 20% 保留视觉 token。未达标病例保留分母；门槛失败停止来源候选，不靠重定义来源去凑数。这是干预覆盖条件，不是读取准确率条件。
4. 对合格病例，SHAM 的同组关系相对真实分组须有实际变化；以 token 对共组关系变化率报告，并要求至少 50% 的合格病例达到 50% 变化。若不足，在模型调用前取消来源归因臂，不能换种子。
5. CPU 小张量独立计算验证 λ=0 恢复原路径、前后向索引、空／单 token／共享来源、非连续支持、组编号置换和数据不丢失。真实模型只需少量固定样例核验，不提前提取全部 220 例。

### B. 实现与受影响检查

未来代码放在 `RQs/RQ4_3/`，五功能模块、7,500 行范围内；新 RCA 评分只从 `scorer` 导入，不引入外部 RCA checkout。新适配显式启用，历史模型路径和 renderer 默认语义不变。静态检查通过后才进入 CPU 回归；最多八个不同物理核 worker，不以人为低内存上限牺牲速度。

CPU 覆盖索引、单位、候选、renderer 字段绑定、QA 接口、预算、原子提交、引用、真实重复、暂停排空及断电恢复。未知结构显式失败，不静默漏来源。正常图像与 QA 图像全部经 `src/renderer/`；已有折线继续跨缺测连接、不标记缺测。

每 arm／数据集只审一个固定例图，并补查最密、长名称与极值。由于主臂 PNG 相同，用同一组图加计算差异清单，避免重复绘图和重复看六遍完全相同图片。

### C. GPU 资格先检验数值与成本

一个共享 smoke 上限 18 次、600 秒，含保存验证；三个固定 eval 身份，覆盖六种新计算、独立 QA 和顺序干预，复用同次调用测 attention 和耗时。具体 18 位置矩阵在实施前冻结；不能在看到结果后替换病例。生成前的无输出特征／算子探针单独登记 GPU 时间，不把它们伪装成免费推理。

重点核验：原生路径等价、有限数值、局部缓存不污染生成、文本因果边界、KV/state 生命周期、mask 与 MRoPE 一致、无重复投影及全模型重放。不得用逐 token Python 循环实现正式局部扫描；优先使用已安装栈的批量变长内核，无法适配就明确停止。

沿用合格本地模型、40960 context、8192 最大输出、GPU 利用率 0.75 和既有排名配方；不为了适配强行改精度或降证据像素。所有请求输入＋输出上限须符合上下文。

小样例交错计时，报告完整冷路径与 prefill／生成分项。先争取平均完整时延相对 U 不超过 1.05 倍；小样例只能筛查明显回归，正式数据才决定最终成本。若算子明显超预算或 600 秒内资格不完整，不启动全量，也不重置 smoke。

### D. 冻结完整运行和恢复

只有未来用户授权且资格齐全才运行。按固定病例哈希及均衡 arm 轮换，不按临时 MRR 改队列。真实生成身份包括提示、PNG、processor、保留索引、来源路由、层号、λ、模型、解码和种子；评分版本独立管理。

成功原子完成标记是恢复边界；关机后跳过已提交结果，不重新打开全部旧图或重新推理完整基线。只允许对未提交基础设施中断使用预留，不重答错误排名或无效候选。

## 8. 结果判定：进步、方法成功、机制发现分别评价

预选方法固定为 **U_LOCAL_BI_ECHO**，不依据结果改选最高分。

**主要比较族**：候选−历史 U、候选−历史 T_FULL。病例与事件组分别使用同一两项 Holm 校正；事件组为主要推断，报告病例加权 ΔMRR。采用双侧 Pratt-zero Wilcoxon、12 位差值、配对 dz，不报告 CI；不把 signed-rank 检验当成任意均值零假设检验。历史对照的时间、后端与曝光限制单列。

**方法解释族**：BI−FORWARD、BI−SHAM、BI−SOFT_IMAGE。只有相应结果支持，才分别归因于反向补充、正确来源组织或递归路径相对 full-attention 适配的额外价值。删除某个资格失败臂时，必须在首个正式调用前同步冻结缩减族。

**次要族**：ECHO−U、BI−U、组合−BI、交互 `(组合−BI)−(ECHO−U)`。只有交互得到支持才称协同，不能把两个单项之和换成新算法贡献。

**机制族**：BI−U 的病例级 QA；两种表示各自的顺序扰动相对重复噪声；两者扰动差异。12 例共同重复子集用于配对噪声比较，其余 60 例扰动率另报，不能拿不同分母直接做成配对检验。稀疏翻转采用病例级精确检验／配对置换，方向、统计量、Holm 族须在调用前固定；不把多个题或 token 当成独立样本。

工程目标分两级，防止把局部进步写成项目完成：

- **值得保留的开发进步**：相对 U 整体 ΔMRR≥0.03，三个数据集 MRR 与 AC@5 不下降；各集实际 input＋output≤U 的 1.05 倍，并记录完整时延。达到而统计不足时，称待确认开发进步。
- **当前研究主目标**：超过历史 T_FULL，整体目标至少 0.5046（T_FULL＋0.02），各集 MRR／AC@5 不下降，实际部署成本≤T_FULL 的 1.05 倍。MARGINAL_FIVE 0.5054 继续并列表述；MRR≈0.60 仍是愿景，不是本轮保证。达到开发目标但未胜过文本，明确只完成局部进步。

所有模型无效回答计零；基础设施未知不计零也不丢弃，报告完整分母紧界限。给出绝对 MRR、AC@1/3/5、Precision、AVG、宏平均、修复／破坏、粒度及绑定错误、输出合法率。按固定哈希每数据集审查 12 例的全部新臂解释，区分读数、归属、阶段与无依据因果断言，不把措辞流畅视为可信。

## 9. Attention 与实际成本

只在固定机制子集复用真实调用记录：文本说明、图像标签、图元及页眉区域。沿用已资格聚合方案，每次硬上限 64 KiB；包括索引、分配和临时文件的每 10,000 次峰值不超过十进制 1 GB。不要保存完整矩阵、Q/K/V 或逐调用热图。

新增局部分支最多保存每层的聚合增量范数、支持数量与计时，不输出各 token 状态。full-attention 摘要不能冒充递归记忆测量；attention 变均匀也不作为成功门槛。采集若破坏资格则关闭，不阻塞主方法。

分别报告文本 token、图像 token、总输入、输出、绘图／来源编译、视觉编码、局部扫描、prefill、生成、验证和峰值显存。**图像 token 数相同不等于成本相同。** 历史 U 的耗时不是同期冷路径证明；少量相同栈微基准用于工程资格，不产生可替代整批历史结果的新基线。

## 10. 初稿的取舍、时间边界与停止条件

这是一项有风险的机制驱动优化，成功概率尚不能从历史 MRR 推出。第一优先级是验证新路径是否有足够来源覆盖、数值可靠且便宜；不先耗费几天搭建全量分析后才发现内核不适配。

未来获准实施后，建议一个工作日内完成源码适配与少量算子可行性判断；第二个工作日完成剩余资格及是否值得启动的决策。全量时间用真实 smoke 吞吐估计，不沿用别的后端的在线秒数给出保证。若初期适配失败，应交付明确失败原因，不以增加更多实验臂掩盖。

本轮不追加：新的布局、边际图数量搜索、标题删除、更多剪枝比例、多阶段 RCA、训练、全批次特征提取、同期强文本重跑、自动追跑事后赢家。

若只 ECHO 改善，承认实用提示改进，结束双向来源候选；若 BI 有整体收益但来源控制不支持，承认新计算收益，收缩来源归因；若 QA 改善而 MRR 不改善，保留有边界的脱节发现，不以机制发现代替主线性能。若全都失败，停止本候选，不自动换层／调 λ。
