## 一、核心判断：问题不是“缺少更多选择器”，而是没有保住不同故障所需的证据结构

下一步不继续淘汰赛，不简单合并若干“获胜专家”，也不立即训练 Composer。

应当把淘汰赛的案例规律转化成一个统一方法：

> **保留不同故障机制赖以成立的关键观测，再选择能够区分竞争解释的补充证据；不能为了形成漂亮的对比包，先把无法配对的有效信号丢掉。**

这里的“统一方法”是同一套确定性规则处理所有 cases，不是运行多个 RCA 方法后挑正确答案，也不是根据数据集名称切换策略。

1. **X 确实找到了 P0 遗漏的一部分有用信号，不能全部放弃。**
2. **X 为获得这些新增信号，丢掉了更多原先有效的证据，不能直接整体替换 P0。**

另外，旧报告的“根因证据可见”包含 G 中的关联事实。新分析必须分别统计：

- 根因是否在候选名单；
- 是否只有拓扑／部署关系涉及根因；
- 是否有根因自身的 M/R/L；
- 是否有与该故障机制相关的观测；
- 是否真正进入模型可见输入。

### 1.2 淘汰赛是下一版方法的主要设计依据

采用下面这张“发现—规则—实验”映射表，而不是按新增淘汰数挑专家。

| 淘汰赛发现 | 合理推论 | 新方法规则 | 如何验证 |
|---|---|---|---|
| R2 稳健偏离与 R3 Trace-SC 修复了不同案例 | 不同统计量能暴露不同诊断信号 | 保留资源变化与操作级行为两类入口，不统一压成一个异常分数 | 去除机制覆盖约束 |
| R3 在 AegisLab 的互补明显，AIOPS-2025 较弱 | Trace 的作用受可观测性和故障机制制约 | 有 Trace 时利用操作差异；没有 Trace 不削弱其他证据的资格 | 稀疏 Trace 分层 |
| R4、R18、R33 的日志策略有收益，但成功不一定来自根因日志 | 减少竞争症状、改变上下文也可能有用 | 区分根因支持证据、竞争者证据与重复噪声 | 日志／干扰替换实验 |
| R10→R11 事实集合相同，Metrics 文本化后新增 43/37 个成功 | 有些失败发生在表示与比较环节，不是选择环节 | Metrics 文本＋R/L/G 图像必须保留为主要条件 | 同事实文本、图像、混合对照 |
| node 故障经常误选 pod/service | 需要区分宿主压力与局部实例故障 | node、pod、service 分层保留证据；关系不代替遥测 | 去除层次覆盖约束 |
| AIOPS-2025 的剩余难例常缺根因 Trace/Log | 跨来源完整性不能成为证据入选前提 | 单来源资源、状态证据可以独立入选 | 强制完整配对的反向消融 |
| R35 的个别成功来自请求量变化与相对稳定的执行耗时 | “变慢”并非唯一重要异常；下降与不变也有区分力 | 同时保留流量、错误、执行耗时的方向和对照 | 去除区分证据 |
| 后期多数方法增量很小，剩余案例多次出现过根因证据 | 更多异常排序并不必然提高诊断 | 优先保留诊断机制与竞争解释的差别，不继续扩充算法名单 | 同预算选择与排名修复分析 |

R11 的收益同时涉及承载、token 和画布内容变化，因此不能直接宣布“数字阅读”是唯一原因。新实验负责进一步拆分。

### 1.3 当前 X 的三个结构性风险

代码与结果结合后，可以确定以下机制值得优先验证：

**第一，容易配对的证据占便宜。**

当前宿主—实例对比需要较完整的同服务实例、宿主映射以及兼容指标；真实数据不满足时，很多资源事实不能进入这种 bundle。

而 node 单独的内存、磁盘或 CPU 证据，即使有用，也不应因为没有另一个合适对象而失去入选资格。

**第二，便宜的关系可能挤占昂贵的遥测。**

当前预算将 metric series、trace 摘要和图关系赋予不同成本，选择又使用增量成本。共享关系和 Trace 可以形成便宜的组合；图边还可以同时“覆盖”两个实体。

但“覆盖了两个图端点”不等于“保住了两个实体的诊断证据”。

**第三，选择器之外还改变了统计表达。**

X 使用了不同的分析分界、稳健统计及极值投影；部分异常分数来自整个窗口的最大偏离。因此旧 X 与 P0 的差异不能只归结为“对比式选择好不好”。

下一版必须把：

> 公共统计 → 证据选择 → 表示承载

分开控制。

相关研究也支持按异常类型、观测条件分别处理，而不是要求所有来源始终齐全。例如 MicroHECL 区分延迟、错误和流量的分析方向；TORAI 专门处理调用图的可观测性盲区。这里只借鉴其问题结构，不把本项目方法称为这些系统的复现。[MicroHECL](https://arxiv.org/html/2103.01782)、[TORAI](https://arxiv.org/html/2604.13522v2)

## 二、新方法：诊断信号保留与区分式编译

暂名 **CanvasRCA-SignalCover**，简称 **SC**。

名称不是创新性结论。方法的可检验贡献是：

> 在有限上下文中，同时保住有效的基础证据、覆盖异质故障信号，并提供少量有针对性的竞争解释对照。

### 2.1 固定部署边界

- 一个冻结 Solver，一次调用完成 RCA。
- 不训练模型，不运行预诊断 LLM，不进行多轮检索。
- 最多一张真实 Dashboard。
- 主部署候选：**Metrics 文本＋R/L/G 图像**。
- 全视觉是正式比较条件，不预设它最好。
- TPV 作为强对照保留，不因不符合主部署的混合限制而取消。
- 候选列表继续放在文本中；数字匿名化、granularity-aware scorer 保持。
- 不新增 attention 记录。
- 不修改既有模型推理配方。

### 2.2 输入来自完整 per-case 数据

所有新证据入口直接读取 canonical per-case public telemetry。

P0 是一个需要保留和对照的选择策略，不是新方法唯一可以访问的证据池。MET-Z、TRC-L、LOG-R 和 Denum 可以复用已有实现，但不得把它们历史 top-k 的输出误当成完整数据。

在模型调用前，CPU 侧统一完成：

- 实体与公开部署关系绑定；
- 指标类型、单位和计数器语义识别；
- 固定公开时间区间上的统计；
- 操作级 Trace 与来源可追溯的日志结构；
- 状态转移、流量变化及可靠的同类比较。

不将完整遥测序列化为巨型 prompt。

### 2.3 从算法名单改为六类信号结构

这六类是统一选择器识别的观测结构，不是六个独立 RCA Agent。

| 信号结构 | 保留内容 | 主要针对的失败 |
|---|---|---|
| 持续水平变化 | 基线、当前值、变化方向、持续程度 | 资源压力被瞬时尖峰掩盖 |
| 波动与短时事件 | 方差变化、脉冲、恢复片段 | 均值不明显但行为改变 |
| 离散状态与可用性 | readiness、restart、进程状态、明确观测到的停止／恢复 | pod/process 故障未被普通异常排名捕捉 |
| 流量与错误组成 | 请求量、错误比例、状态码和 operation/template 组成 | 高频正常日志、重试或流量变化误导 |
| 宿主与实例范围 | node 自身资源、所属实例、可比较 peer | node/pod/service 层次混淆 |
| 本地行为与关联影响 | 真实 span 支持的耗时、相邻调用、流量和时间关系 | 把受影响组件当故障源 |

具体约束：

- 同时考虑上升、下降和有依据的不变。
- 不把低日志量自动当健康。
- 不把采集缺失当数值零或请求停止。
- 不用汇总 p95 相减伪造 exclusive latency。
- 不要求日志必须能按 trace ID 联结。
- 不强制所有故障都沿调用图解释。
- 无法可靠识别语义的指标仍可保留原始观测，但不能生成未经支持的机制结论。

FSE 的故障传播评估研究特别指出，遥测停止、观测盲区及矛盾信号是现有方法的困难来源；这支持上述入口，但不证明这些规则一定提高本项目 MRR。[论文项目与材料](https://operationspai.github.io/revisiting-rca-evaluation/)

### 2.4 选择规则：基础保留、机制覆盖、区分补充

默认沿用 P0 每个 case 的 M/R/L 显示容量。按“series／operation profile／template group”等实际证据单元计数，不按 JSON 拆出了多少条 fact 计数。

每个区域的容量分为：

1. **基础保留：约 50%。**  
   保留 P0 排序前部的有效证据，避免整个方法因换选择器而失去已验证的基本能力。

2. **机制覆盖：约 25%。**  
   从完整池补入尚未表示的实体层次和信号结构。

3. **区分补充：剩余容量。**  
   选择能检验已展示异常解释的对照或关联证据。

整数配额：基础部分向上取整，覆盖部分向下取整，余数归区分补充。缺少合格证据时按同一区域的确定性顺序补齐，记录原因，不伪造对照。

机制覆盖按以下顺序选择：

- 优先填补尚未表示、但有可用信号的 node/pod/service 层次；
- 再填补尚未表示的信号结构；
- 再按同语义信号内部的公开强度排序；
- 最后使用稳定 hash 打破并列。

这里不使用数据集名称、根因标签、历史成功与否或模型回答。

**G 单独管理。** 图关系用于连接被选证据，不占用 M/R/L 的诊断覆盖名额，也不能让一个实体仅凭出现在图边上就被标为“已覆盖”。

### 2.5 对比包不再是准入门槛

新的对比包最多包含：

- 两个主要观测；
- 两个必要的辅助观测；
- 对应的公开关系。

允许三种形式：

- **自身前后对比**：不需要另一个实体。
- **同类对象对比**：语义、单位、时间范围兼容。
- **关联对象联合观察**：保留各自单位，不假装它们能直接相减。

对照不存在时，保留有用的单侧证据。不能把 node 资源事实放进一个语义上次等的“杂项上下文”区域。

对比规则不是“两个异常最大的 service 二选一”，也不向 Solver 提供“选择器认为谁是根因”的分数。

### 2.6 公共统计先固定，避免再引入隐藏变量

主要选择实验使用同一份公开分析区间与统计契约：

- 继承经过核验的 P0 公共时间分界，不使用注入时间；
- 每种新选择策略看到同样的源观测及统计；
- 基线和当前阶段分别计算；
- 当前异常分数不把基线期的最大尖峰混入；
- 趋势、极值和状态分别保存，不用一种聚合代替全部信号；
- 原 X 的统计保留为独立对照，而非悄悄覆盖历史。

这不是禁止使用新统计量，而是让新统计量的影响能够单独测量。

### 2.7 表示不再进行大范围自由搜索

只保留四种新承载：

- **C-Flat**：紧凑、按区域组织的文本。
- **C-Contrast**：同事实、真正局部并列的文本对比。
- **V-Contrast**：真实图表，相关观测在空间上相邻。
- **M-Text**：Metrics 使用文本，其余模态进入同一张图。

另保留 V-Standard 作为视觉组织对照。

使用已有可读图表原语，不重新搜索大量配色、剪影和布局。新设计的重点是：

- entity、单位、时间和关系绑定清楚；
- 不让读者在大量 O/C 引用之间来回跳转；
- node 的自身证据与 pod/service 的证据具有同等地位；
- 对比文本获得与对比图像相同的组织信息。

因此可以直接回答 reviewer：

> 同样的证据与对比分组已经提供给强文本条件；视觉的作用由剩余的性能、错误绑定和稳健性差异检验，而不是由更好的选择或额外说明冒充。

公共 RCA 方法与输出契约尽量继承原 SIRCL-style prompt。表示说明单独替换，Text 不收到 Dashboard 指南。不强迫模型输出五个候选来人为提高 MRR；候选数量、非法 ID 和格式失败单独报告。

## 三、实验设计：先验证规则，再验证视觉，最后锁定泛化

新研究登记为 **RQ3.2**。旧 RQ1.1、RQ2.1、淘汰赛和 RQ3.1 的代码、结果及报告全部保留。

### 实验前分析：把淘汰赛变成“模式证据表”

不产生模型调用。

对所有已完成轮次与实际运行过的 cases，建立以下对应关系：

```text
公开数据特征
→ 本轮相对前轮增删了什么证据
→ 根因及主要竞争者的证据如何变化
→ 排名如何变化
→ 公开 reason 是否引用对应观测
```

分别统计：

- 新增根因相关观测；
- 根因观测未变，但竞争上下文变化；
- 事实未变，仅承载变化；
- 选到根因自身遥测，但没有选到相关机制；
- 正确排名伴随错误解释；
- 多轮始终未进入前五；
- 曾进入前五，但始终不是第一。

在同一轮的共同剩余集合内比较成功与失败；跨轮只使用实际共同观测，不补造已淘汰案例的结果。

按五个数据集分别、两个 AIOPS 合并、全部 cases 汇总。小样本规律单列计数，不据此硬编码规则。

产物是可追溯的模式表，不训练成功预测器，不用 case ID 建路由表。

### 实验一：`exp_signal_selection`

**问题：哪条规则真正改善了证据选择，而不是靠更大的输入？**

全部条件使用 C-Flat、相同公共 prompt 和评分器。

| Arm | 变化 |
|---|---|
| `P0_CAL` | P0 选择＋公共新文本接口 |
| `X_NATIVE_CAL` | 原 X 统计与选择＋同一文本接口 |
| `X_ALIGNED` | 原 X 选择规则，但使用公共统计契约 |
| `SC_COVER` | 基础保留＋机制覆盖；区分配额按覆盖规则补齐 |
| `SC_FULL` | 完整基础保留、覆盖与区分 |
| `SC_NO_BACKBONE` | 取消 P0 基础保留，其名额交给新规则 |
| `SC_NO_STRATA` | 取消实体层次与信号结构覆盖约束 |
| `SC_STRICT_PAIR` | 非基础部分只允许完整双侧对比包 |
| `P0_MORE` | P0 相同排序，容量增加 25% |
| `SC_MORE` | 完整 SC，容量同样增加 25% |

**调用上限：10×480×2＝9,600。**

这组实验可以区分：

- X 的问题来自统计还是选择；
- 基础保留是否降低破坏；
- 机制覆盖是否补到资源／状态盲区；
- 强制配对是否损害稀疏案例；
- 收益来自更好的选择，还是仅仅增加信息。

除了 MRR，还必须报告根因 M/R/L 及机制证据的入选变化、repair/break、node→pod/service 误选率。

`SC_FULL` 是预注册主方法；其他条件是解释与预算敏感性对照，不按 case 挑最佳结果。

### 实验二：`exp_signal_representation`

**问题：保住信号后，视觉是否还有独立价值？**

固定两种选择：`P0`、`SC`。

每种选择运行：

- C-Contrast；
- V-Standard；
- V-Contrast；
- M-Text。

C-Flat 已由实验一提供，不重复调用相同请求。

**新调用：8×480×2＝7,680。**

另外保留原 T、原 TPV、SIRCL_TEXT 三个强桥梁；完整请求及评分契约兼容则复用，否则登记新调用，最多 **2,880**。

关键比较：

1. `SC C-Contrast − SC C-Flat`：文本对比组织本身是否有用？
2. `SC V-Contrast − SC C-Contrast`：相同内容与对比组织下，图像是否提供增量？
3. `SC M-Text − SC V-Contrast`：Metrics 的承载是否仍是瓶颈？
4. `SC V-Contrast − SC V-Standard`：空间邻近是否有效？
5. SC 与 P0 的对应差值：选择和表示是否存在交互？
6. 新部署条件与原 TPV、SIRCL_TEXT：最终是否值得采用？

**不能只拿新方法的最佳图像与旧方法较弱文本比较。**

### 实验三：`exp_signal_mechanisms`

**问题：改善是否真的发生在我们推断的环节？**

从 RQ480 的五个数据集各 hash 选 20 个，共 100 个；不按是否改善挑选。

对固定的 C-Contrast 与 M-Text 各运行七个条件：

1. 移除一个合格的根因机制证据包；
2. 移除模态、规模匹配的非目标证据包；
3. 保持事实，取消局部对比分组；
4. 在选择池中加入预注册的、来自同 case 的重复／低诊断价值观测；
5. 一致地重匿名化；
6. 原输入独立重复调用一次；
7. 原输入再独立重复调用一次。

**调用上限：7×2×100×2＝2,800。**

#### 2026-09-22 固定画布下的噪声干预修订

画布尺寸、raster scale、字体和图像 processor 在 RQ3.2 中保持为控制量，
不作为本实验的研究因素。原 `REDUNDANT_NOISE` 直接取噪声池前 12 条，
其中长日志可能集中占满固定 L 区。修订后的 `region_capped_v2` 仍按原有、
标签盲的噪声池顺序最多加入 12 条，但日志最多 2 条，其余名额由后续合格的
Metrics/Trace 事实补足。全 100-case CPU 构造审计均通过；99 个 case 加入
12 条，1 个 case 因公共候选耗尽加入 11 条。

该修订不扩大画布或改变 renderer。`REDUNDANT_NOISE` 的 C-Contrast 与
M-Text 两种表示均按新规则完整重新判定；请求逐字节相同的单元允许复用其
content-addressed 结果，事实发生变化的单元必须重新调用模型。旧规则下不再
匹配新请求的结果仅作为 superseded audit artifacts 保留，不与修订后结果
混合。其他机制条件不受影响。

前两项只由 evaluator-private 离线构造；不存在合格目标或匹配对照时记为不适用，不造数据。

重复调用只估计输出波动，不取最好答案。噪声实验同时检查选中集合和最终排名，区分选择器抵抗噪声与 Solver 抵抗噪声。

重点报告：

- 根因从前五外进入前五；
- 根因已在前五时进一步到第一；
- 原正确案例被破坏；
- node/pod/service 错误归属；
- 数值、状态、调用边和部署关系的引用正确率。

公开 reason 只能支持可观察的解释分析，不能被当成隐藏推理过程的完整记录。

### 实验四：`exp_signal_locked_generalization`

**问题：锁定后的单一方法能否在非开发病例上保持收益？**

在实验一、二结束后锁定：

- SC 规则；
- 一个统一预算；
- 所有 prompt、表示与输出契约；
- 不再根据 test 的成绩改变规则。

统一预算只在 `SC_FULL` 与 `SC_MORE` 中选择：依据 RQ480 上 Qwen 三主数据集等权 MRR；差距不超过 0.01 时选择较小预算。全部 ablation 仍完整报告。

固定六个方法：

1. 原 T；
2. 原 TPV；
3. SIRCL_TEXT；
4. SC C-Contrast；
5. SC V-Contrast；
6. SC M-Text。

数据分两层：

- **既有 360-case test：**作为已暴露的锁定回归评估，不能再次称 untouched test。调用最多 **4,320**。
- **新的未使用事件：**按用户选择，先审计 unused，目标每个主数据集最多 30 个，共最多 90 个，调用最多 **1,080**。

新事件必须排除旧 eval/test/train、探索访问、事件别名及重叠窗口组。若不足，使用实际合格数量，不拆组凑数。

现有 unused 中 AIOPS-2025 只有 30 个，不能假定现成还有一个三数据集各 120 的全新 test。更大规模独立验证放到方法有效之后单独规划。

### 总调用预算

| 工作 | 最大新增 calls |
|---|---:|
| 选择规则实验 | 9,600 |

不为用完预算增加探索。保留部分余量供一次有界的方法修订；不恢复无限淘汰赛。

## 四、如何判断实质性进展

### 4.1 先检验信号，再检验排名，但不以 coverage 代替 MRR

方法需要沿着以下链条得到证据支持：

```text
原池存在有用观测
→ 新方法更稳定地保留
→ 模型实际获得可读证据
→ 竞争候选更容易区分
→ MRR／AC@1 改善
```

根因实体 Metrics 数量提高并不自动意味着成功。尤其要检查保留的是 CPU、内存、I/O、状态或流量中哪种机制，而不是任何一条碰巧属于根因的指标。

### 4.2 主要统计口径

- Primary：MRR。
- Secondary：AC@1/3/5、AVG@3/5、repair/break、排名移动。
- 每个数据集单独报告。
- 两个 AIOPS 分别及合并报告。
- 同时报告三个主数据集 macro、五数据集 macro 和 pooled，不混用分母。
- 配对 Pratt-Wilcoxon、paired Cohen’s dz、预注册 Holm families。
- 存在重叠事件组时做 group-level 敏感性分析。
- 不报告 CI，不把两模型、不同 arms 或重复调用当作额外病例。

主方法相对 `P0_CAL`、TPV、SIRCL_TEXT 的比较构成一个预注册 family；机制消融及表示比较分别构成独立 secondary families。

Gemma 是跨模型检验，不将两个模型的预测合成一个部署答案，也不要求它与 Qwen 有相同候选数量。

### 4.3 成功与停止低价值分支的规则

**选择阶段的有效进展：**

- SC 相对 P0 的诊断增益不能主要来自少数饱和 RE2 cases；
- node 与稀疏可观测性案例不再被系统性牺牲；
- 新增信号带来的 repair 足以抵消删除旧信号带来的 break；
- 等预算对照表明收益不只是“塞得更多”。

**视觉阶段的有效进展：**

- 与同事实 C-Contrast 比较，而非仅与较弱文本比较；
- 达到准确率提升，或者在保持较高准确率时显著降低输入开销；
- 输入与输出 token 分开报告，不承诺输出更短；
- 视觉若退化，保留负结果，不靠调整解释挽救。

“实质性准确率提升”继续使用 ΔMRR≥0.05 且 Holm-adjusted p<0.05。

项目原有目标——test MRR≥0.65、两个 AIOPS 分别≥0.60——保留为长期效果目标，不宣称本方案能够保证达到。90 个新事件的验证也不足以替代未来更充分的独立评估。

如果 SC 在公共文本条件下仍明显不如 P0，先处理选择问题；不把大规模新布局搜索或 RL 当作默认补救。

## 五、实施检查与最终交付

### 5.1 必须先通过的检查

- 完整 per-case 数据入口没有被旧 top-k 提前裁掉。
- 每个选择规则真实改变对应证据，不能只有名称不同。
- 图关系不再被误计为直接遥测覆盖。
- node 独立证据不因缺 peer、Trace 或 Log 而失去资格。
- 自身前后、peer 和调用关联三类对比没有混淆。
- 计数、率、单位、状态值和时间区间一致。
- Text 与 Canvas 共享同一选中事实集合，不在 renderer 中二次筛选。
- 关键字段真正可见，不只是出现在 manifest。
- 旧桥梁不修改；新公共描述层的变化单独登记。
- 失败、未知候选、少于五个候选和基础设施错误分别处理。
- 已完成单元可安全续跑，不重算全量 preparation，不做不必要的大文件重新核验。
- 不新增 attention 大文件，不训练，不启动多 Agent 系统。

每个实验仅一个 ≤18 calls、≤600 秒的逻辑 smoke。正式运行前查看真实输入、Dashboard、raw response 和 conversation，而不是只看 summary 是否成功。

### 5.2 最终交付物

主计划和后续报告应包含：

1. **淘汰赛规律图谱**：哪些信号结构修复了哪些失败，哪些规律只有少量支持。
2. **P0→X→SC 的证据组成变化**：特别是资源、状态、Trace 与图关系的替换。
3. **完整对照结果**：包括失败和退化方法，不只展示最佳条件。
4. **选择×表示交互**：哪些信号适合图像，哪些更适合文本。
5. **机制验证**：相关证据移除、匹配移除、噪声和重复调用。
6. **锁定后的泛化评估**：明确区分旧 test 回归与新的独立事件。
7. **可部署单方法定义**：固定规则、固定预算、一次调用，不依赖事后选答案。

最终希望形成的故事不是“图像能压缩遥测”，而是：

> **淘汰赛揭示了三种不同瓶颈：关键证据未被选择、竞争解释未被区分、已选证据未被有效读取。CanvasRCA 用一套保留诊断信号结构的证据编译方法分别处理这些瓶颈，再通过同事实的强文本对照，确定视觉究竟在哪些环节提供了额外价值。**

这比继续增加选择器、继续更换 Dashboard，或直接把问题交给 RL，更有机会带来可解释且可复用的实质性进展。
