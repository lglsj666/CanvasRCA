## 1. 决定：先辨认强方法的有效部分，再补真正不同的信息

**不继续叠加异常评分、宿主提示和数学关系，不再次整体替换 TPV，也不立即训练或引入多轮 Agent。**

下一步分成两条独立、可证伪的研究线：

1. **强基线拆解：**SIRCL 在部分 node/pod 和 AIOPS 案例上的优势，究竟来自它保留的证据，还是它的诊断指令？用交叉实验回答，不能看到局部高分就按数据集切换方法。
2. **联合证据：**保留 TPV，新增“相同请求/可比较实例中，某个局部现象与可观测失败如何共同出现”的统计。先与边际摘要和普通加量比较，再研究视觉怎样承载这种关系。

提出第二条不是因为“还没试够方法”，而是 RQ3.3 的 COHORT 实际只在 10/60 cases 进入了输入，且全部来自 AIOPS-2022。我们没有充分检验它在另外两个主数据集的价值。**这是旧假设的实质补验与重新设计，不包装成从未考虑过的新概念。**

拟检验的核心问题：

> 在冻结、单次调用的 RCA 中，保留强骨干后，显式提供与观测到的失败相关联的联合证据，能否比“更多异常摘要”更有效地区分源头与受害者？相同联合证据下，视觉是否进一步改善排名和实体绑定？

MRR 仍为首要指标。真实性、自洽性、可读性、成本各有价值，但均不能替代诊断效果。

### 2.2 成功与失败已经形成哪些规律

**规律 A：覆盖应区分“实体出现”与“机制存在”。**

RQ3.1 的 X 显著削弱根因 Metrics，尤其 node；RQ3.2 恢复部分资源证据，仍没有全面恢复诊断。RQ3.4 原骨干无根因直接 M/R/L、追加后有的 cases，Qwen 11 例和 Gemma 12 例的完整方法均未命中。不能把任意根因实体指标都叫“补全根因信号”。

**规律 B：最显著、最早、可计算，不等于最有区分力。**

RQ3.3 的 480 个见证包中，454 个 `comparison_rank=1.0`，所谓区分度几乎退化。RQ3.4 的 1,850 条 K 关系主要是数值大小、实体类型、时间先后；它们可以正确，却不一定区分为什么是 A 而不是 B。负面案例中，局部 page fault/onset 提示会压过原本已保留的操作延迟。

**规律 C：宿主与实例证据具有双向风险。**

新增 node I/O 可修复漏掉宿主故障的案例，也可把真正的 pod 故障错误上移到 node。应研究“哪些同类实例受到怎样的影响”，而非固定提高 node 排名。RQ3.4 Qwen 的单一 node/pod 子组，SIRCL_IDS 分别为 0.4510/0.5333，完整方法为 0.2059/0.2500；子组很小，只能用于形成待检验假设。

**规律 D：视觉可能主要帮助排序，而不是提名更多实体。**

RQ3.4 相同证据下 G 图像相对 G 文本，Qwen 修复 21、破坏 6 个 Top-1；13 个修复原来已在前五，但 AC@5 反而略低。这比“图像带来更多信息”更接近已有证据：关系表示可能改变竞争候选之间的排序。

**规律 E：格式可靠性与诊断可靠性必须分开。**

SIRCL 的合法 ID 适配将 Qwen 候选契约失败从 11/58 降到 1/58，是真实工程收益。K 减少一些 reason 冲突，却没有稳定提高 MRR。核验告警也可能伴随正确答案，不能用告警自动删除候选或把约束满足当成根因证明。

**规律 F：模型行为和输入信息不是同一个瓶颈。**

Gemma 的 P/H/K 八组合在 49/60 cases 输出相同候选序列，输入却已改变；check 完整方法 118/120 只给一个候选。它不证明模型没读证据，也不能通过强迫凑满五个候选来“修高”MRR。需分别报告 Top-1、提名覆盖与实际候选长度。

## 4. 方法候选：Outcome-Linked Evidence，简称 OLE

这里的 outcome 指**公开观测到的请求失败、延迟或实例可用性状态**，不是 gold root cause、模型答案或最终实验分数。

```text
canonical per-case public data
  ├─ 原 TPV：完整事实、顺序、候选与原 G 图
  └─ 一次索引：请求关联 / 可比实例 / 公开相对窗口
           ↓
     两类有实际分母的联合统计，最多四个包
           ↓
     边际 / 联合计数 / 联合计数＋条件比例 对照
           ↓
     TPV＋有界追加 → 冻结 Solver 一次调用
           ↓
     原 Top-5 JSON 与原 scorer；离线事实核验
```

### 4.1 改变的对象是统计单元，而不是再换 salience 排序

之前经常问：“组件 A 的 p95 是否比 B 大？”

这次问：“在相同业务入口与时间范围内，受影响请求和未受影响请求中，A 的局部现象分别出现多少次？这些现象与 B 是否在同一次执行中发生？”

这是从边际统计转向联合统计。并非声称有关联就有因果，也不将它解释为根因概率。

### 4.2 第一类：请求—局部现象联合包

每个包对应一个入口/operation 分层、相对时间范围和候选实体的可观察现象 X。

| | 观测到目标现象 X | 在可观察范围内未观测到 X |
|---|---:|---:|
| 受影响请求 Y=1 | a | b |
| 参考请求 Y=0 | c | d |

必须公开四个计数、观察对象和分母。Y 优先使用含义明确的入口请求错误状态；仅在状态字段不可用时，才采用相同入口的参考窗口延迟阈值。错误与慢请求是不同类型，不因某组样本少就在两种定义之间挑更有利的一个。

第一版具体规则：

- 使用完整且可验证的 request/trace ID、parent 关联；操作名、类型、时间及单位来自 public 数据。
- 延迟阈值用父版公开参考窗口同入口的 p95；至少 20 个合格参考请求。参考窗口不被称为保证健康。
- 受影响与参考组各至少 5 个可观察请求，才生成条件比例包；这个下限是可执行性规则，不是显著性证明。
- X 可是该实体请求内错误、相同 operation 的局部持续时间异常、明确观测到的重试/状态事件。不能让 X 与 Y 是同一字段的改名；逻辑上由 Y 直接推出的事件也不能作为独立区分证据。
- 只有 trace 采集满足相应完整性条件，才能把“没有记录”记成未出现；否则从这个字段的分母中排除，并保留各字段实际分母。
- 日志仅在有真实关联键时绑定到请求。不拼接大量原始日志；使用模板与必要诊断数字的有界统计。
- 同时保留变化方向。负相关也可以是排除某种解释的线索，不能把它改成“该组件健康”。

模型收到的摘要示例只用于解释形式，不是实验数据：同入口 20 个受影响请求中 X 出现 15 次，40 个参考请求中出现 2 次；关联属于该入口与观察窗口，不扩写成系统全局因果结论。

### 4.3 第二类：部署范围—实例状态联合包

Trace 稀疏时，不强制使用第一类。第二类只在公开部署关系和可比较实例均有支持时提供：

- 固定同服务/同角色、同时间窗口，比较焦点宿主上的实例与其他宿主上的实例；不能将不同业务服务直接当健康对照。
- 展示每组**实际观察到的实例数、受影响实例数、状态/资源条件及测量范围**。宿主只承载一个实例、没有跨宿主 peer 或状态不可判断时，不生成群体结论。
- 一项群体对照至少两台宿主、每组两个可观察可比实例；不足时仍保留 TPV 的单实例/node 证据，不能宣布整个 case 不可诊断。
- 若统计单元是 instance×window，应列出实例数与窗口数；不能把许多相邻 bins 当独立病例增加证据强度。
- request 级、instance 级统计不得混用分母。readiness、restart 与 request error 各有明确语义，不用一个模糊“异常”数替代。

这不是对 H 再命名。RQ3.4 H 主要追加宿主/peer 数值；此处要求观察单元、失败判据、可比组和联合分母实际成立，否则回退原 TPV。

### 4.4 选择、容量与退化行为

1. 两类候选均从完整 per-case 数据构造，不只读取旧 top-k 面板。
2. 第一版仅这两类，不同时添加八种新工具，也不加入学习型 ranking。
3. 包内以公开条件比例差和支持量排序，例如 `abs(a/(a+b) − c/(c+d)) × min(1, min(a+b,c+d)/20)`；保留原计数。该值不是根因概率，也不展示成根因推荐分。
4. 两类统计单元不跨单位直接比数值。各自按原始差异和支持量排序，合格时交替取包，最多四包；同实体最多两包，同一现象的重复模板只取一个。稳定 hash 只打破并列。
5. **先预留并放入联合包，再处理可选说明。** 追加上限 2,048 tokens，分别满足两模型 tokenizer 和完整上下文限制；共同可见事实一致。不能像旧 COHORT 一样把核心干预塞进最后剩余的 512 tokens。
6. 若一个完整包超限，按登记顺序改用下一个合格包；不裁掉分母、负对照或关键字段。最多四包是上限，不强行凑满。
7. 没有合格包则完整复用 TPV 输入，标为 no-op，主分析保留该 case。不得根据 gold 或诊断失败补跑另一个方法。
8. J_MARG、J_JOINT、J_COND 使用同一批预先选定的包；三者共用能完整装下最丰富版本的集合。不能让某个条件因文本短而多选额外实体。

此选择机制依然是待检验启发式。比旧 comparison_rank 多了实质统计分母，不意味着已解决混杂。不同路由、负载和采样率都可能导致关联；入口分层、参考条件和来源审计是必要限制。

### 4.5 暂时不做的内容

不把最早 onset 当必然故障源；不从相关图恢复真实故障因果 DAG；不使用 root label 挑关键路径；不把汇总 p95 相减当逐 span exclusive duration。CRISP 式关键路径只作为来源能力审计项，缺依赖/时钟条件时不进入第一版。

不向 Solver 加入 CPU 的“最可能根因”结论，不缩小完整候选列表，不恢复无限淘汰赛，不增加自动纠错回合，不强制五个输出。SAT/SMT 只核查明确定义的 ID、类型、数值和关系命题，不生成 gold 的替代品。

## 5. 实验 0：零模型调用的可执行性与失败模式分析

### 5.1 先确认哪里真正值得调用 GPU

复用现有 source index、prepared public facts 和会话；缺少的请求关联再从 per-case 读取，不重新处理 full raw data。

对旧 screen60 做一次表格审计，每数据集分别列出：

- 请求关联、入口状态、参考样本、时间/单位、部署 peer 的来源可用率。
- 合格包数、实际入选包数、真实进入输入的包数。
- 四格计数是否存在，而不是只有“支持/置信度”一个评分。
- 请求 ID 完整性、不可比较组、空分母、跨来源不可绑定的排除原因。
- 原 TPV、MORE、SIRCL、J 三条件的完整请求身份和实际 token；no-op 单列。

**来源可用率、处理覆盖率和诊断收益是三个不同量。** 合格 cases 的 RR 可以作 secondary subgroup，但不得只报告它们，把回退 TPV 的困难 cases 隐藏。

首轮手工核查 12 个 cases（三主数据集各四），按“有请求联合包 / 只有范围包 / 两者都有 / 两者都无”尽量覆盖；不足按事实报告，不挑答对样本。检查原输入与真实图文，不把 manifest 有字段当作模型看到了。

### 5.2 用旧结果区分三种错误

不新增推理，建立逐 case 证据表：

1. **提名错误：**根因从未进入该条件前五；记录是否有实际机制观测。
2. **排序错误：**根因在前五但非第一；查看第一名与根因的观测是否存在可比较范围。
3. **解释错误：**命中与否分别统计错误实体绑定、错误单位、局部关系被扩写成全局关系。

SIRCL-only repair、TPV-only repair、二者均失败三组均检查，不能只找支持新方法的案例。以数据集、粒度、Trace 稀疏度和机制类型分层；定性归因与计算所得标签分开保存。

这一步同时复用 RQ3.1 的零调用 `ANOMALY_COUNT`/BARO 排名作为参照：ANOMALY_COUNT 当时 AC@5=0.5917，不表示它已超过 TPV 的 Top-1，更不自动支持“让模型从 CPU 前五中选”。

## 6. 实验 A：拆开 SIRCL 的证据效应与指令效应

拟名：`exp_evidence_instruction_cross`。

### 6.1 为什么必须先做

源码已经明确两类差异：RQ3.4 `compile_integrated_unit` 为 SIRCL 选择 `sircl_system`，其他条件使用 `RCA_SYSTEM_ROLE`；`contract_parts` 又在原 SIRCL parts 上做合法 ID 适配。因此现有 SIRCL-vs-TPV 不是单纯选择器比较。

不应据此宣布“prompt 肯定是原因”；这是一个尚未干净拆开的混杂，需要实验。

### 6.2 六个条件

共同部分：候选完整、类型说明、相对时钟、Top-5 JSON、解析与 scorer 相同。四个交叉条件都使用一份无损的 typed text 接口；图像暂不参与。

| Arm | 事实来源 | 诊断指令 | 目的 |
|---|---|---|---|
| `E_P_D_P` | P0 选中事实 | 父版 RCA 方法 | 共同接口基线 |
| `E_P_D_S` | 同一 P0 事实 | SIRCL 诊断方法 | 固定证据，测指令 |
| `E_S_D_P` | SIRCL 选中事实 | 父版 RCA 方法 | 固定指令，测证据 |
| `E_S_D_S` | 同一 SIRCL 事实 | SIRCL 诊断方法 | 交互 |
| `T_NATIVE` | 原 T | 原父版完整请求 | 共同接口校准桥梁 |
| `SIRCL_IDS_NATIVE` | 原适配 SIRCL | RQ3.4 已修复的 ID 契约 | 原生基线校准桥梁 |

这里只移植诊断规则，不重复候选段、不改变输出格式、不把另一条 arm 的数值说明或私有时间移入 guide。每个方法句子必须和 evidence/schema/answer 句子有明确边界；不能靠粗 regex 把混杂文本随意剪开。

P0 与 SIRCL 证据本来不同，不要求二者等信息；固定 E 的两个 D 必须逐事实一致。每份 common serializer 与自身 native 事实做来源对应，不额外补齐另一套工具才有的统计。

先做 screen60，再冻结在 check120 重复六条件。分别计算证据效应、指令效应和交互；若 common-interface 校准本身明显改变效果，单列说明，不能把变化全归给算法。

**与实验 B 独立：**本轮 B 不因 A 的临时高分替换 guide。若 A 找到有复核支持的改进，后续组合需要单独登记，不能事后把它混入 J 的收益。

## 7. 实验 B：联合观测是否比边际摘要和普通加量更有效

拟名：`exp_outcome_linked_evidence`。全部使用原 TPV 的任务与诊断指南，M/R/L 仍为文本，G 仍为原图；只增加有界文本区。

| Arm | 变化 | 回答的问题 |
|---|---|---|
| `TPV` | 不追加 | 原强基线 |
| `MORE` | 原 `P0_MORE_TRUE`，同一 2,048-token 追加上限 | 是否只是放得更多 |
| `W_NO_K` | RQ3.4 的 `P1H1K0_G` | 是否超过当前局部最好的旧见证方法 |
| `J_MARG` | 同一选中包的边际计数，移除 X/Y 联合交叉格 | 是否需要联合信息 |
| `J_JOINT` | 同一包的 a/b/c/d、分母和关联范围 | 联合计数本身有何价值 |
| `J_COND` | J_JOINT 加可复算条件比例及差值 | 帮助计算是否有额外作用 |

`J_COND` 是预先指定的主候选，不按 case 选最好条件。J_JOINT 与 J_COND 原始观测相同；J_MARG 有意移除联合关联，因此是信息消融，不叫等信息对照。比例必须由原计数复算，不加“因此 A 是根因”的自然语言建议。

MORE、W、J 的上限相同不保证实际 token 数相同。报告实际 input/output、包数与根因机制覆盖，不将短很多的 J 自动称为严格 matched-token 效果。若要匹配 token，后续只能另登记容量对照，不能塞无意义 padding。

依次运行同一 screen60、check120，两模型都保留。只在 screen 检查实现与决定是否值得推进，不能在 check 看完后换主方法或改分群。RE2 不在这轮机制开发中，不据此宣称五数据集有效。

## 8. 实验 C：联合信息的视觉价值，不再默认“全图更好”

拟名：`exp_joint_representation`。只有 B 的数据覆盖和诊断结果值得继续时才投入。

固定 J_COND 的全部事实、计算和分组，比较 G 与联合表 J 的两因素承载：

| 新 Arm | G | J | M/R/L |
|---|---|---|---|
| `G_TEXT_J_TEXT` | 完整关系文本 | 局部并列计数表 | 原文本 |
| `G_IMAGE_CAL_J_TEXT` | 新 compositor 中的 G 图 | 同一计数表文本 | 原文本 |
| `G_TEXT_J_IMAGE` | 完整关系文本 | 真实比例/计数矩阵图 | 原文本 |
| `G_IMAGE_J_IMAGE` | 图 | 同一矩阵图；与 G 合在一张图 | 原文本 |

主视觉机制条件预指定为 `G_IMAGE_J_IMAGE`，不是看到结果后挑一种图；部署候选仍包括 B 的原 G＋J 文本。Text 必须获得同样的分组、数值、实体类型、单位和比较范围。

图形对象：行是明确的实体/现象，列是同一范围内的受影响/参考组；格内显示计数和分母，颜色只编码公开比例，不编码 root label、选择器名或“冠军”。G 中调用与部署边类型明确，不把关联画成故障传播因果箭头。原始数值可直接读取，不只有颜色深浅。

新 composite image 的 G 位置、字体及坐标在两个 G-image 条件间固定。J 图区域预留固定位置，J 文本条件对应区域留白，不能顺带放大 G。图像 raster、processor recipe 均固定；记录真实 image tokens。

**必须单列校准：**`G_IMAGE_CAL_J_TEXT` 相对 B 的原图 J_COND。重新排版到 composite canvas、图像尺寸改变都可能有影响，不能跳过这个桥梁后声称只改变 J 的表示。

本实验新增四条件×180 cases×两模型。它回答视觉的条件贡献；若全文本最好，就如实保留该结果，不把验证工具的可靠性包装为视觉胜利。

## 9. 实验 D：复核、机制与最终范围

拟名：`exp_locked_outcome_linked_rca`。

### 9.1 小型机制复核

从既有 screen/check 的并集中按 seed 42 hash 选三主数据集各 20 例，共 60；不按有无提升选择。固定 `G_IMAGE_J_IMAGE`，新增四条件：

1. 原输入独立 repeat-1；
2. 原输入独立 repeat-2；
3. 一致重匿名化（数据、图、候选及 evaluator 映射同步变换）；
4. 保留联合计数、移除条件比例/差值标注，测试视觉中的计算外显作用。

重复调用不用请求缓存冒充独立采样，不挑最好的答案。第四项是表示/派生计算信息的受控删减，不是根因机制消融。暂不追加需要私有标签挑“最有用包”的大矩阵，避免把主要预算消耗在归因而非提升。

### 9.2 固定六方法与扩量

若前面得到有价值、可复核的结果，再冻结以下六条件：

1. TPV；
2. MORE；
3. SIRCL_IDS_NATIVE；
4. J_COND（原 G 图＋联合文本）；
5. G_TEXT_J_TEXT（强全文本）；
6. G_IMAGE_J_IMAGE（预指定联合视觉）。

先补齐 RQ480 中未完成的 300 cases，包括 RE2 两组；已完成的 180 cases 只有完整请求、模型与评分契约兼容才复用。全部五数据集均报告，主三数据集和 AIOPS 分别及合并必须单列。

再对既有 test360 做锁定回归。这批数据已被多轮研究使用，不能称为 untouched test。它可以检验固定版本在另一组事件上的表现，但不抹掉研发暴露。

最后审计 unused 中真正未用于任何训练、验证、人工难例探索或方法选择的事件，目标主三数据集各最多 30，最多 90。排除事件别名、来源窗口重叠的传递组；不足按实际数量，不拆组凑数。若无法获得足够新事件，报告这一限制，不能仅靠旧 test 达到阈值就声称独立泛化成立。

## 10. 样本、判断规则与统计

### 10.1 数据身份不变

沿用 RQ3.3/3.4 已冻结的 screen60 与 check120，不再为了新方法重抽“容易见效”的集合。它们均是 repeated-exposed development material。

新版本开始前检查两集合之间的事件别名与窗口组关系。若存在交叉，不删除历史结果，也不继续称独立事件复核；按 group 重新冻结本轮分配并重算预算。后文预算假设该检查允许沿用原 60/120。

模型输入不包含 dataset、raw case 路径、gold root、故障类型或真实注入时间。来源能力决定是否有联合包，不允许用数据集名称路由。

### 10.2 手工研究决策，不增加后台自动 gate

以下用于未来阶段完成后的人工研究判断，不改现有运行器，不新建重型校验或自动 fail gate。

- 若大量“合格包”没有实际落到 prompt，先修编译/预算；不跑完矩阵再发现空干预。
- 若 J 只在单一数据集实际生效，结论限定到该观察条件；不能直接扩张成通用主方法。
- screen 只用于发现实现问题和低价值方向。一次版本至多一次有界修订；修订另存版本与调用，不覆盖旧负结果。
- 进入大规模扩量前，check 上 J_COND 相对 TPV 和 MORE 均须显示值得复核的收益：Qwen 主三数据集 macro ΔMRR 至少 +0.03，且不是单一数据集贡献所有增益；对下降达到 0.03 的主数据集必须解释并暂缓扩量。Gemma 原样报告，不将其下降藏进两模型平均。
- 这个 +0.03 是预算决策阈值，不是论文显著性标准。差距边界结合逐 case、重复性与失败分布作书面判断，不能为差 0.0005 无原则补样或偷偷改门槛。
- 若只有 A 的指令交叉有效，停止扩张 J，转向该明确发现；需新的有限组合登记，不默认把两条路线叠加。若都无效，停止大规模新调用，先解决观测能力/诊断任务定义，不默认 RL 或第二次 LLM 调用。

### 10.3 指标和假设族

Primary：MRR。Secondary：AC@1/3/5、AVG@3/5、repair/break、前五内升第一、前五外新增提名、实际输出长度、unknown-ID/解析失败。

按 dataset、service/node/pod/mixed、fault type、请求/范围包可用性、实际干预与 no-op 分层。根因关联与 fault type 仅用于 evaluator-private 离线分析；这些 subgroup 不变成部署路由。

统计单位 case；配对 Pratt-Wilcoxon、paired Cohen's dz、Holm，不报告 CI。原检验家族不因新计划重新拆分。新家族拟登记为：

- **A family：**证据主效应、指令主效应、交互，跨两模型共六个检验；native 校准另作明确的 secondary family。
- **B primary family：**J_COND 对 TPV、MORE、W_NO_K，跨两模型六个检验；J_JOINT−J_MARG、J_COND−J_JOINT 为单独机制 family。
- **C family：**G/J 承载主效应与交互，跨两模型六个检验；原图→新 compositor 校准另列。
- **最终效果 family：**固定部署方法 J_COND 对 TPV、MORE、SIRCL_IDS，跨两模型六个检验；视觉方法对强全文本的比较单独预注册，不事后挑胜者。

等数据集 macro 是主汇总，配对检验以对应共同 case 的差值进行，同时提供各数据集和 pooled。事件重叠补充 group-level 敏感性分析；复用结果不增加样本量。

模型格式失败保留注册分数；基础设施缺失不当模型质量零分，公布全部 fail 及共同配对分母，不套用自动可接受的 5% 门槛。不同 family 的共同 case 集合如有差异，表中明确 n。

“实质性准确率提升”仍采用 ΔMRR≥0.05 且 Holm-adjusted p<0.05。长期目标 test MRR≥0.65、两 AIOPS 分别≥0.60 不变，但本计划不保证达到；更不能在已暴露 test 上反复调到目标后宣称确认成功。

## 11. 解释分析：从“有关系”走向“有诊断作用”

每个 repair/break 保存可核查链：

```text
源请求/实例集合 → 分母与分组 → 四格计数 → 实际可见表/图
→ 模型提名与排序变化 → reason 的实体、数值、范围引用
```

核验 sidecar 对全部条件相同，不向某 arm 额外提供根因提示，不删答案。分别计数：确定矛盾、支持、证据不足、不可解析；“无法核验”不等于 hallucination。

定性样本预先按组 hash 选取，至少覆盖 TPV-only、J-only、两者均对、均错和排名修复。公开 reason 只作为可观察解释，不能恢复隐藏思维链。尤其检查：局部条件是否被说成全局、观测关联是否被说成因果、宿主/实例归属是否倒置。

信息论表述也要落地：J_MARG 与 J_JOINT 的区别是是否提供联合结构；J_JOINT 与 J_COND 是是否显式计算派生量。不能仅凭 MRR 差估计互信息，更不能将与公开失败 Y 的关联写成与真实根因标签的互信息。

## 12. 调用量、速度和执行边界

### 12.1 条件式预算，不一次提交全部队列

| 工作 | 最坏新增调用估算 |
|---|---:|
| A＋B screen：12×60×2 | 1,440 |
| A＋B check：12×120×2 | 2,880 |
| C 四新增表示：4×180×2 | 1,440 |
| D 四机制条件：4×60×2 | 480 |
| 六方法补齐其余 RQ480：6×300×2 | 3,600 |
| 六方法旧 test360 回归 | 4,320 |
| 六方法最多 90 个新事件 | 1,080 |
| A/B/C/D 各一个逻辑 smoke，最多 18 calls | 72 |
| **全部条件路线合计** | **15,312** |

建议最先仅实施零调用审计、A/B screen 及其两个 smoke，最多 **1,476 calls**；不是承诺现在启动。兼容原请求可减少实际调用，尤其强基线和 no-op，但不能将节省额自动变成更多探索。

补齐 RQ480 的预算依赖六方法在前 180 cases 已有兼容记录；若改变方法、prompt 或 renderer，不再按“只补 300”计算，应登记额外调用。CPU 分析、prep 与纯规则核验无模型调用，但有真实时间/硬件成本。

15,312 是规划工作量，不是新的人为硬上限，也不自动重置已有授权的大 RQ 调用余额。后续执行前核对所属预算和累计实际调用；40,000 的授权边界、修复与重试均计入。剩余额度不足时先缩减次要阶段，不能因新建 RQ3.5 名字自动重新获得 40,000。

### 12.2 不再重复慢 preparation

- 复用 canonical processed、现有 case 身份和可用索引；不是重复 raw→per-case。
- 一个 case 的请求/状态索引只构造一次，多个条件复用；不逐 arm 重新解析全部日志。
- 请求级计数使用分组/连接/流式汇总，不做全候选两两原始日志扫描。
- 后续采用已授权的八个独立核心 worker、有界内存和 cloudbed 分散调度；这里只写方案，不启动 worker。
- 单独记录冷启动与已有索引的增量 prep p50/p95/最慢案例，不把多 arm 合计耗时说成单次部署成本。
- CPU 审计先量化规模—耗时关系；出现跨数据集百倍异常就先定位，不把缓存命中差直接解释为算法复杂度。
- 保留原子 done/fail 与未完成续跑；不对所有已完成 case 重建请求或重新 hash 大文件，不自动重跑 fail。

当前新索引没有实测吞吐，因此不承诺总小时数。首轮 CPU 样本完成后分别估计 preparation、两模型推理与切换时间；GPU 估时以实际新请求数而非逻辑 arm 数为基数。

### 12.3 测试与冻结

未来实现时先静态检查，再小范围 CPU 回归，人工查看真实输入和图像，再按项目现行规则做 bounded smoke。每个逻辑 smoke aggregate≤18 calls、≤600 秒；既有用户批准的补验不是无限重试授权。smoke 正确性与 RCA 命中率分开。

正式阶段保持当前实际生效、已资格确认的本项目推理配置、输出适配器与 scorer；不从同名 sibling 仓库复制另一套模型或运行契约。无新增 attention，无训练、API 费用任务或多 Agent。

## 13. 最终可以形成什么故事，以及何时该换方向

值得争取的故事不是“给 LLM 更多真事实”，而是：

> **异常摘要容易保留症状，却丢失“哪些观测属于同一次失败”的联合结构。CanvasRCA 在强诊断骨干上编译可追溯的结果关联证据，再用相同信息的文本与视觉控制，检验联合结构是否帮助根因排序，及视觉是否降低关联绑定错误。**

要成立必须同时看到：联合观测确实进入输入；相对 TPV/MORE 有稳定 MRR 改善；相同联合事实下视觉有可说明的条件收益；适用性和跨事件表现经锁定评估支持。不能用更多图、复杂求解器、较少解释冲突或一个局部最高分代替这些证据。
