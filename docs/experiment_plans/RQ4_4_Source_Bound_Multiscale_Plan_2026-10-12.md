## 2. 方法与三个必要条件

保留历史 U 原始完整 dashboard、候选、均匀规则及其精确保留 token 集合，不继承 RQ4.3 删选、紧凑重绘或双向处理。一次诊断输入原概览及一张完整卡片局部图集。图像全部通过 `src/renderer/`；完整保留实体、操作、单位、阶段、统计、图形与数值写法，不摘取数值，不用文字证据截图。

两图使用原面板标识。公共静态说明指出局部图重复同一观测，不代表新的独立证据，也不表示实体更可能为根因。诊断事实不得进入文本提示、文件名、元数据或工具响应。

令 F_i 为历史 T_FULL 输入，K_i 为 U 保留图像 token，S_i 为新公共说明、模板及图像边界开销：

`D_i = min(8192, 16384 - K_i, floor(0.8 * F_i) - K_i - S_i)`。

80% 是预先固定的工程预算，不按 MRR 调整。局部图宽 2048px，高度按 32px 网格及实际 processor 预算确定，不提高 processor 限制。整卡等比例放大，处理后诊断文字至少 18px、线条至少 1.5px；长名称、坐标、极值不得裁切。无法整包装入者仍留在原概览。选择仅使用公共来源、DOM 字号、几何及编码成本，不用异常大小、根因、历史回答或 QA 错误。优先覆盖不同实体和 M/R/L/G；同一覆盖轮按恢复不足字号的诊断字符数/新增图像 token 排序，来源 ID 打破并列。配额、排序、位置及跳过规则在 CPU 后首次模型调用前冻结。

| Arm | 输入 | 问题 |
|---|---|---|
| SOURCE_ZOOM（预选） | U＋可读性选择的完整高清卡片 | 定向增加细节是否改善排名 |
| REPEAT_VIEW | 同一概览、卡片集合、尺寸和位置；仅放大概览经 processor 后的像素 | 区分恢复细节与重复、定位、突出 |
| HASH_ZOOM | 相同高清标准、覆盖规则、说明、画布预算；固定哈希优先级 | 定向分配是否超过简单同预算补充 |

REPEAT 是明确的细节控制，非主要系统基线；比较包含新增细节和编码变化，不是内部模块纯因果效应。HASH 比较完整选择策略，不声称可见细节相同。历史 U、T_FULL、MARGINAL_FIVE 直接复用，不新跑 U；披露历史后端兼容限制。

## 4. 判定、资格与停止条件

主要比较 SOURCE−REPEAT、SOURCE−HASH：事件组 Pratt-zero Wilcoxon，双侧、两项同族 Holm；另报病例、12 位差值及配对 dz，不报告 CI。QA/顺序是探索测量，不把题目数当病例数。完整报告标准/宽容 MRR、AC@1/3/5、Precision、AVG、逐集和宏平均、修复/破坏、无效、未知和完整分母。

工程进展要求 SOURCE 标准 MRR 比历史 U ≥+.03，三个数据集 MRR、AC@5 不下降，逐集全部实际 input+output ≤历史 T_FULL 的 1.05。项目方向继续争取超过强文本、约 .505，之后再谈冻结验证；历史比较是开发参照。高清优于重复才支持新增细节；优于 HASH 才支持选择策略；整体进步可承认而收缩部件主张。

按顺序执行：

1. 静态和全部 220 例三臂 CPU：事实、来源、候选、预算、实际字号、多图映射；输入+8192≤40960；原概览及 token 集合完全不变。
2. 实际例图每臂每数据集一个，加最长名称、最密关系、最大卡片；核对重复控制几何、高清恢复和跨图对应。
3. 运行回归：双图 processor/MRoPE、逐图 gather、统一 scorer、原子提交、引用、暂停排空/恢复。本地 BF16 Qwen、vLLM、8 独立 CPU worker、GPU 并发 8、显存利用率 .8。
4. 共享 smoke：三个固定 eval 身份，18 调用/600秒含启动、保存和验证，覆盖三臂 RCA、QA、局部 QA、attention 开关。软件问题先修复；答案错误不用于改方法或重测。未完成资格不自动通过。
5. 资格通过后冻结运行，病例哈希和均衡臂顺序，不依据临时 MRR 改队列。

全部 220 例几何容量必须通过，不能删病例、缩字号或加文本证据。CPU 不能形成有效高清/重复差异则停止候选。成本记录编码前图像 token、送入 LM 的 token、输出、编译绘图、编码、prefill、生成和连续冷路径，不把低 token 当速度收益。

若完整结果既无工程排名进展，也无优于两控制的证据，结束局部高清路线，不扩为卡片数量/字号/布局搜索。
