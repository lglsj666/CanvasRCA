## 2. 范围与四个条件

从已有 RQ480 三主数据集各按固定 hash 取 40 例，共 120 例。
不根据历史正确率、根因、异常分数挑选。只用冻结 Qwen3.8-27B，一次诊断，最多一张图。

| 条件 | 实际输入 | 唯一主要动作 |
|---|---|---|
| TEXT_FLAT | 完整公共文本＋公开比较成员表 | 原证据顺序，成员表在后 |
| TEXT_JOINT | 相同文本行＋相同成员表 | 对应观测在成员表旁连续排列 |
| VIS_SEPARATE | TEXT_JOINT＋小型真实图表 | 同组图表分散在固定槽位 |
| VIS_JOINT | TEXT_JOINT＋相同真实图表 | 同组图表排在同一列 |

文本得到相同关系及比较分组，不能靠额外提示制造视觉优势。四条件不是四个选择器。

## 3. 如何形成局部比较

只在父版已经展示的 Metrics/Traces 中找至多两组，每组两条必要观测及至多
一条同实体辅助观测。原文本事实不删除，不重新访问原始日志大表。
依次考虑：

1. 同服务不同 pod、同指标同单位，且公开 service→pod 归属无歧义；
2. 直接 hosts 关系上的 node 与 pod 各自指标；
3. 同实体的一条指标与一条操作级 trace 摘要；
4. 直接 calls 两端的指标与操作级摘要。

优先级、稳定 hash 破同分、组间不重复卡片在运行前固定。第 3 类只叫
“同实体指标与操作观测”，不能把任意 JVM 指标冒称为负载，也不等于真实
exclusive latency 与等待时间分解。当前观测支持不到的诊断机制如实登记为未覆盖。
来源缺失不构造假 peer、假健康或假部署关系。没有合格组时四条件退回同一文本，
只调用一次并引用；报告 no-op 占比，不把它们删除后夸大有效范围。

## 4. 真正控制的视觉变量

复用 unified renderer 的已有组件及操作，全部保留历史入口与默认行为。
完整连续指标用 `metric.line`，带 null 的指标用既有 `metric.time_bars`
避免把缺失段画成连续走势；Trace 用 `trace.paired_bars`。同一卡片在两个
视觉条件中的组件、字体、图形、颜色、大小、标号完全一致，只移动位置。
画布 1800×1272、两列三行、字体16、边距28、间隔18，空槽保留。
不是对历史 full Dashboard、service topology、node→pod 或 service→pod 组件的修改。

时间轴更正：同一 case 的历史 Metrics 生产器使用共同 timestamp 向量建立
同一64箱；不是每条曲线按非缺失值起止时间伸缩。0–63 不是秒，但在核实
该来源后可以跨 Metrics 对齐。不能外推为 Metrics/Logs/Trace/onset 全部同轴。
每例仅核对公共来源与时间列，不读取注入时间，也不重算指标统计。

## 5. 假设与分析

Primary family：VIS_JOINT−TEXT_JOINT、VIS_JOINT−VIS_SEPARATE，Qwen-only 两项 Holm。
Secondary family：TEXT_JOINT−TEXT_FLAT、VIS_SEPARATE−TEXT_JOINT，两项 Holm。
MRR 为主，报告 AC@1/3/5、AVG@3/5、repair/break、前五进出、错误候选、输出失败、
输入/图像/输出 tokens 和延迟。配对 Pratt-Wilcoxon、paired Cohen's dz，不报告 CI。
三数据集分别、macro 和 pooled 分开；按事件组补充敏感性。小样本子组只做探索。

按组是否合格、比较种类、根因层次与 fault type 分层；标签只在离线评价使用。
定性分析覆盖修复、破坏和不变，核对 numerical/ownership/scope 引用，不把 reason
视为隐藏推理。视觉两条件输入 token 相同不等于推理成本一定相同，分别记录。

主要解释边界：这能识别“局部图形冗余＋组织”的效应，不能证明全面观测融合、
多轮因果推理、跨模型泛化或工程师效率。120 例均为暴露开发案例，不是独立验证。
若局部视觉仍输给同内容文本，报告负结果，不自动扩大或另挑赢家。

## 7. 执行、预算与停点

正式最多 480 个逻辑位置与 480 次实际发起；no-op 引用降低实际量，不挪用省下预算。
一个逻辑 smoke 取三主数据集各一例，最多12个计划请求，硬上限18次、600秒，
包含启动；计时到期保存 partial，不自动加测。smoke 与正式结果完全分目录。
CPU 检查预算30分钟，实际120例只访问小型公开缓存、时间列及渲染产物；
最多8独占物理核心 worker、按数据源交错；正式并发36，保持现有40960/8192配方。
不会重算 raw telemetry、训练、启动多 Agent、记录 attention 或切换 Gemma。

资格顺序：三重点静态检查 → CPU/渲染及真实 tokenizer 检查 → 查看实际图 →
GPU smoke → 阅读实际输入、原回答、conversation → 启动正式队列，确认实际提交后停止监控。

沿用客户端300秒连接／读取超时，触发时写 fail，继续、不自动重试；其他基础设施失败 fail-fast；
模型解析/非法候选失败保留模型结果；设计不可执行排除准确率分母。新调用完成
写盘后提交 done/fail；续跑先查小标记，不重建完成请求、不做大文件历史校验。
中断无标记可以续跑，但重发仍占实际调用上限，超预算需另行批准。
注意：该读取超时不是持续流式输出的请求总时长上限；总 smoke 仍由独立600秒
监督器限制。12次资格检查均完成，其中一条长回答403.3秒，未改变原客户端语义。

入口：`bash RQs/RQ3_9/scripts/local.sh <register|static|prepare|cpu|supervise|status|analyze>`。
smoke：`supervise --smoke`；正式：`supervise`。正式启动前要求人工图片与会话审查记录。
