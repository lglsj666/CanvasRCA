# RQ4.3 X_SRP 输入身份故障与恢复

2026-10-11，America/Toronto。范围：v17 正式队列的运行修复，不改变实验方法、冻结输入、评分或调用矩阵。

## 故障与诊断边界

20:01，CPU 预取 `INC-A195F9A69AFC__X_SRP__BASE` 时，`cold_materialize` 报告 `Cold computation differs from frozen request`。运行器排空在途请求后关闭自有模型，保留 1,444 个原子完成记录。该失败发生在模型调用前，没有新增计费尝试；历史 14 次基础设施失败及 14 次中断保持原记录。

X_SRP 的正式路径仍重新进行布局测量、packing、重画、token 支持提取与分组。失败时只记录总身份不一致，RAM 中的差异输入随后释放，不能事后确定是哪一个字段首先变化。对同一个病例分别使用普通目录和正式使用的 RAM 路径复现，两次均与冻结生成身份完全一致：PNG SHA256、提示、保留 token、分组、种子及算子一致。因此底层偶发原因尚未稳定复现，不能声称已证明是字体、并发或某个具体数值错误。

## 修复

X_SRP 改为直接读取已经通过完整 CPU 资格的冻结 PNG、提示、保留集合和分组，沿用其他恢复臂的准备方式。使用 `materialize_frozen_visual` 在提交前验证完整生成身份、通过状态的 renderer manifest，以及实际 processor 的全部计数字段和几何；任何变动仍拒绝。保留原公开事实身份核对，所有图像仍来自 unified renderer。没有禁用、放宽身份校验，也没有用重新生成的不同输入覆盖冻结输入。

冻结队列 SHA256 保持 `0ece585465d3b5185ca191f3cfc6d5cb25e65d652cfe7a39720537c1df182b41`，仍为 4,832 个位置、4,637 个独立请求。模型、解码、token 算子、attention、scorer、renderer 和调度器通过源快照比较确认未变。X_SRP 的计时改为 `cached_input_to_validation_seconds`；`continuous_cold_seconds` 为 null，离线编译绘图开销单列，不能将缓存路径称为完整冷时延。

## 受影响检查

- 静态检查通过，五模块共 5,491 个有效源代码行。
- X_SRP 全部 220 例的实际 CPU 准备、processor、冻结身份与完整请求字段一致性通过，包含登记的回退请求。
- 其余八个恢复臂每数据集一例，共 24 份请求，通过共享校验路径检查。
- 八个独立物理核 worker 完成上述 244 项检查，零错误、零新模型调用。
- 13 项离线回归通过：输入/像素/分组篡改拒绝、同 token 数下几何变化拒绝、原子提交中断恢复、重复启动、结果引用与独立调用、暂停、CPU 核隔离和直接可读结果保留。
- 未重跑不受影响的全量 CPU 和 GPU smoke。模型输入及推理路径未变，继承原资格；本次不是新的 GPU 资格测量。

原凭据、故障记录、修复源及检查证据保存在 [repair_xsrp_v18](../../RQs/RQ4_3/results/repair_xsrp_v18/)。当前运行修订为 `v17_xsrp_frozen_input_v18`，代码身份 `0b5c48b045d4d86315e6a08091c2a933af73363a26d77b3454a10a8669ac762a`。

## 恢复

按用户“排查错误，修复问题，然后继续跑”的指示，从 1,444 个完成位置恢复；不重答已有结果。启动 PID 421230，日志 `formal_v7/worker_1791765028914038378.log`。启动监控完成情况另记于修复目录的 `startup_monitor.json`。

恢复后监控 206.1 秒通过，完成数由 1,444 增至 1459；基础设施失败与中断计数均未增加。CPU 八 worker、GPU 八并发，实验继续后台运行。监控交接后不宣称后续全队列已完成。
