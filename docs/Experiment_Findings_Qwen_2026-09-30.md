# CanvasRCA：Qwen 正向、负向与未决发现清单

更新：2026-09-30。仅讨论 Qwen3.8-27B；依据当前 11 份 Qwen-only 报告及其重分析附件，不新增推理或改变历史结果。本版将实验代号改写为实际配置，保留原有 110 条发现、统计数值和证据等级。

## 阅读规则

- **显著**：通过对应 Qwen 比较集合的 Holm 校正；文中的 pH 均指校正后 p，不是原始 p。
- **线索**：正/负点估计、事后分层或案例支持，尚不能写成已确认的普遍效果。
- **观察**：计数、输入组成、成本或实现审计事实，不自动带有因果含义。
- **未证实**：当前试验未建立预期收益，不等于证明不存在收益。
- 病例级、事件组级、pooled 和等权 macro 保持区分；不同阶段的 MRR 不能横向排冠军。
- 本清单按研究含义去重，完整保留正、负、混合和未决结论；不是把每个 arm×数据集×指标的表格单元重复列成一条发现。

范围为 RQ1.1、RQ2.1、Tournament、RQ3.1–RQ3.5、RQ3.6-A/B、RQ3.7-A/B，以及跨实验画像。**不纳入尚无完整分析报告的 RQ3.7-C、RQ3.8 临时结果，也不把仅注册、未运行的条件当结果。**

## 一、正向发现与值得保留的正向线索

### RQ1.1 / RQ2.1：选择性视觉与读取条件

- **P01【显著】关系图＋指标/调用链/日志文本优于全文本**：主数据集 300 例 MRR 0.3093→0.3819，Δ=+0.0727，主比较 pH=0.0276。[R1]
- **P02【显著】只将关系区画成图，优于四类证据全部画图**：同一主集合 ΔMRR=+0.1162，补充比较 pH≈0.0000116，支持选择性视觉化。[R1]
- **P03【显著】将关系及附带摘要由文本改为图像有正主效应**：十六种模态分配的析因平均 ΔMRR=+0.0561，pH≈0.0011；并非只检验调用边。[R1]
- **P04【观察】模型确实使用图像语义**：定向图像反事实可定向改变排名，空白化可损害诊断；这证明输入影响，不等于正确因果推理。[R1]
- **P05【观察】全视觉可以减少输入量**：相对文本平均输入约少 59.9%，但这是输入 token 收益，不是整体准确率或时延收益。[R1]
- **P06【显著】把画布宽、高均扩大至原来的 1.5 倍能改善当前视觉方案**：480 例 pooled ΔMRR=+0.0459，pH≈0.00684；收益较集中于 RE2-TT，不能据此称所有数据集都受益。[R1]
- **P07【线索】有向分层拓扑图值得保留**：保留环、跨层边和孤立节点的分层画法，使五数据集 macro MRR 0.3664→0.3943，但配对校正未显著。[R1]
- **P08【线索】按实体分组、按异常出现时间排列卡片有小幅正向信号**：两种布局的 pooled ΔMRR 分别约 +0.0182 / +0.0231，均未校正显著。[R1]
- **P09【线索】部分筛选替换在全文本中略有增益**：调用链按异常 span 的支持度/置信度调和得分排序、日志按模板频率排序、证据按相关性与去冗余折中选取，点估计均略高于原始固定筛选，尚不足以确认胜出。[R1]

### Tournament：信号互补与承载修复

- **P10【显著·探索】操作级调用链重排能修复难例**：淘汰赛第三轮采用异常 span 支持度/置信度筛选，相对前轮的 290 个共同剩余病例 ΔMRR=+0.1093，pH≈0.00000147。[R2]
- **P11【显著·探索】把已选指标由图像改为文本能修复大量难例**：淘汰赛第十→十一轮，调用链/日志/关系仍为图像；187 例 ΔMRR=+0.1753、新增 Top-1 43 例，pH≈0.0000273；同时改变了画布分配和 token。[R2]
- **P12【观察】不同诊断信号具有互补性**：稳健资源偏离、操作级 Trace、日志策略、波动与传播前沿各自修复过不同病例。[R2]
- **P13【案例】流量下降与本地执行耗时不变也有诊断价值**：淘汰赛第三十五轮的请求量下降、exclusive latency 相对稳定帮助定位根因，不必所有有效信号都表现为变慢。[R2]
- **P14【观察】现有信息中仍有较大可利用空间**：多轮 Top-1 联合覆盖 394/480，Top-5 覆盖 464/480；它们是探索覆盖，不是单方法性能。[R2]

### RQ3.1 / RQ3.2：新增线索与基础证据保留

- **P15【线索】对比包筛选能补到原始筛选遗漏的部分资源信号**：新增根因指标的 26 例，从“原始关系图＋其余文本”改为“对比包筛选＋并列表格文本”，MRR 0.3365→0.4949。[R3]
- **P16【线索】对比包筛选＋并列表格文本偏向改善部分网络故障**：test 的延迟 / 丢包 / 分区或带宽故障子组，相对原始全文本分别约 0.128→0.544、0.254→0.413、0.304→0.714，均为未校正显著的事后线索。[R11]
- **P17【显著】在覆盖/对比筛选中保留原始基础证据确有作用**：共同紧凑文本接口下，“基础保留＋覆盖＋对比”相对“取消基础保留”和“仅对齐统计的旧对比包筛选”，主数据集 ΔMRR 为 +0.0761 / +0.0869，pH≈0.00267 / 0.00672。[R4]
- **P18【显著】同一套基础保留/覆盖/对比证据中，指标留作文本优于全部画图**：调用链/日志/关系仍用图像，开发配对 ΔMRR=+0.0986；test 同方向约 +0.0918，分别 pH≈0.00000465 / 0.0000132。[R4]
- **P19【线索】基础保留＋覆盖＋对比筛选，配“指标文本、其余图像”，在内存故障中有增益**：55 例相对原始全文本的 MRR 0.3712→0.5212，Top-1 修复/破坏为 16/3。[R11]
- **P20【显著·机制限定】上述指标文本/其余图像输入中的部分根因观测确实有用**：删目标观测比删匹配非目标更差，主数据集 39 对 ΔMRR=−0.1513、pH≈0.0263；不能扩大为完整对比包均被正确利用。[R4]

### RQ3.3 / RQ3.4 / RQ3.5：见证、接口与局部范围

- **P21【线索】保留原证据、追加判别观测，比整体替换证据更有希望**：RQ3.3 复核阶段，“追加观测文本＋关系图”的主数据集 macro 为 0.4398，未追加的“关系图＋其余文本”为 0.4000，尚未校正显著。[R5]
- **P22【线索】针对原缺失观测追加证据更有价值**：保留基础上下文的追加方法新增根因直接观测的 11 例，MRR 0.0455→0.2455。[R5]
- **P23【观察】追加相同判别观测时，关系图的收益包含候选重排**：相对“关系也用文本”，Top-1 修复/破坏 23/11，其中 15 个修复的根因原已在前五；追加观测本身仍是文本。[R5]
- **P24【观察】要求返回合法匿名候选 ID，能减少输出失败**：RQ3.4 的 58 例中，SIRCL 文本方案从原生输出约定改为本项目候选 ID 约定，失败 11→1；MRR 0.3218→0.3750，但整体增益未校正显著。[R6]
- **P25【审计能力】自动核验可发现显式一致性问题**：可检查 ID、绑定、已显示数值和已观测关系；其能力不等于验证根因真伪。[R6]
- **P26【线索】优先级筛选＋宿主/同类支持，不加核验说明的版本更值得研究**：RQ3.4 复核中该“关系图、其余及追加观测为文本”配置 macro=0.4468，高于再加核验关系/数值说明的 0.4219，但不是已确认的消融增益。[R6]
- **P27【案例】restart 与同宿主实例对照可以区分局部故障**：已有病例显示这些观测能帮助判断异常只在单实例还是涉及更大范围。[R6]
- **P28【线索】SIRCL 工具证据搭配本项目诊断指令，曾有较大筛选阶段增益**：RQ3.5 共同全文本接口下，SIRCL 工具证据 / 项目原始证据的 macro 为 0.4006 / 0.3191，尚待后续复核。[R7]
- **P29【线索】追加优先级/宿主观测的简单方案，优于追加条件比例证据的方向值得保留**：RQ3.5 筛选阶段，前者（不加核验说明、关系用图）macro 0.4026，高于不追加观测的 0.3411 和追加联合计数/条件比例的 0.3387。[R7]

## 二、负向发现与需要修复的退化模式

### 表示与选择的损害

- **N01【显著】指标、调用链、日志改为图像，平均有读取代价**：RQ1.1 析因效应依次为 −0.0503 / −0.0325 / −0.0166，三者均通过各自主效应校正。[R1]
- **N02【显著】指标图与关系图的收益不能简单相加**：RQ1.1 同时把指标区和关系区视觉化的交互约 −0.0482、pH≈0.0220，存在相互抵消。[R1]
- **N03【观察】把原文直接截图没有改善当前 RCA**：RQ1.1 主集合，原文截图 MRR=0.2228、原文文本=0.3093；不能由此直接断言所有真实图表都优于截图。[R1]
- **N04【显著】把真实图表换成图像中的表格会退化**：RQ2.1 表格画法相对原图表画法，pooled ΔMRR≈−0.0747、pH≈0.00133。[R1]
- **N05【显著·历史效用口径】全视觉在八种选择策略下均弱于文本**：RQ2.1 480-case 对照均显著；不可执行设计零分和可执行病例分析必须区分。[R1]
- **N06【显著】同预算随机选择严重破坏诊断信息**：RQ2.1 相对原始固定筛选，全文本/全视觉的 pooled ΔMRR≈−0.1962 / −0.2160。[R1]
- **N07【显著】仅换成原生三西格玛指标排序并不更好**：调用链/日志/关系保持原筛选，全文本/全视觉相对原始筛选分别约 −0.0519 / −0.0577，pH≈0.0025 / 0.0416。[R1]
- **N08【显著·历史效用口径】追求覆盖、多样性或模板频率会损害某些视觉输入**：优先新增实体/语义、按相关性与去冗余折中、按日志模板频率筛选的全视觉版本，相对原始固定筛选均退化；不能以覆盖数代替诊断质量。[R1]
- **N09【观察】跨更多证据区域的联合读取更困难**：QA V2 从读取一个区域到四个区域，整题全对率的全视觉版本从 45.73% 降至 8.07%，同事实文本从 67.24% 降至 21.75%；这里区分的是所需区域数，不是推理深度。[R1]
- **N10【观察】输入变短不等于输出变短**：RQ1.1 全视觉输入减少约 59.9%，输出均值反而增加约 8.4%。[R1]

### 对比包筛选、基础保留/覆盖/对比筛选的资源与机制损失

- **N11【显著】对比包筛选后的两种视觉部署明显弱于强基线**：test360 中，“全部画图”/“仅指标留作文本”相对原始“关系图＋其余文本”ΔMRR≈−0.1082 / −0.1163，也显著弱于 SIRCL 工具文本方案。[R3]
- **N12【观察】对比包筛选的问题在渲染前已经出现**：并列表格文本 MRR=0.3095，未超过原始“关系图＋其余文本”的 0.3843；不能把失败全部归咎于画图。[R3]
- **N13【观察】对比包筛选用调用链覆盖换掉了大量资源证据**：相对原始筛选，含根因指标的病例 207→67、含根因关联调用链的病例 148→231；node 根因指标覆盖 28/51→2/51。[R3]
- **N14【线索】对比包筛选删除旧信号的损失超过新增信号收益**：原筛选保留、对比包筛选丢掉根因指标的 166 例，从“原始关系图＋其余文本”改为“对比包并列表格文本”，MRR 0.4874→0.2502。[R3]
- **N15【显著】对比包筛选对 node 根因损害尤其严重**：test 中 51 例，从原始全文本改为对比包并列表格文本，MRR 0.3464→0.0196，分层校正 pH≈0.000085。[R3][R11]
- **N16【线索】对比包筛选牺牲了内存/磁盘故障能力**：test 中，原始全文本→对比包并列表格文本，内存 MRR 0.3969→0.2322、磁盘 0.3553→0.1368，不能称所有故障都同向变化。[R11]
- **N17【观察】同文本截图仍有读取损失**：RQ3.1 100-case 机制子集的表格文本→截图 MRR 0.4958→0.3653。[R3]
- **N18【观察】过度压缩证据会损害文本诊断**：RQ3.1 的 50% 预算明显退化，75% 变化较小；压缩存在下限。[R3]
- **N19【显著】只把公共统计窗口对齐，不能挽救旧对比包筛选**：RQ3.2 共同紧凑文本接口下，对齐统计后的对比包筛选相对原始固定筛选，主集合 ΔMRR≈−0.0678，pH≈0.0396。[R4]
- **N20【观察】基础保留＋覆盖＋对比筛选恢复实体覆盖，但未恢复完整诊断能力**：test 中该方法/原始筛选的直接根因指标覆盖为 159/162，node 覆盖恢复到 33/51，排名仍未稳定恢复。[R4]
- **N21【显著】基础保留/覆盖/对比证据全部画图的退化延续到 test**：相对同选择证据的强文本，开发/test 配对 ΔMRR≈−0.0776 / −0.0757；test 也显著弱于原始全文本、原始“关系图＋其余文本”和 SIRCL 工具文本。[R4]
- **N22【线索】基础保留＋覆盖＋对比筛选仍未解决修复/破坏失衡**：相对原方案，丢旧信号的 24 例 MRR 0.3556→0.2361；新增信号的 21 例仅 0.2635→0.3008。[R4]

### 排序、故障范围与新增上下文的代价

- **N23【观察】不断增加选择器的边际回报很低**：Tournament 后十轮 904 次逻辑尝试只新增 8 个 Top-1 病例。[R2]
- **N24【观察】宿主资源和可用性故障仍是薄弱点**：Tournament 的 AIOPS-2022 node-memory 仅 1/5、AIOPS-2025 pod-failure 5/13、node-CPU 2/6 曾被 Top-1 覆盖。[R2]
- **N25【观察】困难不只是根因未被提名**：Tournament 未 Top-1 的 86 例中，70 例曾进入前五；低 MRR 还包含竞争候选排序问题。[R2]
- **N26【案例】宿主证据能把 pod 故障错误上推到 node**：保留原上下文后追加观测、或补充宿主提示，在多阶段出现这种破坏；宿主异常不等于宿主是故障源。[R5][R8][R9]
- **N27【线索】换用 SIRCL 工具证据可以保留根因实体，却丢掉正确机制**：项目原证据已有根因指标的 59 例，在同项目指令下替换证据后，MRR 0.5944→0.4986；已有内存 working-set 峰值被 CPU 字段替换的案例。[R8]
- **N28【线索】换用 SIRCL 工具证据在内存故障中有较大下滑**：RQ3.6-A 固定项目指令和全文本接口的 15 例，MRR 0.4889→0.1500；幅度大不等于已通过分层多重比较检验。[R11]
- **N29【线索】SIRCL 工具证据替换的总体均值掩盖跨场景取舍**：相对项目原证据，两 AIOPS 合并点估计改善，AegisLab 却 0.6539→0.4639；前五新增/丢失为 10/20。[R8]
- **N30【观察】增加宿主背景可能扩大备选，却损害首位**：RQ3.6-B 全文本对照中，在同一批追加锚点上再补宿主观测，相对仅追加锚点，AC@5 上升而 AC@1 轻微下降。[R9]
- **N31【线索】异常摘要排名/出现时间可能造成锚定误导**：从关系区删除异常出现时间，在摘要首位与根因对齐组约 −0.1629、其余组约 +0.0677；这是依赖真实标签的事后分层。[R9]
- **N32【线索】数值面板邻近实体＋归属连线仍会牺牲 node**：相对同事实实体分组强文本，node MRR 0.3467→0.2933，pod/service 的改善不能掩盖它。[R10]

### 可靠性、稳健性与成本

- **N33【观察】自报信心不能替代可靠性检查**：Tournament 未 Top-1 的完整回答中约 89.53% 仍报 high confidence。[R2]
- **N34【观察】排名正确不保证理由正确**：已有正确首位伴随理由矛盾、错误实体类型或疑似虚构调用边；数值面板邻近实体并加归属连线时，类型误称计数为 32，高于同事实实体分组强文本的 22。[R5][R6][R10]
- **N35【显著·探索】等值数字写法会改变诊断**：改成科学计数法造成的首位翻转超过原输入重复；同事实实体分组强文本 / 数值面板邻近实体并加归属连线，两者的配对翻转检验 pH≈0.00586 / 0.00977。[R10]
- **N36【线索】数值面板邻近实体＋归属连线尚未消除单位敏感性**：真正适用等价单位换算的 22 例，ΔMRR≈−0.1061，样本小、未校正显著。[R10]
- **N37【观察】数值面板邻近实体＋归属连线不是低输入成本方案**：保留原文本且重复编码数值，平均输入约 23,048 tokens，高于同事实实体分组强文本的 14,773 和原始“关系图＋其余文本”的 14,589。[R10]
- **N38【观察】增加 LLM 并不保证超过简单排名**：RQ3.1 不调用 LLM 的 CPU 异常计数排名 MRR=0.3483，高于对比包并列表格文本推理的 0.3095、低于原始“关系图＋其余文本”的 0.3843；这不是同输入的纯推理效应。[R3]

## 三、未证实、相反证据并存和暂不能回答的发现

- **U01【未证实】把同一批完整事实同时放进文本和 Dashboard，不能保证增益**：RQ1.1 的完整图文重复输入没有确证超过仅文本/仅真实图表，不能把冗余编码自动解释为有效融合。[R1]
- **U02【未证实】紧凑结构化文本不是自动更准确**：RQ1.1 同事实紧凑文本相对自然语言文本的小幅正点估计未显著；压缩与准确率是不同终点。[R1]
- **U03【未证实】真实图表并未普遍、显著优于原文截图**：RQ1.1 全视觉真实图表相对原文截图，点估计 +0.0430，但校正未显著；截图较差不能单独完成视觉创新论证。[R1]
- **U04【未证实】多数更换画法/布局的收益未建立**：热图、叠线、哑铃、矩阵、压缩留白、横竖排、拓扑居中等没有普遍确认的 MRR 改善。[R1]
- **U05【未证实】换用现成异常检测工具不天然优于原始筛选**：RQ2.1 的 BARO 稳健异常排名等没有显示统一优势；工具复杂度不等于诊断收益。[R1]
- **U06【未证实】对比组织和时间对齐并非已确认的通用解法**：RQ3.1 消融效果不一致；RQ3.2 部分动作未真正实现，不能据此全面否定这些机制。[R3][R4]
- **U07【未证实】更大预算没有形成稳定突破**：给“基础保留＋覆盖＋对比筛选”增加显示容量，未解决选择瓶颈；保留原上下文后的追加观测预算从 2,048→4,096 tokens，也未形成稳健改善。[R4][R5]
- **U08【未证实】给追加观测增加语义说明、显式计算的独立贡献仍不清楚**：分别补字段/观测解释和可执行派生计算，未形成清晰独立增益；实际输入相同的病例不能算有效消融。[R5]
- **U09【未证实】第二次调用尚未证明值得额外成本**：首次诊断 / 原输入独立重答 / 用原证据核验首答 / 用追加判别观测核验首答，MRR≈0.3500 / 0.3417 / 0.3417 / 0.3694；无显著收益，二次方案调用成本约翻倍。[R5]
- **U10【未证实】优先级筛选＋宿主/同类支持＋核验说明，未胜过强基线**：RQ3.4 复核中，该完整组合与“关系图＋其余文本”及“原筛选顺延补更多证据”的差异未显著；字面一致性与正确因果诊断不能互相替代。[R6]
- **U11【未证实】追加联合计数/条件比例尚未优于简单判别观测**：RQ3.5 前者 macro=0.3387，低于“优先级筛选＋宿主/同类支持、不加核验说明”的 0.4026，但配对校正未显著。[R7]
- **U12【未证实】更长领域说明或显式核验措辞不是稳定收益来源**：RQ3.5–3.6 将 SIRCL 风格诊断指令、系统领域说明、假设核验/修订措辞分别替换或组合，没有形成独立、稳定改善。[R7][R8]
- **U13【未证实】关系区收益尚未定位为某一单独字段**：分别删除异常排名、严重度、出现时间、调用边，或切换调用/部署关系及观测绑定方式，都未形成普遍更优组合。[R9]
- **U14【未证实】数值面板邻近实体＋归属连线的具体增益机制尚未完全识别**：相对“完整调用/部署关系图、没有数值面板”和“相同面板远置、仅 ID 对应”均未校正显著；邻近、连接及交互三项也未显著。[R10]
- **U15【未证实】普通 QA 或 attention 不是可靠 RCA 代理终点**：现有 QA–RCA 关联较弱，attention 相关也不能建立因果使用或收益。[R1]
- **U16【不能归因】现有数据不能独立回答“擅长几 hop”**：图深度几乎随数据集/应用变化，缺少足够的同条件深度对照。[R11]
- **U17【观察边界】指标条数不等于动态复杂度**：AIOPS-2022/2025 的 series 中位数约 4,612/937，但抽样有效秩约 21.77/21.10；有效秩也不是完整系统熵。[R11]

## 四、影响以上结论的实现与有效性审计发现

- **A01【覆盖边界】根因可见性必须分层**：候选中有根因、图边涉及根因、有直接遥测、有相关机制、模型真正读到，五者不能合并。[R1][R3][R4]
- **A02【观测事实】缺少直接根因遥测的病例非常困难**：RQ1.1 主集合 44 例没有相关已展示指标/调用链/日志，全文本和全视觉均未命中，“关系图＋其余文本”仅 1 例；不是因果不可识别定理。[R1]
- **A03【no-op】部分“取消分组/增加机制”的输入并未改变**：这种结果不能用来证明分组无用、鲁棒或某新机制有效。[R4][R5]
- **A04【覆盖不足】联合计数/条件比例实验没有充分测试宿主范围机制**：60 例仅 28 例有新增包，105 个包全来自同一请求内部的关联，没有宿主/同类实例范围包。[R7]
- **A05【时间语义缺陷】RQ3.2 指南与窗口边界不一致**：影响 444/480 eval、339/360 test，限制相关时间推理结论。[R4]
- **A06【动作混杂】RQ3.2 部分对照不是单变量**：标为“原始筛选扩容”的版本不只扩容，旧新证据池的统计/调用链语义有差异；标为“强制双侧配对”的版本不总有双侧，目标包删除也可能只删首条事实。[R4]
- **A07【作用位置错误】选择后加噪只能检验 Solver 抗干扰**：不能将 RQ3.2 这项结果称为选择器抗噪能力。[R4]
- **A08【测量/因果边界】错误单位与“最早异常即源头”规则不能支撑机制结论**：历史调用链单位误标须保留记录，且已有故障源异常晚于症状的反例。[R6]
- **A09【实际绘图覆盖】RQ3.7 并非所有病例都画了连续条形图**：两个 AIOPS 没有合格连续条形图、仅读数；AegisLab 为 44/60，不能宣称跨数据集条形图收益。[R10]
- **A10【缺失敏感性】超时掩码会影响候选方法的表面顺序**：RQ3.6-A 将超时计零的敏感性分析，可轻微反转“项目原证据”与“SIRCL 工具证据”的顺序；应保持主口径并同时披露敏感性。[R8]
- **A11【可执行性口径】不可执行设计不是模型读错图**：历史零分效用与后来排除规则不能混用，也不能把未发请求的低 token 当效率收益。[R1]
- **A12【外推边界】高分、oracle 和反复暴露都不能冒充独立泛化**：不同阶段、原 test、RE2、累计覆盖需单列；未开展人工研究，不能宣称已降低工程师 MTTR。[R1][R2][R3][R11]

## 五、合并后的研究判断

1. **已有正证据不是“视觉普遍有效”，而是特定信息与组织条件下有效。** “只有关系区用图”“追加宿主/同类观测并去重后，关系用图”“数值面板邻近实体并加归属连线”是不同层次的正证据，不能互相替代机制归因。
2. **最反复的负模式是能力置换。** 新增网络/操作线索或改善 pod/service 排序时，可能丢掉 node、memory、I/O 的原有能力。
3. **最值得守住的是机制证据，而不是实体覆盖数。** 同一个根因的一条 CPU 指标不能替代其真正有用的内存或 I/O 信号。
4. **视觉的候选价值之一是重排竞争根因。** 多轮和多个图文比较都出现“原已入前五、后来升至第一”，但不能据此跳过覆盖与破坏分析。
5. **MRR 与可靠性必须并列。** 更高 MRR 可以同时伴随更高输入成本、错误绑定或数字敏感性；解释自洽也可以不提高 MRR。
6. **未显著的正方向应保留，未真正实施的动作不能被否定。** 后续研究需要修复机制与归因缺口，而不是不断重跑一般图文胜负。

以上六点是对前述证据的综合解释，不是额外六个独立实验发现。当前没有据此新增实验、修改队列、重新打分或启动模型。
