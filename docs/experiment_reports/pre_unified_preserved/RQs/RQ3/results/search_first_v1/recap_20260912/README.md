## 6. 从这些尝试得到什么

1. **增补证据比盲目替换更有希望，但增补对象要对。** 保留top8并补节点CPU/内存
   在一批case上有效；均衡各类指标、强制owner覆盖却退化。
2. **覆盖率不等于诊断价值。** 直接根因相关展示覆盖18→23/24而MRR下降是明确反例；
   还要看展示的是否是能区分原因的信号，而不只是同一实体的任意遥测。
3. **读对实体类型是必要进展，不是充分条件。** 类型提示把误用从6例降到1例，
   但模型仍会选择错误的原因，说明不只是OCR或ID复制问题。
4. **更多图表、更多元数据、更多解释并不自动有益。** 所有hosting关系、更多
   统计标签、词典和均衡资源补齐都有负结果；可能增加竞争线索，不能归为信息越少越好。
5. **Trace有明显的局部价值，但不能普遍代替Metrics。** 某些局部延迟/调用链案例
   获益，node IO等案例需要资源证据；统一trace-only或当前路由都不够稳。
6. **时间窗口和坐标轴会改变判断，而且数据集方向不同。** 说明表示设计确实影响
   输出，但没有找到共同稳定的参数；四舍五入或曲线更平并不能保证正确诊断。
7. **耗费更多推理token没有稳定回报。** low thinking输出约17–21倍，未同时改善两集。
8. **纯视觉并非当前自动省输入。** 较强候选使用大图，image tokens从4692升到16002；
   图内容减少但尺寸不变时，input也不一定下降。不能把MRR增益包装为同时省成本。
9. **公开理由中存在因果捷径。** 例如把最早onset/最大z当原因、把caller当传播起点、
   把普通资源变化叫耗尽、把命名组当hosting。有时排名正确但理由仍错。
10. **最明显的未解决问题是跨case稳定性。** 改一个小细节在重复小样本上得到高分，
    不能替代对新训练事件的核查。当前没有达到两AIOPS均>.54和总体>.65的证据。

这些是阶段性观察，不将小样本涨跌称为已经证明的普适贡献。已登记的配对统计及
负结果保存在每批paired_review/log；多数后期对比的Holm检验并不显著。
目前尚未测出可以直接进入全量eval／新SFT+RL的稳定共同方案。
