# RQ4.2：共同图像修复与分组干预 CPU 审核

日期：2026-10-09。当前权威产物：`RQs/RQ4_2/results/partition_v3/`。

**结论：实现和技术检查取得进展，但完整 CPU 准入没有通过。** 220 例共同图像的容量、来源完整性、实际渲染已经通过；预选 SEM 在 AegisLab 仅 38/100 例同时满足原登记的干预强度要求，低于 50/100。一个有原理依据的面积加权修订提高到 44/100，仍未通过。按登记停止候选，未启动 GPU smoke、真实特征提取或正式实验，新增模型调用为 **0**。

这不是新的 RCA 性能负结果。没有测量本候选 MRR，也没有新的真实模型 attention 数据。此次不能宣布“全部 CPU 测试和门槛通过”。

## 1. 执行边界与版本

用户授权修订代码、测试，并在评估需要时调整计划；本轮终点限于 CPU，暂不启动 GPU smoke。所有图片均由 `src/renderer/` 生成，所有诊断事实仍仅通过图像进入候选方法；单调用规则、中央 `scorer` 及历史保护规则不变，未修改 `Codex.md`。

- `partition_v1`：此前乐观容量必要条件失败的完整材料，保留。
- `partition_v2`：紧凑显示、四竖区实现及修复过程。其早期测量漏检了长文字内部溢出，前景掩码还误计节点底色；随后又发现将 `Observed entities` 与完整候选目录混淆。**该版本的分组通过数及 SHAM 取消预告均已作废，不能作为资格。** v2 的不完整 processor 检查主动终止，未运行模型。
- `partition_v3`：修复上述问题后的权威渲染及分组审核。原算法最终结果在 `grouping/report.json`；面积加权修订独立保存在 `grouping_ink_weighted/report.json`。没有覆盖原算法失败结果。

[实施修订说明](../experiment_plans/RQ4_2_CPU_Revision_2026-10-09.md)记录了具体语义与显示变化。原四轮评审针对原设计；不把这些 CPU 修订说成获得了新的盲审认可。

## 2. 已解决的共同表示问题

原四象限中完整来源单元高度与大量重复字段前缀造成容量不足。当前采用四个等面积竖区：主图宽 4096，高度按 3072、4096 依次检查；每区宽 1024，普通卡片宽 512，图关系及完整候选目录可跨本区两列。页眉高 32。完整卡片不跨区，全部矩形对齐 32 px 网格。

显式 `source_scopes_v2` 将相邻字段的公共名称前缀呈现为可见作用域，独立反解后必须逐项还原原名称、值与出现顺序。数字不舍入、不量化、不删除；长摘要真实换行。曲线保留横坐标及全部有效观测，继续跨缺测位置连接，不标记缺测。事件图采用按事件数决定的固有高度，避免把实际内容塞进无效 SVG 高度。

`evidence_regions` 在 unified renderer 注册测量后的精确布局与四张原生区域导出，补足原比例布局无法表达不等高完整单元的问题。NATIVE4 的四张图逐像素等于主图对应区域，没有重新绘制或重采样。

| 数据集 | 完整来源装箱 | 实际主图渲染 | 图内原字段与绑定 |
|---|---:|---:|---|
| AIOPS-2022 | 60/60 | 60/60 | 通过 |
| AIOPS-2025 | 60/60 | 60/60 | 通过 |
| AegisLab | 100/100 | 100/100 | 通过 |
| 总计 | 220/220 | 220/220 | 404,452 个绑定 |

本地 DOM 诊断字形最小实测约 17.99995 px（浮点几何误差，登记值 18 px）；这不代替实际 processor 处理后的资格。当前 v3 全量 processor 检查尚未运行，不能用几何推算宣称已通过 16,384 图像 token／40,960 context 门槛。

## 3. 来源、目录和前景定义

完整候选目录由精确标题 `Candidate IDs · exhaustive fixed order` 识别。`Observed entities` 只是较短的已观测实体目录。二者都是全局组件，不产生“同时属于所有实体”的优化权重。实体排序使用完整候选目录顺序。这一纠正影响所有病例，故 v3 重新进行了受影响的排放、渲染和分组审核。

来源单元按原记录身份闭包；公共请求配对集合用显式 `PAIRxx` 键区分不同记录。不能因为实体相同或值相同就合并观测。聚合关系图是独立的全局单元，图中的来源引用不把整张图与所有端点记录合并为一个单元。

`CardDiagnosticInkV1` 的前景面积采用实际绘制像素的 alpha 加权面积。排除 HTML 背板、面板边框、固定页眉与图节点的固定内部底色；保留诊断文字、节点轮廓、数据点／条／线、坐标、关系边和箭头。正常 PNG 在掩码生成前已保存，掩码仅供审计。所有旧错误掩码与失败记录保留。

## 4. 权威 SEM／SHAM 门槛结果

每例同时要求：卡片加权与前景加权同组关系变化率均 ≥20%，真实关系切边权重下降 ≥15%。随后要求**每个数据集至少 50% 病例**同时达标。完整分母保留，未按病例结果换队列。

同组变化率使用全体无序单元对的加权不一致比例；它是共同分组关系的变化，忽略组编号重命名。没有改为正关系集合的 Jaccard 距离，也没有降低百分比阈值。

| 数据集 | SEM 同时达标 | 要求 | SHAM 同时达标 |
|---|---:|---:|---:|
| AIOPS-2022 | **50/60** | ≥30/60 | 47/60 |
| AIOPS-2025 | **55/60** | ≥30/60 | 54/60 |
| AegisLab | **38/100** | ≥50/100 | 68/100 |

**SEM 未通过，因此整个候选停止。** 当前正确版本的 SHAM 自身通过；不能沿用 v2 的“取消 SHAM 后运行四臂”结论。

| 数据集 | 卡片变化率中位数 | 前景变化率中位数 | 真实关系切边降幅中位数 |
|---|---:|---:|---:|
| AIOPS-2022 | 30.57% | 23.44% | 59.69% |
| AIOPS-2025 | 29.05% | 28.76% | 63.60% |
| AegisLab | 26.64% | **18.64%** | 59.90% |

AegisLab 中，92/100 例达到卡片变化率门槛，100/100 达到切边下降门槛，只有 39/100 达到前景变化率门槛，联合达标 38/100。因此，失败不是 SEM 与 GEOM 完全相同，也不是没有减少真实跨组关系；问题是按当前预注册前景口径，干预在足够多病例上的幅度仍不够。全局图与目录保留在分母中，不能为过关把它们删出前景或当作可自由移动背景。

## 5. 获授权的修订评估

没有使用任何新旧排名来挑选本轮修订病例。固定哈希每数据集选 10 例先检验，然后只对有明确依据的一项修订做全量 CPU 审核。

### 5.1 同实体内按诊断图元面积分配关系权重

关系类型与端点度数归一化不变；一条实体关系对应多个来源单元时，按双方实际诊断图元面积乘积归一化分配权重，而非平均分配。原实体边的总权重守恒，没有添加新边或根因分数。

| 数据集 | 面积加权修订 SEM 达标 |
|---|---:|
| AIOPS-2022 | 53/60 |
| AIOPS-2025 | 54/60 |
| AegisLab | **44/100** |

仍未通过，**未采用为正式方法，也未把它增加为新实验臂**。修订和原算法报告并列保存，不能用两个版本各自成功病例的并集作为方法资格。

### 5.2 三组循环交换的小范围验证

考虑异尺寸完整来源单元可能使两两交换停在局部最优，增加仅在普通移动／交换没有改善时才检查的三组循环交换。目标仍只优化真实关系切边；没有直接优化资格变化率。沿用同一个固定 30 例子集，其达标数为 10/10、9/10、3/10；未解决 AegisLab 问题，故没有继续做全量该变体，也没有采用为正式算法。

这些均是 CPU 开发评估，不是诊断效果、统计显著性或方法泛化的证据。

## 6. 代码与技术回归

代码位于 `RQs/RQ4_2/src/`，保留五功能模块。新增共享 `vlmrca.vlm.vision_partition` 适配器与从历史实现提取的轻量 attention 摘要工具，未改历史实现。新增评分代码仅从 `scorer` 导入。

已通过的技术检查包括：

- 静态结构、调用预算、默认关闭入口、111 项历史文件保护。
- 全 220 例真实 DOM、原字段恢复、布局边界、全部绑定、完整来源单元、四区原生像素相等。
- 四组精确等容量、2×2 merger 邻域保留、背景移动上限、无操作映射不变、组重命名不变。
- 在 CPU 随机权重的真实 27 层 Qwen 视觉架构上验证 K=1 原路径一致、有效分组产生不同输出、退出与异常时恢复原路径；独立显式 attention 块与掩码计算一致。**未加载真实 checkpoint，未使用 GPU，不能替代真实模型 smoke。**
- 中央评分器、无效输出计零、同输入引用、已提交结果先于输入物化跳过、暂停与持久回复恢复、单实例锁。
- attention 摘要的文本和图像区域归一化、64 KiB 单调用限制及每万次含预留空间小于十进制 1 GB 的存储上界。只有合成 CPU 输入，真实采集与速度尚未测量。
- 48 项回归通过；随后另有 2 项涉及当前共享组件的历史浏览器测试通过，合计 **50 项独立测试**。仍有 10 项未涉及本轮变化的可选历史浏览器测试未运行，不记为通过。
- 历史默认示例 PNG 逐字节一致，SHA256 为 `78fd3614dd860a58b663767027dfcd68e52e4b6e8f77ed3bf5d4910c83cf617c`。

已实际打开三数据集固定主图、最密关系区域及最长标题病例主图。密集关系图仍有大量边交叉；查看器对大图进行了缩放，因此人工检查不代替逐字形或实际 processor 可读性资格。当前 QA 图与完整边界例图审查未完成，详见 `examples/visual_review.json`。

当前 v3 没有完整 CPU 资格凭据。QA 图、实际 processor 全请求审核、完整冷路径／正式运行器端到端资格不列为通过；v2 的 QA 输入检查不能替代当前版本。GPU 适配器、被动采集和单调用运行器是待进一步资格的代码，不是可启动的已验证部署。

## 7. 状态与下一步

**当前唯一状态：`stopped_scientific_gate`。** 不启动模型，不生成正式队列，不自动选 FULL、SHAM 或其他条件替代 SEM。1,500 次登记调用预算尚未消耗，也不会自动转换成新臂。

共同表示已经解决了原容量障碍，适配器和审计基础可以保留复用。但要继续这一候选，必须先有实质性的来源单元／分组设计论证，或公开说明并重新登记干预指标的科学依据；不能把 38/100 或 44/100 写成通过，也不应继续围绕这几个百分比盲目搜索布局。此次到此停止，等待下一步研究决策。
