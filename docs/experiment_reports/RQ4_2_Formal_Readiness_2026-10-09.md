## 关机与恢复语义

| 中断位置 | 再次启动后的行为 |
| --- | --- |
| 已有 `completed/<key>.json` | 信任原子提交，直接跳过；不重绘、不重推理 |
| 完整回答已持久化，但评分／完成标记未提交 | 恢复原回答，只补验证、评分和提交；不新增模型调用 |
| 请求已登记，但没有完整回答 | 保留旧尝试和 partial，记为 interrupted；从头执行该请求，计入恢复预算 |
| 只完成部分 CPU 绘图 | 保留旧目录，新请求使用新的目录，不读取半成品 |
| 全阶段完成标记存在 | 加载模型前直接返回完成状态 |
| 已观察到代码、身份或基础设施错误 | 保留错误并阻塞，先诊断修复；不伪装成断电自动重试 |

恢复粒度是**请求级**，不是从断电时生成到一半的 token 继续。已经完整保存的答案不会因为缺最后的提交标记而被浪费。恢复旧答案时连续冷时延记为 null，保留原始读入至回答的时间，不把恢复后的短评分时间当成完整诊断速度。

SQLite 采用 WAL 和 FULL 同步；JSON 写入先 fsync，再原子替换并同步目录。最终阶段标记在全部请求提交、attention 排空和结果清单落盘后写入。
