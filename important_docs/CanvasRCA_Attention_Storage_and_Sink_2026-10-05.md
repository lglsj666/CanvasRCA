# CanvasRCA attention：低存储记录、视觉 sink 与后续验证

日期：2026-10-05。性质：对话整理、来源复核与未来研究建议。

**当前结论：可以设计每 10,000 次调用新增 attention 文件低于十进制 1 GB 的记录方案；视觉 attention sink 值得作为机制与方法候选。前者目前只有存储预算测算，后者尚未在 CanvasRCA 验证。本文件不代表采集器已经实现、资格测试通过或新实验启动。**

用户支持未来把研究分为相互反馈的两条线：一条优化 MRR 与实际成本，另一条解释重要的反直觉现象。attention 是连接两条线的测量和干预工具。主线仍是保留有效 M/R/L/G 证据，改善真实根因排名，同时控制成本；未来工程目标为 MRR 约 0.60、相对兼容强基线成本最多增加 5%，优先降低。目标不是既有结果，也不追溯改变历史实验的采用门槛。

本文集中保存此前有关存储与 sink 的讨论，不替换[反直觉发现记录](CanvasRCA_Counterintuitive_Findings_2026-10-05.md)、[研究方向建议](CanvasRCA_Empirical_to_Method_2026-10-05.md)或[历史与文献复核](CanvasRCA_Empirical_Literature_Review_2026-10-05.md)。本次没有修改模型、renderer、采集代码或任何实验的冻结输入及执行状态。

## 1. 历史观察及其范围

### 1.1 为什么停止大量记录 attention

用户反馈的实际问题是，每 10,000 次调用约产生 100 GB 记录，硬盘无法长期承受。因此未来恢复采集的前提是明确控制新增存储，而不是事后清理。

[历史归档收据](../RQs/RQ1_1/results/ATTENTION_ARCHIVE_20260909.md)核实了七棵 attention 目录合计 **251,800 个文件、111,453,790,762 字节**，校验后迁入离线归档。这个数字是七目录合计，不能当成严格的“每 10,000 次调用”实测斜率。本次没有恢复全部离线文件，也没有测得各类旧文件的实际压缩率。

从[旧保存逻辑](../RQs/RQ1_1/src/main.py)与[采集器](../src/vlmrca/vlm/attention_probe.py)可确认：

- 一次调用会保存 raw probe、文本映射、图像网格及热图 PNG，生成答案字段另有对应记录。
- 长浮点向量、token ID、位置及映射信息会出现在多个派生 JSON 中；热图可以按需重建，不必每次保存。
- 旧生成阶段已经对注册的答案 token 在线求均值，最多 128 个目标 token；不能把旧方案误述为保存了每个生成步骤的完整 attention 矩阵。
- 旧 `read_sidecar` 已清理消费后的响应/引擎临时副本，不能把新方案的预期节省全部归因于修复这个已处理的问题。
- 旧采集没有把全部原始 Q/K/V 写入磁盘，但运行时仍需额外状态；磁盘成本和 GPU 内存成本必须分别衡量。

### 1.2 标题区域的 attention 聚集

历史 `rq1_rca / headline / V` 汇总中，标题带 attention 的单位面积密度，相对实际 M/R/L/G 证据区平均密度为：

| 查询口径 | 密度比 |
|---|---:|
| 最后一个 prompt token 查询（pre） | 6.1578 |
| 注册答案字段 token 查询的均值（gen） | 2.0822 |

测量来自首个注册 full-attention 层、跨 heads 平均。标题带是顶部矩形区域，不是仅标题文字的字形；gen 对 prior prompt keys 计量，不等于整个推理过程或所有层的总体 attention。完整数字、相关性及有效掩码见[CF-02](CanvasRCA_Counterintuitive_Findings_2026-10-05.md#3-cf-02标题带-attention-密度异常高)及其[原始汇总表](../docs/experiment_reports/RQ1_1_RQ2_1_findings/assets/rq11_attention_all_arms.csv)。

这一现象值得研究，但当前未证明标题有害、标题就是 sink，或删除标题能提高 MRR。高 attention 的视觉 token 经上下文计算后也可能携带其他区域的信息，不能直接把像素位置等同于它在模型内部承载的全部内容。

### 1.3 与 QA–RCA 脱节的关系

历史三主数据集 293 个共同有效病例中，视觉 QA 与 RCA 的 Spearman ρ 为 0.0212；视觉相对文本的 QA 改变量与 RCA 改变量的 ρ 为 0.0511，原家族 pH 均为 1。见[CF-01](CanvasRCA_Counterintuitive_Findings_2026-10-05.md#2-cf-01测得的读取能力与诊断表现脱节)。

这支持优先追问“测得会读，是否代表诊断时有效使用了证据”，但未证明两种能力独立，更未把脱节的原因定位到 attention sink。两条观察可以形成共同假设，暂时不能合并成同一个已确认机制。

## 2. 低于 1 GB 的方案：改变记录内容与保存方式

### 2.1 设计原则

核心是**在线汇总、二进制存储、共享输入按哈希引用、仅少量预定样本保存明细**。这是面向研究问题的有损摘要，不承诺把旧 100 GB 文件无损压缩成 1 GB。

默认不落盘全层、全头、全 query×key attention，不保存完整隐藏状态或 Q/K/V，不为每次调用自动生成热图 PNG。浮点统计优先用 FP32，避免未经验证地转成 FP16 后丢失小概率；二进制可额外压缩，但预算按未压缩上界设计。

记录同一次真实调用中的信号，不为画热图额外重新调用模型。logger 的被动观测与后续修改 attention 的主动干预使用不同版本和资格记录。

### 2.2 每次调用保存什么

| 内容 | 建议保留方式 | 可回答的问题 |
|---|---|---|
| 调用和来源身份 | call key、模型/输入/PNG/processor/区域定义哈希、采集版本 | 是否与该次真实输入和输出匹配 |
| 查询定义 | pre 与 gen 分开；目标字段、实际 query 数量、上限、截断及不可适用状态 | 比较的是否为同一种测量 |
| 分层分头区域 mass | 在原始 token 几何上积分后保存 FP32 | 标题、各模态、候选和指令的分配差异 |
| 面积、token 数与覆盖 | 固定区域定义及覆盖信息，公共几何尽可能共享 | 面积/长度校正与未分配质量 |
| 空间摘要 | 每层每查询口径一个跨头平均 32×32 网格 | 大致热点和空间漂移 |
| 有界 token 明细 | 固定数量 top-k、必要位置及残余总量 | 辅助定位少数重点位置 |
| 状态和完整性 | 缺失原因、实际字节数、校验和、原子提交状态 | 失败与恢复是否被诚实记录 |

区域 mass 必须先由有效 processor 的真实 post-merge/post-pooling 几何积分，再单独生成粗网格。不能从 32×32 缩略图反推很窄标题带的精确质量。空间积分沿用原测量中“token mass 在其对应像素覆盖内均匀分配”的定义，不是像素级因果归因。

视觉区同时报告 raw mass、mass/面积，以及相对实际 M/R/L/G 证据区的密度比；标题、留白和未分配区域另列。文本区保存 raw mass 和按 token 数校正的 focus。使用可守恒的互斥区域划分；如果另有重叠语义标签，不能把其总和当作全部 mass。

**归一化域必须显式记录。** 历史 gen probe 对 prior prompt keys 重新归一化的结果，不可直接与对全部可见 keys 归一化的原生权重混用。新版本如改变 key 范围，须另列口径和版本。

### 2.3 可复算的存储上界

以下是候选配置的预算，尚未选择最终层位或实现采集器：4 个预先选择的 full-attention 层、2 种查询口径、24 个 heads、24 个固定区域槽，FP32。纯文本、不适用或不足槽位的情况用明确定义的状态处理，不能伪装成零 attention。

| 每调用组成 | 算式 | 字节 |
|---|---|---:|
| 分头区域 mass | 4×2×24×24×4 | 18,432（18 KiB） |
| 跨头空间网格 | 4×2×32×32×4 | 32,768（32 KiB） |
| 有界元数据、覆盖、top-k、校验及容器开销 | 固定总配额 | 14,336（14 KiB） |
| **每调用总上限** | 上述三项之和 | **65,536（64 KiB）** |

附加明细在完整调用清单上按预定哈希选至多 100 次，约为 1%；每次最多 1 MiB。它只能保存登记的层、头、query、token 子集或统计，不承诺装下任意长度的完整矩阵。不得依据 MRR 或热图效果挑选后再声称样本有代表性。

| 10,000 次调用的组成 | 字节 |
|---|---:|
| 全量 64 KiB 摘要 | 655,360,000 |
| 至多 100 份、各 1 MiB 的额外明细 | 104,857,600 |
| 全局索引、共享映射、配置与其他持久化开销总预留 32 MiB | 33,554,432 |
| **持久化总预算** | **793,772,032，约 794 MB** |
| 全局临时写入及可清理预览缓存总预留 64 MiB | 67,108,864 |
| **包含临时文件的预算峰值** | **860,880,896，约 861 MB < 1,000,000,000** |

这是**逻辑字节上界的算术测算**，不是已经跑过 10,000 次调用后的磁盘实测。文件系统分配、目录/容器开销和并发临时文件仍需验证；实现宜使用少量有界分片，避免大量小文件。真实资格必须同时核对文件字节与实际磁盘占用。

“低于 1 GB”范围为这 10,000 次实际尝试新增的 attention 数据及其索引、必要新增映射和临时文件；已有实验必须保留的 prompt、回答和 dashboard 不重复保存，也不计作本次新增 attention 文件。如果没有已有映射，新生成映射必须计入 32 MiB，不能转移到另一个目录假装免费。重试也是实际尝试，不能只数成功调用。模型或区域数增加后必须重算，不能沿用这个上界。

### 2.4 写入、恢复与超限处理

1. 前向过程中在线求和或有界抽样，只把最终摘要转移并序列化。GPU 中间状态也要有上限，不能“磁盘小、显存无限增长”。
2. 独立二进制帧/分片包含长度、版本和校验；可以压缩，压缩无收益时保留原格式，不依赖压缩率通过预算。
3. 完成提交后用 call key 去重；恢复信任原子完成标记，不重扫全部历史 PNG，不重新发起已提交模型请求。
4. 临时文件、预览缓存和并发写入共用全局 64 MiB 配额，不是每 worker 各有 64 MiB。生成热图只按需进行，禁止不受限缓存。
5. 每条记录写入前检查上限。可选明细超限则记录未保存状态；若必需摘要或共享映射无法容纳，判为采集资格失败，不能静默截断关键指标或删除旧成果腾出“已通过”空间。
6. attention 缺失、答案字段没有可测 token、模型无效输出分开记录；不能把这些情况混成零值或借机重答。

### 2.5 保留能力与信息损失

可研究：预定层/头的区域分配、面积校正后的标题密度、粗空间热点、pre/gen 差异，以及这些摘要与 RCA 排名/失败类型的关系。

不能事后恢复：任意层、任意 query 的完整 attention，完整逐 token 推理轨迹，已平均掉的头或 query 差异，任意新定义区域的精确统计。可重建的是已保存摘要的热图，不是原始分辨率的全部历史热图。少量明细只能支持其登记范围。

若要识别 sink，还需要前向中计算隐藏状态的相关激活统计；仅有区域热图不够。可以保存有界的激活分布、候选位置及判别配置摘要，详细样本保留指定 token 的信息。这部分必须装进既有配额或重新审计，不能默认免费；全量隐藏状态不落盘。老 probe 的 pre value 指标位于 output projection 之前，gen 对应贡献指标不可用，不能直接当作论文的完整贡献度量。

## 3. Visual attention sink：论文实际支持什么

聚焦复核对象是 Seil Kang、Jinyeong Kim、Junhyeok Kim、Seong Jae Hwang 的 **See What You Are Told: Visual Attention Sink in Large Multimodal Models**，ICLR 2025；arXiv v1 为 2025-03-05。本次复核日期 2026-10-05，采用[官方会议页](https://proceedings.iclr.cc/paper_files/paper/2025/hash/da8a39bc39ae1c89dd6ebb1e3bcbb3f3-Abstract-Conference.html)、[原文](https://arxiv.org/html/2503.03321)和[作者代码仓库](https://github.com/seilk/VisAttnSink)。官方仓库/README 已查看，尚未完成代码移植或后端兼容验证。这是对已讨论论文的定点复核，不是完整的新文献检索。

| 项目 | 原文结论与方法 |
|---|---|
| 识别（§4.1） | 使用隐藏状态中特定维度的归一化异常激活，不能只按 attention 大小挑 token。 |
| 屏蔽验证（§4.2） | 屏蔽文本查询对视觉 sink 的连接影响较小；等量随机视觉位置屏蔽更容易损害性能。 |
| VAR（§5） | 在选出的 image-centric heads 中，把部分 sink attention 按现有权重比例分给非 sink 视觉 token。 |
| 结果及边界（§6、附录 C） | 在包括 Qwen2-VL 的多模型视觉任务中改善表现；未经 head 选择全面重分配可能严重失败，原始 attention 的定位也有局限。 |

性能方法是**选择性权重重分配**，不是直接删除高 attention token。它不需训练或额外推理步骤，但未建立 CanvasRCA 的 RCA 收益，也不自动减少输入 token；实际后端开销需测量。[方法与消融原文](https://arxiv.org/html/2503.03321)

## 4. 对 CanvasRCA 的解释与迁移假设

### 4.1 可以研究的核心问题

**模型是否已经读到了正确事实，但根因比较时没有有效使用这些事实；某些低贡献视觉位置是否参与了这种分配问题？**

这是把 QA–RCA 脱节、标题聚集和“保留完整文本再加图反而退化”联系起来的假设。三种现象可能有不同原因，目前没有证据把它们统一归因于 sink。先从现有破坏病例、公共事实绑定与采集定义定位问题，避免另开一轮泛泛的文本对图像比较。

标题像素、token 位置、视觉上下文、提示封装都可能影响结果。若要声称“标题造成 sink”，除内部信号还需注册保持事实的内容/位置控制；仅让热图变暗不够。相关控制如需重绘，仍必须通过 `src/renderer/`，保持缺测连线规则和公共事实边界。

### 4.2 模型和运行成本不能直接照搬

本次读取本地部署模型配置（`${CANVASRCA_QWEN_MODEL}/config.json` 对应的项目模型），记录到 24 个 attention heads、4 个 KV heads、64 层，层类型为三层 linear attention 加一层 full attention 的重复结构；配置哈希见配套复核文件。目录别名与配置内部类型不是适配依据，应按实际模块验证。

因此须分别核对 full-attention 层的 hook、归一化域、缓存和批处理；不能把普通 softmax attention 的修改直接套到所有线性层。也不能复制其他基础模型的 sink 维度编号并声称已识别本模型的 sink。

轻量日志首先解决磁盘问题。额外重算 attention、获取隐藏激活或绕开原高效 kernel，都可能增加时间和显存。单层兼容性应先验证，再决定是否启用四层；四层是预算示例，不是当前采集设置。

记录与干预分别衡量：

- **记录开销**：logger 关闭/开启时的延迟、吞吐、GPU 峰值和磁盘增量；输入及推理结果应保持被动观测语义。若后端切换造成差异，要单独披露。
- **干预效果**：同输入、同候选、同解码配方下的 MRR、AC@1/3/5、修复/破坏和输出长度；修改模型计算需要独立版本。
- **部署成本**：实际输入与输出 token、端到端耗时、吞吐、峰值显存、模型规模和 reasoning 配方。输入 token 不变不代表运行免费；存储减少不等于推理成本减少。

## 5. 未来最小验证建议

这是待登记的候选设计，尚无新调用额度、队列或启动凭据；不改变任何现有实验。

### 5.1 先完成测量资格

先用离线合成数值验证质量守恒、区域映射、归一化域、二进制往返、超限与中断恢复，检查 10,000 条有界记录的字节与磁盘占用。CPU 检查不能证明真实 GPU hook 正确；后续授权的 GPU 资格还需核对原生张量、批处理/缓存、被动观测开销和无结果相关抽样。

层位、查询字段、采样规则、数据角色、sink 识别与干预参数必须预先固定。识别 sink 不读取根因标签；方法开发与独立确认分开，已暴露 eval 不能改名成独立测试。

### 5.2 四个条件分别回答什么

| 候选条件 | 唯一主要改变 | 回答的问题 |
|---|---|---|
| ORIGINAL | 原始模型；使用一致的测量/后端条件 | 同期性能基线 |
| RANDOM_MASK | 同层、同头、同 query 规则下，屏蔽等量预定随机视觉位置 | 改变 attention 连接本身的影响 |
| SINK_MASK | 屏蔽独立规则识别的 sink 位置 | 被识别位置是否具有不同于随机位置的贡献 |
| SINK_REDISTRIBUTE | 在预定 heads 中选择性重分配权重 | 这种干预是否改善实际诊断 |

“等量”首先指位置数，不代表移除的 attention mass 相等；同时记录移除质量，不能把位置数匹配写成全部干预强度均已匹配。屏蔽发生在 softmax 前还是后、是否重新归一化、分配给谁，都必须写进正式协议。

为防止把更换计算后端的差异误归因于方法，所有条件使用可比后端；必要时在资格中加入不修改数值的 hook 检查。实验条件的公平性依赖匹配输入和运行设置，不能通过削弱强基线制造“视觉贡献”。

### 5.3 什么结果值得继续

- 目标是根因排名与成本改善，热图只是机制证据。sink mass 降低但 MRR 不改善，不能称方法成功。
- 定向屏蔽好于随机屏蔽，可以支持位置选择有区别，但未自动证明重新分配会提分，更未证明标题是原因。
- 重分配如改善 MRR，应同时检查数据集差异、Top-5、修复/破坏、重复波动和预算；候选采用需正式锁定统计比较与门槛。
- 识别不可靠、实现开销明显不合目标或干预无实质诊断收益时，记录适用边界，停止该候选，不自动扩大全层/全头搜索。

## 6. 与论文贡献及两条研究线的关系

直接迁移 VAR 应作为已有方法的适配或对照，不能包装成新算法。潜在研究价值是查明诊断证据在“读出—绑定—用于比较”哪个环节失效，再据此提出可验证、成本受控的方法。

机制线给方法线提供干预依据；方法线给机制线提供真实 RCA 效用检验。两条线共享病例、公共事实、强文本控制和成本账本，每阶段优先一个明确机制与一个主要候选，避免为了丰富图表而展开大网格。

可借鉴的未来方向包括：仅在已验证的适用条件下调整证据利用，或使用与公开实体/组件绑定相容的分配规则。这些都只是研究设想；是否比已有 VAR 有新意、是否产生可分离收益，仍需要相关工作核查和控制实验。
