# CanvasRCA：纯视觉方向的重新聚焦

日期：2026-10-06。性质：阅读与方向决策，**不是已注册实验，也不授权实现、训练或推理**。用户已取消并要求整体删除 RQ3.22；本记录不恢复其编号、计划、代码或资格。最新用户决定：**停止原 RQ3 开发路线，后续研究统一从 RQ4 开始。**

## 1. 现在要解决的问题

主线改为：**把遥测编译成具有明确实体、信号和时间归属的纯视觉表示，在一次诊断调用中超过强文本的根因排名，并控制实际部署成本。**

纯视觉限定诊断证据的输入通道，**不是完全不用文本**。RCA 任务定义、dashboard 怎么看、图形编码约定及输出格式要求仍以文本说明，但不能夹带该病例的观测或根因提示。图内允许必要的实体名称、单位、数值标签和日志模板。候选清单也放入图中，宿主程序保留候选合法性检查，但不通过动态 schema enum 偷渡给模型。图片失败不得退回完整诊断文本。所有图仍由 `src/renderer/` 生成。

强文本是要击败的对手，不是方法内部的旁路。基线可以在登记的评估中使用文本，这与纯视觉方法定义不同。单纯把文本基线删掉，不能建立“纯视觉打败文本”的结论；也不能降低它的证据质量或输出预算来制造优势。

## 2. 对 conversation_oct_06 的判断

已完整阅读 [原对话](conversation_oct_06)。其中最值得保留的是：renderer 本来知道每个图元的来源，应研究如何把这种确定性归属用于视觉特征组织和压缩。实体、信号、阶段不能在压缩中混成无区别的表示。

原对话最后提出“少量视觉 token＋必要的精确文本”。这一项与最新用户方向冲突，**不继承**。图外精确文本补丁、模型先选证据再诊断、重新枚举边际卡片数量，都不是本阶段主方法。

纯视觉并不自动带来创新。由 telemetry 渲染的图不会凭空增加信息；要证明的是某种视觉计算在给定成本下更有效。区域提取、多尺度处理和 token 压缩已经有相关工作，需要具体到 RCA 中如何保留诊断信息，不能只更换名词。

## 3. 为什么大量实验尚未收敛

以下判断基于本次复核的 RQ1.1/RQ2.1、RQ3.1、RQ3.7/3.8、RQ3.21 详细报告及反直觉发现记录；本次没有重新计算历史统计，也不声称重新认证所有历史运行。

| 证据 | 对下一步的约束 |
|---|---|
| RQ1.1 三主数据集：纯视觉 MRR 0.2658，文本 0.3093；纯视觉输入约低 59.9% | 成本压缩曾经做到过；真正未解决的是压缩后的诊断质量。不同历史样本的分数不能直接与当前 220 例比较。 |
| RQ2.1 放大分辨率有约 +0.0459 pooled MRR 的支持，同时输入约 4,820→7,484 token | 局部细节可能值得保留；全图放大不是已经解决的成本方案，数据集收益不均。 |
| RQ3.1 更换选择器后，node 直接资源证据大量丢失 | 冻结证据集合，先研究同图像/同来源的视觉处理，不同时换选择器。 |
| RQ3.8 完整文本加整图在原登记比较中退化 | “更多图形”和“更完整 dashboard”不是诊断质量代理；混合输入下的图形干预不能直接回答纯视觉机制。 |
| RQ3.21 当前 RAW_VISUAL 约 0.4934；紧凑实体视觉约 0.4180，虽然 token 下降 | 当前约 0.50 的历史锚点属于混合方案，不是纯视觉已取得的起点；数学可逆也不代表模型可理解。 |
| QA/RCA 脱节、标题 attention 聚集、实体块位置扰动 | 是有价值的现象；应帮助定位一个方法的失败环节，而不各自扩成无止境的大矩阵。 |

过去经常同时改变证据、表示、输出接口和适用病例；收益难以沉淀到同一冻结方法。资格测试又不断跟随方案变更重做。后续应先锁定一个可实现的核心操作，再用少量比较决定采用或停止。

## 4. 建议只推进一个候选：保留诊断结构的视觉压缩

候选流程是：公共证据 → unified renderer 图像及审计映射 → 视觉编码 → 受归属约束的视觉 token 保留/聚合 → 一次 RCA 排名。没有第二次模型取证调用，没有图外诊断文本。

具体研究对象不是一个整 service 向量，而是**实体 × 信号语义 × 阶段/时间区间**。尝试保留三类信息：

1. **身份与读数解释。** 标签、单位、坐标和其所属图元不能在压缩后失去对应；不同实体、不同量纲不直接混合聚合。
2. **局部变化形态。** reference/current、短时尖峰与持续变化不能只剩相近的平均外观；保留形态的效果须实测，不由算法定义自动保证。
3. **诊断所需对照。** 有公共依据的父子、部署与同类实例关系保留其方向/类型；正常对照和单侧 node 资源证据不能只因不显著被丢弃。缺少合法对照时不编造。

这些是拟检验的结构约束，不是已经实现或证明新颖的算法。第一版保持证据选择、图像像素和诊断模型配方固定，优先比较进入语言模型前的视觉处理。区域预算不得利用标签、历史正确答案或故障注入时间。

必须先查清局部特征与真实 processor patch/token 网格的映射、跨区域 token 处理、位置编码及输出嵌入数目约束。原始 patch 特征经过全局注意力后可能已混合信息，不能仅凭区域索引宣称完全隔离。任意 RoI 平均向量也不一定能被冻结 Qwen 正确解释。

如果现有接口不能安全接入，优先判断是否确实需要小型可学习适配器及合法训练数据。**本回合不授权训练**。不要把需要训练的方案伪装成无需训练的插件。输入侧“全局概览＋局部重新渲染”可作可行性工具，但它不等于已经实现了视觉特征压缩，也不能成为新一轮无限布局搜索。

|---|---|---|
| [TokenPacker，arXiv:2407.02392v2](https://arxiv.org/html/2407.02392v2)，方法 §3、实现 §4.1 | 用局部高分辨率特征补充压缩表示；论文在 LLaVA/CLIP/Vicuna 上训练 projector 等模块 | 对现有 Qwen 无训练即插即用；它的通用视觉成绩证明 RCA 有收益 |

候选的新意只能落在**诊断结构约束、可操作的预算算法、以及 RCA 的性能—成本证据**上，仍须和通用压缩、直接数值/结构方法比较后判断。先把这些差别写成可反驳的假设，再讨论论文贡献。

## 6. 下一步的工作顺序和停止点

**第一步，限定一天完成可行性决策。** 用固定公开病例核对最新 unified renderer 能否承载冻结证据，输出区域映射，并对齐真实模型处理后的网格；同时检查模型特征接口与位置编码。交付接口可行性、证据缺口和实际预算表。禁止通过删关键事实、偷偷改像素上限或引入文本补丁来过关。该时间是工作目标，不是已完成承诺。

**第二步，接口成立才登记小规模机制验证。** 建议先固定每数据集 20 个开发病例，不按根因或既有错误选例。核心比较仅四个：强文本基线、常规纯视觉、同预算通用视觉压缩、拟议结构约束压缩。主候选最后一个提前锁定。这个小批次最多 240 个主请求；资格/失败预留另行登记，当前没有新调用授权。小样本用于开发决策，不能用于宣称最终显著性或事后筛掉难数据集。

强文本承担整个可用公共证据集，不能为配成本而故意截断；视觉压缩两臂使用同源图像与相同保留 token 数。如果发生证据选择差异，分开报告方法效果与纯压缩效果。先证明方法在实际 MRR 和成本上值得继续，再扩展到完整冻结批次；不能靠 QA 提高或 attention 热图漂亮代替 RCA 结果。

**第三步，给机制支线一个直接问题。** 在同一方法上检查实体/信号/阶段错配是否减少，以及绑定扰动的影响是否超过真正独立重复。QA 只测这些约束对应的读数，不给 RCA 传答案。Attention 若采集沿用轻量限制，仅用于定位，标题 sink 暂不独立开大实验。保持当前约 80/20 的方法/机制资源倾向，它是阶段策略，不写入 Codex。

**48 小时目标是形成继续/停止的依据，不是再完成一个无论结果如何都继续扩展的大矩阵。** 如果接口需要大规模重训、没有合规训练集，或无法把绑定/细节约束落到真实模型输入，明确停止该原型并重新做方法决策；不自动恢复混合输入，不自动转向下一个布局。

## 7. 什么时候接近完成

交付的是一个冻结的、单调用纯视觉方法及有限证据链，而不是不断累加的实验编号。

- 在完整预注册病例上超过有竞争力的强文本，报告逐数据集、失败分母、MRR/AC 和配对统计。历史约 0.50 的混合方法作为额外参照，不能直接改称纯视觉能力。
- 实际 input＋output 成本不超过强文本 1.05 倍，优先明显下降；若修改视觉编码器或加适配器，计入视觉前处理、模型运行和训练摊销，token 减少不冒充总算力减少。
- 同预算通用视觉压缩对照能显示拟议结构约束的作用；冻结后进行独立性/曝光审核合格的验证。若没有独立病例，明确这是开发证据，不能重新命名历史 test。
- 保留可核验解释证据和一次有边界的机制验证即可，不以解明所有反直觉现象为交付前提。MRR≈0.60 是工程目标，不是保证，也不是无限追加实验的理由。
