# CanvasRCA QA：已确认踩坑记录与设计规范

审计日期：2026-10-20。覆盖 RQ4.1—RQ4.7。本文用于独立事实问答（QA）的出题、提示、评分、资格审核和结果解释。

**核心结论：历史 QA 的低分同时包含实验接口缺陷和真实答错，二者不能混为一谈。尤其是空标准答案、未说明的定位协议和整份格式判零，已经直接损害了测量有效性。** 本文前半部分只记录有证据的问题；设计目标、规则和建议全部集中在后半部分。

本次没有新增模型调用，没有修改历史输入、回答、评分器、原分数或 `Codex.md`。离线核查涉及七轮 **1,454 个保留的正式 QA 回答位置**；这是逻辑位置数，包含精确引用，不能称为 1,454 次独立调用。重新执行的三个评分反例中，两个是明确标记的合成审计输入，一个使用真实历史回答，均未写回实验结果。

## 阅读口径与证据范围

- **标准答案（oracle）**：出题程序或人工登记的答案及其来源，不等于天然正确。
- **来源绑定**：将读数与正确实体、信号/操作、单位、统计量和阶段关联起来。
- **完整联合正确率（joint）**：所要求的多个字段同时正确。例如数字正确但实体错误，联合分仍为零。
- **格式合规**：是否满足 JSON 键名、字段类型等接口要求；与答案内容正确性是不同维度。
- **可用性/可见性**：本文分别注明是源记录存在、实际文字绘制、几何位置有效，还是剪枝后支持检查通过。这些不是同一个指标。
- **标准/宽容评分**：历史登记名称。标为“宽容”不代表已覆盖全部语义等价表达。

核查依据包括历史报告、题目生成函数、原提示构造、保留答案与标准答案、逐题表、可见性记录和已完成的图像抽查。RQ4.7 的三个 M 条件及相关材料已按用户指示删除；本次不恢复它们、不引用其已删除回答。RQ4.7 的逐题结论仅针对仍保留的 S_COMPARE QA。

本轮新增图像查看为 **0 张**；沿用此前 RQ4.7 审计实际查看的13张图及其原像素来源记录，未突破用户总计20张的抽查上限。没有把全部 DOM/字段检查写成逐张目检或全部光栅文字可读性认证。

本文件不设“待证实风险”清单。踩坑条目均有直接记录、源码路径、实际回答或可复现的评分反例；没有把几何覆盖比例直接解释成模型丢失了等比例信息，也没有把任何格式归一化直接当成根因推理正确。

### P01｜文本 QA 继承了 RCA 指令，导致任务和输出要求冲突

**发生于 RQ4.1 正式实验。** T_FULL 的全部87份QA提示保留了识别根因和输出 `services` 的原任务，再追加独立QA要求；视觉QA条件没有这项RCA指令混入。实际73/87份文本QA回答含 `services`，只有23/87份返回恰好两个 `blocks`；两个计数有重叠。

因此，该文本QA条件没有形成干净的同任务模态对照。输出根因排序不能被简单解释成模型不会读取被问的事实。源码中 `qa_packet` 从完整 `RAW_TEXT` 构造标记版文本，却没有清除原任务外壳；[接口表][A41]记录了实际提示和回答类型。该问题不是由图像token剪枝造成。[L1]

### P02｜只给坐标，没有定义坐标和图号的读法

**发生于 RQ4.7 保留的60份正式QA请求。** 目标是图号及四个数的数组；实际含义是零起始图号、0—1000归一化坐标、`[left, top, right, bottom]`。原QA提示没有说明这些约定，也没有把目标框实际画出来。

本次直接读取60份已保存的完整 `messages`：均未提供0—1000或四个坐标分量的解释。RCA任务的其他指南虽有部分坐标说明，但 `make_request(task='QA')` 会使用独立QA文本，因此那些指南没有进入这批QA请求。

360个坐标与登记DOM框一致，均位于相应面板和画布内。**错误在模型可见的目标契约缺失，并非坐标计算跑到图外。** 定位错误与读取错误因而混在一起。[L7][C47][A1]

### P03｜目标框覆盖整行多个数，却没有说明询问哪种数

**发生于 RQ4.7 的61/360个目标。** 这些框覆盖新增比较整行，包含观测读数，也包含坐标刻度、实体或操作标识。题目只给框和统一的 `value/entity/unit/statistic/phase` 模板，没有说明读取观测值而非刻度等辅助量。

已核对的 `INC-1E7AE92CAA11` current span count 行中，真实观测为2807，轴上限为9422，还出现实体279等数字。图形标识本身仍有语义，但“框中的值”没有指明应返回哪个角色的数字。这是已确认的目标定义不足。

这里没有把9422和2807登记为同一测量的两个正确值；它们在图中承担不同角色。61是整行目标数，不是经过人工证明有61道多解题。[L7][A47]

### P04｜关系级观测被硬套为单实体题，标准实体为空

**发生于 RQ4.7 的19/360题，涉及17病例。** AIOPS-2022为5题、AIOPS-2025为7题、AegisLab为7题。联合请求数和配对数量属于父子关系，生成器却回填 `entity=""`，并把它作为五字段联合正确的条件。

具体记录包括：

| 病例 / 原零起始题号 | 实际观测 | 原oracle错误 |
|---|---|---|
| INC-B646C4677B96 / q4 | 父86432、子12534，reference指定联合分组请求数0 | 单实体答案为空字符串 |
| INC-96E8C237EFAF / q5 | 父888、子173，reference指定联合分组请求数40 | 单实体答案为空字符串 |
| INC-776EE000D01C / q5 | 父902、子690，reference配对请求数506 | 单实体答案为空字符串 |

数值0、40、506在图中，并不是数值未绘制；**没有合理定义的是要求单个实体的完整正解**。空字符串也未在图或提示中定义为合法实体答案。这19题属于出题与资格审核缺陷，不能作为模型答错的证据。生成路径见 `source_rows` 的实体回退及 `qa_material` 的直接oracle复制。[L7][C47]

### P05｜阶段答案使用了未展示、未解释的后台词汇

**发生于 RQ4.7 的90/360题：83个 `whole_window`、7个 `observed_window`。** 这两种标准阶段词不在相应卡片可见文字中，也不在60份QA提示中；评分却要求字符串匹配，登记宽容评分没有对应语义转换。

例如 `INC-85C93CE3CB89` 的指标卡显示baseline=14.22，oracle阶段为 `whole_window`；`INC-39682657768A` 的日志模板次数为14，oracle阶段为 `observed_window`，同卡另有reference/current内容。出题直接继承来源元数据的阶段词，没有向答题者定义它与图中文字的对应关系。

这是已确认的**隐藏答案词汇约束**。90题与空实体等类别有重叠；不能与其他条目直接相加，也不能据此把全部数值读取都说成无解。[L7][A47]

### P06｜“source unit”没有区分整条记录与被问数值的单位

**发生于 RQ4.5。** 题目要求source unit；某些Trace源记录的整体单位是复合串 `counts_microseconds_and_log2_fold_change`，目标耗时字段的物理单位却是microseconds。一个记录同时包含数量、耗时、比值，这个复合串不能作为所有字段共同的物理单位。

已保存题目、源单位和模型回答体现了这个冲突。将复合串整体替换为微秒会把语义差异当成拼写差异；原报告的事后单位别名分析没有这样做。该问题不同于P07的空格/下划线正规化。[L5][A45]

### P07｜照抄可见单位或使用等价拼写，仍被“宽容”评分拒绝

**在 RQ4.5—RQ4.7 反复出现。** 登记规则覆盖了部分ID前缀或数值字符串，却没有一致覆盖 `source unit/source_unit`、自然空格版单位、`µs/μs/us/microseconds` 等有明确对应的写法。

- RQ4.5纯视觉三个条件的病例平均登记宽容QA分别为0、0.0056、0.0056；仅做单位别名的事后敏感性分析后分别为0.1417、0.1333、0.1306。数字、实体和关系没有被修复。
- RQ4.6仅加入空格/下划线等价后，U的逐题联合正确率从16.86%到22.09%；VALUE从14.53%到19.77%。这是逐题率，与病例平均QA口径不同。
- RQ4.7有19个 `ratio_or_percent`、22个 `milliseconds_or_source_unit` oracle。图上使用空格版文字；本次把一题其余字段保持oracle正确，仅将单位改为图上原文 `milliseconds or source unit`，历史宽容评分返回0。

最后一项是**合成评分反例**，不是伪称该模型此题实际全对；该实际回答还存在数值错误。反例与原评分函数哈希保存在[A1]。[L5][L6][L7]

### P08｜合法来源描述与唯一ID的表达差异被等同于绑错实体

**RQ4.4与RQ4.7有具体证据。** RQ4.4隔离卡片QA的实体严格正确率为10/30，去掉明确的 `pod/service/node` 前缀后为30/30。例如 `pod 70779` 与 `70779` 表达相同实体。

RQ4.7 `INC-C10F5EA649A5` 的原q2，图中对应service619、操作 `745.619/PlaceOrder`、current exclusive p95=77933.15µs。模型写：

```json
{"value":"77933","entity":"745.619/PlaceOrder","unit":"µs","statistic":"exclusive p95","phase":"current"}
```

该操作在这张来源卡片中明确归属619。原提示没有要求实体字段只能填数字ID；宽容评分仍因操作字符串与619不相等而判整题错，其他四字段均通过登记宽容规则。

这是实际回答中的表达接口失配，不是通过任意“包含619”的字符串猜测实体。相反，RQ4.3把570回答成65901等已有证据的不同实体，属于真实绑定错误，见P20。[L4][L7][A1]

### P09｜语义相容的统计名称扩写也被判为错误

**RQ4.7 `INC-98BF3F9714D0` 的实际回答**将统计名称写成 `reference exclusive p95` 或 `current exclusive p95`，同时在phase字段填写对应阶段；oracle统计名只有 `exclusive p95`。现行规则没有消除这种与阶段一致的冗余前缀。

这里的差异不等于把p50答成p95。相同量的冗余描述与统计量本身错误在原联合评分中都表现为失败，但事实含义不同。[L7][A47]

### P10｜顶层格式错误让其他正确题目也整份归零

**RQ4.3正式发生，其他轮也存在同类已验证代码路径。** RQ4.3的180份QA中145份不满足完整六键接口，包括28份空对象、8份完整JSON不可解析，以及额外键、标点键名、字符串化对象等。原评分先检查整体shape，失败后用空答案替换整份回答。

事后按题提取、保留内容要求后，U/P_LOCAL_BI/C_GLOBAL_BI的病例平均QA从0.0583/0.0361/0.0250变为0.1194/0.1167/0.0972。原分保留，没有重新请求模型。

RQ4.5的 `score_qa` 也先整体验证schema。本次用真实非空oracle构造六题全对回答，仅加一个额外 `comment` 键，结果是标准分与登记宽容分均为0。这个合成反例证明代码路径存在；实际180份RQ4.5回答均具备六个顶层键，不能把该反例说成它们全部失败的实际原因。RQ4.2的236份回答也全部具备六键，未把潜在分支冒称成该轮发生的大面积格式故障。[L3][C45][A1]

### P11｜已经写出正确答案，但自动提取仍未读到

**RQ4.3 `INC-89856C07F4EE`。** U和P在自由文字中明确写出正确Q1=54.25，却未使用可识别的 `q1` 字段，连事后自动宽容提取也没有给分；Global以结构化字段写同一数值获得该题分。三者独立RCA均RR=0.5。

这说明“自动宽容后仍为零”也不必然是内容错误。该例人工识别的正确片段在报告中单列，没有人为填补其他全样本分数。另一方面，`{}` 或缺失答案确实没有可评分内容，不能被“宽容”自动补出。[L3]

### P12｜精确转录、近似读图和浮点尾数被同一总分压在一起

**RQ4.6实际存在精度敏感的回答。** H_DEPLOY_ONLY的112个数值题，104个精确正确；事后1%敏感性下112个均通过。H_MARGINAL_PHASE则只有14个精确正确，1%下20个通过。两者既包含小误差，也包含大幅错读，放宽后表现不同。

源码中的完整边际图和阶段边际图直接显示原数值字符串；例如总体p95字符串包含很长的浮点尾数。因此这里确认的是**对实际可见长数值的精确转录要求及其评分敏感性**。登记精确分与事后近似分回答不同的测量问题；只有明确精度口径，才能解释两者的差额。

另一个实际错误完全不是小数精度问题：`INC-8991CE65FDA1` 把p50的48.282/95.86回答给p95，正确p95为60.698099999999975/190.94179999999997。原图同时展示两种统计量，错误在口径选择。[L6][CM]

### P13｜QA目标标记本身引起渲染失败或遮挡

**这是资格阶段已发现并修复的历史问题，不是把失败图片算入正式结果。** RQ4.1一次CPU审核停止时处理155例，108通过、47失败，集中于QA标记找不到无遮挡位置。旧38×24标记仅尝试六个周边位置，与紧凑右对齐日志详情冲突。后续采用为标记和原数值预留行内空间的实现，普通RCA图哈希未变。

RQ4.3资格阶段也出现标记与行内容重叠、关系边中点被节点覆盖等问题；后续采用独立标记空间和可用边位置完成修复，后续60例审核没有这类错误。两轮记录说明，增加目标定位标记本身就是输入变化，曾经发生真实的渲染兼容问题。[F41][Q43]

RQ4.3的GPU资格检查还发现 `Current/current` 大小写会造成阶段绑定误判；随后仅修改离线匹配规则，三份smoke QA复算分数未改变，未新增模型调用。该项属于正式批次前已修复的评分兼容缺陷，不能冒称它造成了正式结果中的分数变化。[Q43]

### P14｜原图有答案，不等于剪枝后的问题具备完整支持

**RQ4.3的冻结支持检查已记录这一差异。** 每臂353道适用题中，263道通过支持可见性标记、90道未通过；三臂合计789/1,059通过。病例平均可见比例74.22%，与直接汇总的263/353略有区别。

具体每臂：q1/q2各60题仅36题支持可见，q4/q5各58题仅37题支持可见；q3为59/59，q6为58/58。原主分仍包含全部适用题。这个分数混合了证据保留与在保留证据上的答题能力；条件分与全分母分代表不同问题。

这些是冻结的几何/token支持定义，不是人工证明另外90题绝对不可推断。RQ4.7也有51个目标框面积保留不足50%，但没有目标完全不与保留token相交；本次没有将这一面积指标转换成丢失字数或无解题数。[L3][A1][L7]

### P15｜QA目标很少受到被测方法的实际增强

**RQ4.4的高清机制测量。** SOURCE_ZOOM与REPEAT_VIEW的QA目标只有2/30进入局部图集，HASH_ZOOM只有1/30。大多数问题仍问原概览中没有得到局部增强的目标。

因此整体QA并没有充分测量“被恢复高清的目标”的效果。SOURCE与REPEAT两例入图目标均五字段正确，但分母只有2；不能从2例推广到全部病例，也不能将另外28例的低分称为目标高清处理失败。这是实际干预覆盖不足，不是统计检验显著与否的问题。[L4]

### P16｜隔离卡片对照同时改变了多个因素

**RQ4.4 ISOLATED_QA**的宽容字段准确率0.96、数值对30/30正确，明显高于完整输入条件；但隔离同时改变了定位难度、干扰数量、分辨率和token保留。

结果支持“这批完整目标卡片在隔离条件下能够被读取”，不能单独识别字号、注意力、裁剪或干扰中的哪一项产生了收益。把这一差值全部归给视觉编码分辨率会超出实际控制范围。[L4]

### P17｜复合答案的联合分出现地板，遮蔽了具体失败位置

**RQ4.1和RQ4.7都出现联合恒零。** RQ4.1每个题块同时要求两数值、两侧四字段绑定和比较，四臂Joint均0/174；只做表面格式正规化后仍没有双侧完整绑定正确。RQ4.7五字段joint为0/360，但数字、实体、单位、统计量、阶段的正确数量不同，还混有P04—P09的出题和评分缺陷。

RQ4.6提供了另一种掩盖：VALUE数值正确率31.40%，高于U的27.91%；实体正确率却从U的79.07%降到73.26%，完整联合正确率从16.86%降到14.53%。只看数字或只看joint都会漏掉一部分变化。

完整分恒零时，与RR的相关系数没有定义；不能把未定义值报告成相关系数0。这里的RR是单病例根因排名的倒数，MRR是其平均。[L1][L6][L7]

### P18｜阶段答案高度偏斜，简单常量回答已有很高分

**RQ4.5的60个比较目标中，53个正解为current、5个为reference、2个为equal。** 始终回答current已有88.3%的方向正确率；三个hybrid为56/60，即93.3%。单报93.3%会隐藏相对于常量答案仅多答对3题的事实。

RQ4.1也有“两个数值都错，但大小关系碰巧正确”的实际回答。比较子项高分不能单独证明正确读取了目标数值。[L1][L5][A1]

### P19｜不同题族和不同聚合方式，被同叫作“QA”

RQ4.2主要测两个Trace卡片；RQ4.4报告五字段平均和完整五字段率；RQ4.5每题通常要求多个字段；RQ4.6则在不同arm使用不同题族：hybrid是关系＋总体分位数，部署纯视觉是六个关系集合，剪枝/U是数值与来源。

这些都不是同一个测试。RQ4.6三类题的适用数、难度与答案结构不同，不能把全330份分数合成一个“视觉vs混合的总体理解能力差”。同一轮的病例平均与逐题微平均也可能不同，RQ4.3可见比例就是具体例子。[L2][L3][L4][L6]

### P21｜完全相同的请求引用不能算多份独立成功证据

**RQ4.5 `INC-27CBD1F8668A`。** 三种hybrid在该例没有可转移的相关图形事实，使用同一文本请求的精确引用；四道适用QA全对，但RCA均未命中前五。三份逻辑臂记录不是三次独立测得的成功读取。

这个例子同时展示了“问到的事实答对”和“问到的事实足以支持诊断”不同。QA未由故障标签选出关键证据，正确QA并不自动充分。[L5]

## 第三部分：注意事项、设计目标、原则与规则

2026-10-20 RQ4.8 smoke 补充：题干已明示的字段名与语义类别映射属于合法答案
等价表达，接收器应独立于 oracle 规范化，并保留矛盾表达反例。可回答性检查应针对
模型实际接收的编码进行类型化解析，不能以原始 JSON 是否逐字出现在投影文本中
代替事实可见性。出题器漏问与方法真实删除证据必须分别计账；漏问没有模型答案，
不能通过离线重评分补造覆盖。

### 2026-10-20 用户修订：宽容接收与多值题部分得分

QA 与两步 dashboard 选卡均采用确定性宽容接收器。先解析轻微格式错误，再逐项排除无效 ID，保留其余有效回答后评分；不得因为一个条目无效而抹掉整份回答。无效 ID 的判断使用公开的题号或实体／卡片编号域，不使用正确答案。合法但答错的 ID 仍是错误答案，不能用“过滤非法 ID”将其改成正确答案。解析不得从解释中任意抓数字、猜测编号，或依据 oracle 解决互相冲突的回答。

区分两种语义：多个可接受的替代解，答出任一完整合法解即得满分；确实要求同时给出多个值的题目，完整答对得 1 分，宽容解析后只答出一个正确值也得 **0.5 分**。非空但不完整的正确部分按同一半分口径登记，未答对任何值得 0 分；混入其他合法但错误的值不能获得满分。联合解必须来自同一个合法解，不能把不同解的字段任意拼接成满分答案。另存严格格式、完整内容正确率与宽容部分得分，避免混淆测量口径。

这是后续实验的评分修订，优先于下方 Q07 对完整答案的旧全对口径；历史踩坑记录及历史分数保持原样。RQ4.8 的计划与独立评分器登记具体版本，不修改 `Codex.md`。

以下“必须/禁止”为后续QA协议要求；“建议”为实施选择。它们不修改历史分数，也不自动授权新的模型调用。

### 1. 目标与优先级

QA首先要成为**可以答、知道问什么、答对能得分、答错不能蒙混得分**的测量。其次才是分析读取、来源绑定和诊断之间的关系。

设计优先级为：可回答性与清晰提示 → 评分语义正确 → 实际输入/目标支持 → 合理难度与覆盖 → QA—RCA分析。统计显著性、可运行JSON、CPU通过和smoke通过都不能替代前几项。

### 2. 多答案题比例：硬上限20%

**Q01｜需要填写多个答案的题目，占实际QA题目比例不得超过20%。** 至少80%为单答案题。比例按语义题目计算，不按LLM调用数或JSON字段数机械计算。

| 类型 | 是否算多答案题 | 例子 |
|---|---|---|
| 一个数值，问题已明确单位和目标 | 否 | “标记Q1处的current p95是多少µs？”只答一个数 |
| 一个实体、一个单位名称或一个方向类别 | 否 | “Q2读数属于哪个实体？”；“current更大、reference更大还是相等？” |
| 有多个等价正确表达，但只需给其中一个 | 否 | `us`或`µs`均可；多个并列对象中题目明确只需一个 |
| 同时填写数值＋实体，或实体＋单位 | **是** | 一题要求 `{value, entity}`，即使JSON只有一个对象 |
| 同时读取reference与current两个数 | **是** | 两个空、两个数构成一个请求 |
| 写全部端点、多个选项或整条边的源/类型/目标 | **是** | 集合题、复合关系题、多选题 |

实施口径：

1. 全实验、每个QA条件及每个数据集都满足 `n_multi ≤ floor(0.20 × n_questions)`，防止只在总体上合格而某臂仍全是复合题。
2. 若按每例六题打包，一例最多一题多答案；不足五题的题包不安排多答案题。小题包不能通过四舍五入获得一个额外名额。
3. 不适用占位符不计入题数，不能用空题稀释比例；有效性审核后重新计算。首次调用前按注册确定性规则完成题库调整和冻结，不能按模型答对与否替换；运行后发现无效题时按Q06保存并报告原记录。
4. 将一个原本必须联合填完的复合题拆成若干编号、仍要求整组全对才算一题，按原复合语义计数，不能规避上限。
5. 真正独立的单值题、单实体题可以共享一个目标，用于分解读取和归属；逐题计分。另报共同目标的联合描述指标，但不能让该联合指标替代80%单答案主测量。
6. `question_id`等协议标识不算额外诊断答案；若需要模型填写实体、单位或来源，它们就是被评分答案，不能称为“元数据”绕过规则。

该20%规则是本次用户新增要求，不把历史实验追溯改写成“违反当时已有上限”。

### 3. 出题与答案资格

**Q02｜每道可回答题都必须有非空、类型明确的正确答案。** `""`不能代表未知实体、未知阶段或无法建模的关系。合法的数值0、明确的空集合 `[]` 与空字符串不同；空集合仅在完整观测范围确实没有满足条件的元素、且题意明确时成立。

**Q03｜答案依据必须存在于该题实际提供的输入中。** 纯视觉核对最终图像；hybrid核对该请求图像与文本的并集。原始遥测、隐藏HTML属性、tooltip、审计JSON或另一个arm中的事实不算已提供证据。派生比较题可以不直接印出答案，但全部操作数及比较定义必须可获得。

**Q04｜为每题保存答案证明。** 至少包括问题身份、任务类型、来源记录/字段、实际输入哈希、可见位置、显示字符串、原值、单位、统计口径、阶段、接受答案集合和评分版本。每个被评分字段都要有依据，不能只证明数字存在。

**Q05｜根据事实类型设计答案，而非把全部事实套成单实体五元组。** 单实体属性、父子关系、边、全局统计分别定义题型。父子联合计数若需要问归属，使用语义明确的关系或端点题，并计入多答案预算。

**Q06｜明确区分四种状态。**

- `answerable`：输入与提示支持确定答案。
- `not_applicable`：该病例不能实例化已登记题型，不发出这道题。
- `invalid_question`：题目或oracle有错误，属于实验错误，不属于模型答错。
- `unanswerable_control`：仅在专门登记的拒答/不可回答研究中存在，有明确的正确拒答协议。

普通读取实验不以空oracle生成“不可回答题”；事后发现无效题时保留原账本、标注受影响范围，不能无声地删掉失败分母，也不能让模型重新回答修好的同一道题并覆盖旧结果。

**Q07｜多解接受的是完整正确答案的集合。** 若题目允许任意一个并列对象，则任一满足条件对象都可得分；若题目问“全部端点”，正确答案是完整无序集合，不是其中任意一个。若要多个排序位置或配对值，则保留顺序/对应关系。集合、顺序列表、替代答案集合三者使用不同数据类型。

**Q08｜不能按字段任意拼凑多解。** 两个允许答案 `(实体A, 数值x)` 与 `(实体B, 数值y)` 不意味着 `(A,y)`也合法。保持每个解的来源联合一致性。实体别名必须由实际来源中唯一的映射证明，禁止按“字符串含某ID”猜测。

### 4. 提示必须让答题者知道准确任务

**Q09｜QA使用独立的system/user任务接口。** 不继承根因排名、五候选、因果分析或RCA输出schema。检查最终序列化请求的全部消息，而不只检查某个QA常量。

**Q10｜每题写清目标及返回内容。** 给出实际可见的目标标记、卡片或来源定位；明确读取观测值、刻度、总体分位数、条件分位数还是样本。标题、轴上限和数量不能靠评分器事后猜测区分。

**Q11｜定位约定完整可见。** 使用坐标时，说明图号起点、坐标范围、原点及四项次序；多图映射跟随实际图像顺序。框内有多种数字时继续说明目标角色。标记/编号本身必须在实际输入中，并核查没有遮挡被问内容。

**Q12｜单位、阶段和统计词以可见表示为依据。** 明确“卡片整体单位”还是“该字段单位”；count、µs、log2比值等不共用一个物理单位答案。对后台规范词建立读者可见的说明，或者以图中文字作为接受表达。p50/p95、inclusive/exclusive、reference/current不能作为拼写别名混同。

**Q13｜输出schema与提示一致。** 在提示中给最小示例，说明必需键、值类型、数字/字符串、null的含义和集合是否有序。解码器能约束JSON形状，不等于模型已知道字段语义。

**Q14｜不把答案放进问题后声称测到了绑定。** 单实体绑定题可以给目标定位和被问字段名称，但不能同时提供正确owner再让模型复制。若问题明确给实体以测试数值读取，则结果只支持读取，不支持发现实体归属。

### 5. 数值、单位与格式评分

**Q15｜先根据任务登记数值规则。**

| 任务 | 正确评分依据 |
|---|---|
| 转录已印出的数字 | 接受显示值的数值等价写法；若允许复制原精度值，必须证明它也可见或可由显示精度规则接受 |
| 从曲线/条形估读 | 预先按坐标变换、分辨率与图形可辨尺度登记允许区间；不能要求隐藏的原始精确值 |
| 精确计数、实体ID、年份等 | 不套用百分比误差；实体ID按身份匹配 |
| 数值计算/比较 | 使用题目明确的可见输入、量纲和精度；显示精度相同时不能要求分辨未显示的小差异 |

原值、实际显示字符串、显示变换和允许区间分别保存。小数、科学计数法、负数、零、百分数和数量级后缀要有明确解析。零值使用登记的绝对规则，不能仅依赖相对误差。百分号到比例的转换必须保持量纲一致。

**Q16｜不以统一1%或5%替代数值语义。** 借鉴ChartQAPro不代表所有遥测都容许5%。允许误差不能把p50当p95、把µs当ms，不能因为数字接近就接受另一实体的读数。

**Q17｜将内容正确与格式合规分开报告。** 保留原始原文，按题提取并评分；一个额外键、一个题缺失或一个字段类型偏差不能自动抹掉其他可确定的正确答案。格式合规率仍独立保留，不能把它悄悄隐藏。

**Q18｜宽容只能消除表示差异，不能修补事实。** 可预先接受无歧义的空白、大小写、code fence、JSON字符串包装、数字字符串、已登记键名别名、实体类型前缀及单位同义词。不能改方向、换实体、补缺失读数、把非法ID映射到“最近正确ID”，或从回答里多个冲突数值挑一个碰巧等于oracle的值。

**Q19｜冲突答案按明确规则处理。** 重复JSON键、同一题多个不一致结论、相互冲突的单位/阶段不能被普通字典覆盖后悄悄消失。提取阶段不知道正确答案；判断阶段只评价提取出的确定结论。歧义不能通过看oracle解决。

**Q20｜按题型评分并保留分量。** 主体是单答案题；少量复合题同时报告各分量和完整联合正确。关系集合报告完整正确和描述性端点precision/recall；部分集合不能冒充完整正确。多题结果按病例/事件组聚合，不把字段数量当作独立样本。

### 6. 实际输入、剪枝与实验资格

**Q21｜核对模型实际接收的表示。** 来源正确、DOM正确、截图存在、processor后的几何、token保留是连续但不同的检查。文字的单位/阶段/标题和关系端点都属于答案支持，不仅是数字所在框。

**Q22｜预先区分两种测量。** 一种评价包含剪枝损失的端到端QA，另一种评价具有完整支持时的条件读取能力。两者都保留原分母和支持标记。若某arm明确移除事实，该题不能继续被无条件称为该arm的“可回答读取题”；方法造成的可用性损失仍单独计入，不能靠删除题目隐藏。

**Q23｜机制题确实覆盖干预。** 测高清、局部比较或特定来源绑定时，冻结前检查有多少题目标实际处于被修改区域，并报告共同支持子集。不能看到模型回答后再换成有利目标，也不能用2个被增强目标代表30例的增强效果。

**Q24｜几何可运行与人可解答分别验收。** 使用实际最终输入和完全相同提示进行少量人工解题，解题时先不看oracle；之后核对来源、替代答案和评分。单人审核明确记录，不冒充双盲。当前用户图像查看上限继续有效；本文件不授权扩大查看或启动多人agent。

**Q25｜未解决的题目有效性错误阻止该QA批次启动。** 空oracle、不可定位目标、未定义单位/阶段、答案仅在隐藏资料中、评分拒绝已登记正确表达等，必须在模型调用前查清。不能把“格式smoke通过”写成“QA测量有效”。研究方法本身的RCA资格与独立QA资格分别记录。

### 7. 分析、统计与解释

**Q26｜控制题库答案偏斜。** 至少报告单答案类别的常量/多数类基线、适用率及任务分布。对比较题记录reference/current/equal比例。需要question-only等新增模型控制时单独登记调用；本文件不自动启动它们。

**Q27｜题族必须可比。** 跨臂比较同一语义问题时，记录实际承载模态、是否仍有答案支持、是否精确引用。不同题族分开报告，不拿关系集合题与单数值题的平均准确率直接比较“模态能力”。

**Q28｜统计单位是病例或事件组。** 多题、多字段、同请求引用均不增加独立病例数。报告适用题数、有效题数、无效题数、实际调用和逻辑引用。按协议冻结比较族；保留项目要求的校正和不报告CI等统计口径。

**Q29｜常量分数的相关系数记为未定义。** 不显著不是独立；低分地板、测量噪声、题目覆盖和样本选择必须与相关结果一起说明。不能仅用QA相关筛选RCA方法，也不能只挑QA答错、排名下降的病例构造故事。

**Q30｜实际读回答，分开编码错误。** 至少区分：任务接口/无法提取、数字错误、另一来源、单位/统计/阶段错误、正确局部观测但诊断错误、理由与排名矛盾。真实数字出现在其他卡片只是匹配证据，不自动证明内部注意路径；解释和attention都不替代受控因果证据。

**Q31｜明确干预实际执行情况。** 位置交换保持答案不变时核对所有图像副本；语义替换改变QA答案时登记新oracle。被语义修改的输入不能继续配原真实故障标签做RCA归因。不适用或未执行的干预不作零效果解释。

### 8. 版本与保存

**Q32｜题目、输入、评分分别版本化。** 固定问题ID、输入身份、oracle版本、提取规则和评分版本。修评分不触发重新生成答案；事后敏感性结果与原注册分并列，不能覆盖原分。

**Q33｜保留可审计的原材料。** 保留实际prompt、图像、完整回答、oracle证明、接受答案集合、逐题解析/评分、失败与不适用原因。遵守每万次实际完成调用25GB及attention1GB的直接可读、去重保存规则。不要用重渲染的“更好图片”替代当时实际输入。

**Q34｜资格记录明确到版本和范围。** 记录静态、数值/解析反例、图像抽查、模型smoke分别做了什么。修了prompt/图/目标/token操作后，旧资格仅能复用未受影响部分；原失败记录与原调用保持。

## 第四部分：可直接用于未来设计的提示骨架与验收表

以下是新协议的示例骨架，不是已经部署或测试通过的代码。占位符必须在出题时用公开定位信息替换；不能把答案oracle放入提示。单次调用可以包含多道独立单答案题，并不因此变成多阶段RCA。

### 1. 独立QA公共提示骨架

```text
Answer the independent factual questions below using only the supplied evidence.
Do not diagnose or rank root causes.

Image indices start at 0 in the order supplied. If a box is used, it is
[left, top, right, bottom], normalized to 0..1000 in that image, with the
origin at the upper-left corner. The question states which observation
inside the box is requested; axis ticks and panel identifiers are not
measurement values unless explicitly requested.

Each question asks for one answer unless explicitly labeled MULTI.
Copy the displayed value at its displayed precision. Do not invent
unshown digits or infer an unstated unit. If the requested content cannot
be determined, return null for that question; this does not make null a
correct answer to an answerable question.

Return a JSON object whose keys are the supplied question IDs.
Use strings for single answers and arrays only for questions explicitly
requesting a set or ordered list. Answer the other questions even if one
cannot be answered.
```

针对纯视觉题，`supplied evidence`明确为图像；hybrid题明确为本次提供的图像与文本。不能让同一模板暗示存在实际没有提供的证据。

### 2. 六题的合规结构示例

| 题号 | 题意骨架 | 答案形式 | 多答案计数 |
|---|---|---|---:|
| q1 | 在标记Q1处读取current exclusive p95；单位已在题中指定 | 一个数值字符串 | 0 |
| q2 | 标记Q2处的读数属于哪个实体？返回实体ID | 一个ID | 0 |
| q3 | 标记Q3所指具体字段的显示单位是什么？ | 一个单位字符串 | 0 |
| q4 | 标记Q4的总体分位数是p50还是p95？ | 一个类别 | 0 |
| q5 | 指定同口径reference/current两观测，哪个更大，或显示精度下相等？ | 一个类别 | 0 |
| q6 | **MULTI**：从指定实体沿明确关系类型，列出所有直接目标ID；不含可达但非直接的节点 | 一个完整无序集合 | 1 |

比例为1/6，约16.7%。这是题型示例，不保证每个病例都能实例化；生成前仍按Q02—Q08验证。q1明确单位是在测试读数；q2不在题干泄漏正确owner。若q6不适用，不能用另一个复合题未经预算检查直接补上。
